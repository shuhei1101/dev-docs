# 設定

端末の設定と dev-docs.yaml のキーの一覧

設定は、端末の値（`~/.config/dev-docs/settings.yaml`、Git の外）と、配信元の値（`dev-docs.yaml`）に分かれます。
どちらもスキーマを dev-docs が持ち、起動時と読み直しのときに検証します。
表に無いキーと、存在しない ID への参照は誤りとして返します。

## ファイル

| ファイル | 管理する値 |
| --- | --- |
| `~/.config/dev-docs/settings.yaml` | 端末の値（クローンの場所・待ち受け・配信元と権限・状態の置き場所） |
| 配信元の設定の YAML（ファイル名は任意） | 配信元の値（配信する文書・検査・変換・画面の構成（#17）・書き込み・説明）。端末の設定の `sources[].config` に並べた順にマージする |

マージの仕方は [配信元と権限](../はじめに/コアコンセプト/配信元と権限.md) の「設定のマージ」にあります。

## 環境変数

| 環境変数 | 型 | 既定 | 説明 |
| --- | --- | --- | --- |
| `DEV_DOCS_CONFIG` | str | `~/.config/dev-docs/settings.yaml` | 端末の設定のパス |
| `DEV_DOCS_PORT` | int | 端末の設定の `port` | 待ち受けのポート。設定の `port` より優先する |

## 端末の設定 settings.yaml

反映の列は、変えた後に何が要るかを表します。

<!-- table: data -->

| キー | 型 | 必須 | 既定 | 説明 | 反映 |
| --- | --- | --- | --- | --- | --- |
| `version` | str | ✅ | - | 設定のバージョン。サーバーが読めるバージョンより新しい値は誤り | 読み直し |
| `clone` | str | ✅ | - | dev-docs のクローンの場所。管理用プラグインのフックが `dev-docs serve` を起動するクローン | 即時 |
| `port` | int | - | `8781` | 画面の API・文書の MCP・管理の MCP を待ち受ける 1 つのポート | 再起動 |
| `bind` | str | - | `127.0.0.1` | 待ち受けるアドレス | 再起動 |
| `sources[]` | list | - | `[]` | 配信元のテーブル。1 行が 1 つの配信元 | 読み直し |
| `sources[].id` | str | - | 配信元の設定の `name` | 主キー。MCP の引数 `source` で指す。英小文字・数字・`-` だけ | 読み直し |
| `sources[].config` | str か list[str] | ✅ | - | 配信元の設定の YAML の絶対パス。配列なら上から順にマージする。先頭のファイルのフォルダが配信元のフォルダ | 読み直し |
| `sources[].enabled` | bool | - | `true` | `false` で行を消さずに配信を止める | 読み直し |
| `sources[].scope.read` | list[str] | - | `[]` | この配信元を読める作業場所（`cwd`）のパスの glob | 読み直し |
| `sources[].scope.write` | list[str] | - | 配信元のフォルダだけ | この配信元を読み書きできる作業場所のパスの glob。極力小さくする | 読み直し |
| `state_dir` | str | - | `~/.local/state/dev-docs` | 会話キーごとの返し済みの記録・変換の結果・リビジョンの書き出し・表の列の設定を置くフォルダ | 再起動 |
| `log_dir` | str | - | `{state_dir}/logs` | 起動時の検証の失敗と警告のログを書くフォルダ | 再起動 |
| `seen_retention_days` | int | - | `7` | この日数を過ぎた会話キーの記録を消す | 再起動 |
| `script_timeout_sec` | int | - | サーバーの既定値 | 検査・変換・生成のスクリプト 1 回の制限時間（秒） | 再起動 |

<!-- /table -->

`scope` のパスは作業場所と照らします。
`/**` を付けないパスはそのフォルダだけに当たり、`/**` を付けると中のフォルダにも当たります。

```yaml
version: "1"
clone: /home/me/repo/dev-docs
sources:
  - id: knowledge
    config: /home/me/repo/knowledge/dev-docs.yaml
    scope:
      read: [/home/me/repo/ai-monitor/**, /home/me/repo/aituber/**]
      write: [/home/me/repo/knowledge]
  - id: workspace
    config:
      - /home/me/repo/knowledge/tmp/workspace/dev-docs.yaml
      - /home/me/repo/knowledge/tmp/workspace/local.yaml
    scope:
      write: [/home/me/repo/**]
```

## 配信元の設定 dev-docs.yaml

パスはすべて配信元のフォルダ（`dev-docs.yaml` のフォルダ）からの相対です。
`id` は設定の中で一意にします。

### 全体

<!-- table: data -->

| キー | 型 | 必須 | 既定 | 説明 |
| --- | --- | --- | --- | --- |
| `version` | str | - | サーバーが読めるバージョン | 設定を記載したときのスキーマのバージョン。古い設定の配信元を検出する |
| `name` | str | ✅ | - | 配信元の名前。画面の API のパスと、端末の設定の `sources[].id` の既定に使う |
| `enabled` | bool | - | `true` | `false` でこの配信元を配信しない。端末の設定の `sources[].enabled` と両方が `true` のときだけ配信する |
| `default_ref` | str | - | `develop` | リビジョンを指さないときに読むリビジョン |
| `tags` | str | - | - | タグのマスターのファイル。タグの検査と `group_by: tags` の語彙に使う |
| `visibility` | obj | - | - | Pages に出す文書の条件 |
| `worktrees[]` | list[str] | - | `[./.claude/worktrees/*]` | ワークツリーの場所の glob。配信元のフォルダからの相対パスか絶対パス |
| `description` | str | - | 空 | `describe()` の一覧に出す 1 文 |
| `instructions` | str | - | 空 | `describe(source)` で返す、その配信元に固有の使い方 |
| `ids.format` | str | - | 制約なし | `write_docs` で新しい文書を作るときの ID の形（`{kind}-{slug}` など）。合わない ID は書き込みで断る |
| `related.types[]` | list[str] | - | `[references, depends_on, see_also]` | 文書の `related` の各行の `type` に使ってよい語。一覧に無い語は検査で断る |
| `diff.ignore_keys[]` | list[str] | - | `[updated]` | 差分と `list_changes` に出さないキー |
| `github.repository` | str | - | - | GitHub のリポジトリ（`owner/name`）。記載した配信元は、#17 の画面が Issue を作成するボタンを出す |
| `github.issue_labels[]` | list[str] | - | `[]` | Issue の作成画面の URL の `labels` に渡すラベル |

### documents[]

1 行は、同じ形式・同じスキーマ・同じ検査で扱う文書のまとまりです。
`paths[]` に当たった各ファイルが、それぞれ別の文書（1 レコード）になります。
行の `id` は、文書の MCP の `kind` になります。

<!-- table: data -->

| キー | 型 | 必須 | 既定 | 説明 |
| --- | --- | --- | --- | --- |
| `documents[].id` | str | ✅ | - | 主キー。`nav`・他のキーから参照する |
| `documents[].type` | `yaml` / `markdown` | ✅ | - | 文書の形式 |
| `documents[].paths[]` | list[str] | ✅ | - | ファイルのパスか glob の並び。当たった各ファイルが 1 つの文書。ID は YAML の `id`、Markdown はパス |
| `documents[].title` | str | - | 1 ファイルなら文書の `name`、glob なら `id` | #17 の画面・MCP に出す名前 |
| `documents[].enabled` | bool | - | `true` | `false` で配信も検索もしない |
| `documents[].schema` | str | `yaml` のとき ✅ | - | この文書を検査するスキーマ。スキーマの `title` が種類の名前になる |
| `documents[].validators[]` | list[str] | - | `[]` | 通す `validators[].id`。スキーマの検査は常に通す |
| `documents[].converter` | str | - | 既定の変換 | 使う `converters[].id` |
| `documents[].writable` | bool | - | `yaml` は `true`、`markdown` は `false` | `write_docs`・`delete_docs` を許すか |
| `documents[].after_write[]` | list[str] | - | `[]` | 書いた後に流す `generators[].id` |
| `documents[].search` | bool | - | `true` | `false` で検索の対象にしない |
| `documents[].records` | str | - | - | `yaml` のとき、ファイルの中のこの配列の各要素を 1 件の文書にする |
| `documents[].body_file` | str | - | - | `records` の各要素で、本文として返すファイルのパスを持つ列。パスは YAML のファイルからの相対 |
| `documents[].metadata` | obj | - | 各キーは同じ名前の列の `ref` | 共通のキー（`id`・`name`・`description`・`tags`・`related`・`status`）ごとに、値の取り方を `{type: ref, field: 列名}`（文書の列から取る）か `{type: custom, value: 値}`（行の全文書に同じ値）で記載する |
| `documents[].defaults[]` | list | - | `[]` | `paths[]`（glob）に当たる文書に付けるメタデータ。上から順に重ね、最後に文書自身のメタデータを重ねる。`tags`・`related` は和集合、ほかのキーは後に重ねた値が優先 |

<!-- /table -->

### validators[]・converters[]・generators[]

| キー | 型 | 必須 | 既定 | 説明 |
| --- | --- | --- | --- | --- |
| `validators[].id` | str | ✅ | - | 主キー |
| `validators[].run` | list[str] | ✅ | - | 配信元のフォルダで実行するコマンド。標準入力に文書の YAML、終了コードと標準出力の JSON（違反の一覧）で結果を返す |
| `validators[].on` | list | - | `[write]` | 通す時点。`read`（読むとき。不合格は警告として返す）・`write`（書くとき。不合格なら書かない） |
| `converters[].id` | str | ✅ | - | 主キー |
| `converters[].run` | list[str] | ✅ | - | 標準入力に文書の YAML、標準出力に Markdown を返すコマンド |
| `generators[].id` | str | ✅ | - | 主キー |
| `generators[].run` | list[str] | ✅ | - | 書き込んだ文書のパスを引数に受けるコマンド |

スクリプトは 1 回ごとに `script_timeout_sec` の制限時間があります。
超えたスクリプトは止めて失敗として返します。

### nav

#17 の画面のタブとサイドバーの構成です。
`nav` が無ければ、文書の行ごとにタブを作ります。

| キー | 型 | 説明 |
| --- | --- | --- |
| `nav.tabs[]` | list | 画面上部のタブの並び |
| `nav.tabs[].title` | str | タブに出す名前 |
| `nav.tabs[].items[]` | list | サイドバーの項目。`group`・`page`・`auto` のどれか |
| `….group` | str | サイドバーの見出し。子の `items[]` を持ち、入れ子にできる |
| `….page` | str | ページの文書。1 ファイルだけの行は `documents[].id`、複数ファイルの行の 1 つは `{行の id}/{文書の ID}` |
| `….auto` | obj | 行の文書をページとして並べる。`document` に行の ID、`group_by` でメタデータごとにグループにする |
| `….title` | str | サイドバーに出す名前の上書き。既定は文書の名前 |

```yaml
nav:
  tabs:
    - title: 規約
      items:
        - auto: {document: rules, group_by: tags.lang}
    - title: 設計書
      items:
        - group: アーキテクチャ
          items:
            - page: architecture
```
