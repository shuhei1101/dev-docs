# 設定

端末の設定と dev-docs.yaml のキーの一覧

設定は、端末の値（`~/.config/dev-docs/settings.yaml`、Git の外）と、配信元の値（`dev-docs.yaml`）に分かれます。
どちらもスキーマを dev-docs が持ち、起動時と読み直しのときに検証します。
表に無いキーと、存在しない ID への参照は誤りとして返します。

## ファイル

| ファイル | 管理する値 |
| --- | --- |
| `~/.config/dev-docs/settings.yaml` | 端末の値（クローンの場所・待ち受け・配信元と権限・状態の置き場所） |
| 配信元の設定の YAML（ファイル名は任意） | 配信元の値（配信する文書・検査・変換・画面のタブとサイドバーの構成・書き込み・説明）。端末の設定の `sources[].config` に並べた順にマージする |

マージの仕方は [配信元と権限](../はじめに/コアコンセプト/配信元と権限.md) の「設定のマージ」にあります。

## 環境変数

| 環境変数 | 型 | 既定 | 説明 |
| --- | --- | --- | --- |
| `DEV_DOCS_CONFIG` | str | `~/.config/dev-docs/settings.yaml` | 端末の設定のパス |
| `DEV_DOCS_PORT` | int | 端末の設定の `port` | 待ち受けのポート。設定の `port` より優先する |

`scope` のパスは作業場所と照らします。
`/**` を付けないパスはそのフォルダだけに当たり、`/**` を付けると中のフォルダにも当たります。

```yaml
version: "1"
clone: /home/me/repo/dev-docs
sources:
  - id: knowledge
    config: /home/me/repo/knowledge/dev-docs.yaml
    scope:
      read: [/home/me/repo/ai-monitor/**, /home/me/repo/aituber/**]
      write: [/home/me/repo/knowledge]
  - id: workspace
    config:
      - /home/me/repo/knowledge/tmp/workspace/dev-docs.yaml
      - /home/me/repo/knowledge/tmp/workspace/local.yaml
    scope:
      write: [/home/me/repo/**]
```

## 配信元の設定 dev-docs.yaml

パスはすべて配信元のフォルダ（`dev-docs.yaml` のフォルダ）からの相対です。
`id` は設定の中で一意にします。

1 行目に `# yaml-language-server: $schema=https://raw.githubusercontent.com/shuhei1101/dev-docs/v{バージョン}/schemas/dev-docs.schema.json` を置くと、エディターで補完と検証が効きます。
`{バージョン}` は dev-docs のバージョンで、`/dev-docs:setup` が書きます。

### documents[]

1 行は、同じ形式・同じスキーマ・同じ検査で扱う文書のまとまりです。
`paths[]` に当たった各ファイルが、それぞれ別の文書（1 レコード）になります。
行の `id` は、文書の MCP の `kind` になります。
文書をどの行に入れるかは [documentsの行の判定](../使い方/documentsの行の判定.md) で決めます。

<!-- table: data -->

| キー | 型 | 必須 | 既定 | 説明 |
| --- | --- | --- | --- | --- |
| `documents[].id` | str | ✅ | - | 主キー。`nav`・他のキーから参照する |
| `documents[].paths[]` | list[str] | ✅ | - | ファイルのパスか glob の並び。当たった各ファイルが 1 つの文書。ID は YAML の `id` |
| `documents[].exclude[]` | list[str] | - | `[]` | `paths[]` に当たったファイルのうち、ファイル名（パスの末尾の要素）が当たる glob の並び。どれかに当たったファイルはこの行の文書にしない。他の行の `paths[]` に当たれば、その行の文書になる。`/` を含む要素は誤りになる |
| `documents[].title` | str | - | 1 ファイルなら文書の `name`、glob なら `id` | `nav` が無いときの文書の画面のタブの名前・MCP に出す名前 |
| `documents[].enabled` | bool | - | `true` | `false` で配信も検索もしない |
| `documents[].schema` | str | ✅ | - | この文書を検査するスキーマ。スキーマの `title` が種類の名前になる。`records` を持つ行はファイル全体のスキーマを指す |
| `documents[].validators[]` | list[str] | - | `[]` | 通す `validators[].id`。スキーマの検査は常に通す |
| `documents[].converter` | str | - | 既定の変換 | 使う `converters[].id` |
| `documents[].writable` | bool | - | `true` | `write_docs`・`delete_docs` を許すか |
| `documents[].after_write[]` | list[str] | - | `[]` | 書いた後に流す `generators[].id` |
| `documents[].search` | bool | - | `true` | `false` で検索の対象にしない |
| `documents[].records` | str | - | - | ファイルの中のこの配列の各要素を 1 件の文書にする。要素 1 つずつの検査・変換と、`search_docs`・`list_changes` の項目の一覧には `schema` の `properties.{records}.items` を当てる。`describe` はファイル全体のスキーマを返す |
| `documents[].body_file` | str | - | - | `records` の各要素で、本文として返すファイルのパスを持つ列。パスは YAML のファイルからの相対 |
| `documents[].metadata` | dict[str, str] | - | `{}`（各キーは同じ名前の列から読む） | 共通のキー（`id`・`name`・`description`・`tags`・`related`・`status` と、エイリアスのキー `alias_type`・`aliases`・`command`・`cwd`・`url`・`avoid`・`skill`・`tool`・`path`・`port`・`replacement`）→ 列名の対応（`name: title`）。入れ子の列は `meta.summary` のように `.` でつなぐ。オブジェクトの配列は `tags: tags[].name` で要素ごとの値を、`main_tags: tags[main].name` で `main` が真の要素の値を取り出す。値は文字列だけ。`name` は、空ならファイル名から拡張子を除いた名前になる（`records` の要素は `body_file` が指すファイルの名前、`body_file` が無ければ `id`）。`write_docs` は共通のキーをこの列へ読み替えて書き、`describe(source, kind)` が対応を表で出す |
| `documents[].alias_type` | `term` / `doc` / `command` / `url` / `skill` / `tool` / `path` / `env` / `avoid` | - | - | 行の全文書のメタデータの `alias_type` になる値。列から読んだ値より優先する。`alias_type` を持つ行の文書のエイリアスのキーは、起動時と `check_project` で alias-inject のスキーマ（取り込んだバージョンは `check_project` の結果に出る）に照らし、違反した文書は警告して用語の検索とツールチップから外す |

### 管理用の YAML

ソースコードなど YAML でない文書は、タグや概要文を自分では持てません。
管理用の YAML の `files[]` に 1 ファイル 1 行で記載し、`records: files`・`body_file: path` の行で配信します。
雛形のスキーマは dev-docs の `templates/files.schema.yaml`（JSON Schema Draft 2020-12）で、配信元のフォルダにコピーして行の `schema` に指します。
1 行ずつの検査には、このスキーマの `files.items` を当てます。
`properties.files.items` を定めないスキーマを指すと、`check_project` が `documents[{番号}].schema` の違反にします。

<!-- table: data -->

| キー | 型 | 必須 | 既定 | 説明 |
| --- | --- | --- | --- | --- |
| `files[]` | list | ✅ | - | 配信するファイルの並び。1 行が 1 つの文書 |
| `files[].path` | str | ✅ | - | 管理用の YAML のフォルダからの相対パス。1 行 1 ファイル。glob は入れない |
| `files[].name` | str | - | ファイル名から拡張子を除いた名前 | 何のファイルかを表す日本語の名詞句（例 `タスクのリポジトリ`）。クラス名・ファイル名の繰り返しは入れない |
| `files[].description` | str | - | - | 1 文で「何を受け持つか」と「どんなときに読むか」（例 `タスクの保存と取得を受け持つ。保存先や検索の条件を変えるときに読む`）。関数の一覧・実装の手順は入れない |
| `files[].tags` | list[str] | - | - | `topic`（扱う概念）と `tool`（使うライブラリ・外部サービス）。`kind`・`scope`・状態・評価の語は入れない |
| `files[].related` | list | - | - | `implements`（コード → 設計書。設計書と 1 対 1 の部分は必ず記載する）・`tests`（テスト → コード）・`see_also`。import で分かる依存と、逆向き（設計書 → コード）の関連は入れない。`to` は関連先の文書の ID で、関連先が `id` を持たないファイルなら拡張子付きのパス（`src/a.py`） |
| `files[].status` | str | - | - | `deprecated` など、検索で外したい状態だけ |

<!-- /table -->

```yaml
documents:
  - id: src
    paths: [src/files.yaml]
    schema: schemas/files.schema.yaml
    records: files
    body_file: path
```

起動時と読み直しのときに、メタデータと管理用の YAML のずれを数えて警告のログに残します。
ずれが 1 件でもあれば、配信元の ID・ずれの種類・件数・並びの値を種類ごとに 1 行で記録し、配信は止めません。

| ずれ | 内容 |
| --- | --- |
| `metadata` の列の欠け | `metadata` に書いた列が無い文書。書いていないキーは数えない |
| 索引に無いファイル | 管理用の YAML のフォルダの配下（下のフォルダを含む）のファイルのうち、`files[]` に無いもの。管理用の YAML 自身と、`node_modules` などの読み飛ばすフォルダ、行の `exclude[]` に当たるファイル、[文書のメタデータ](../はじめに/コアコンセプト/文書のメタデータ.md) の「載せるファイルの判定」の除外の条件に当たるファイルは数えない |
| ファイルが無い行 | `files[].path` が指すファイルが無い行 |

### validators[]・converters[]・generators[]

<!-- table: data -->

| キー | 型 | 必須 | 既定 | 説明 |
| --- | --- | --- | --- | --- |
| `validators[].id` | str | ✅ | - | 主キー |
| `validators[].run` | list[str] | ✅ | - | 配信元のフォルダで実行するコマンド。標準入力に文書の YAML、終了コードと標準出力の JSON（違反の一覧）で結果を返す |
| `validators[].on` | list | - | `[write]` | 通す時点。`read`（読むとき。不合格は警告として返す）・`write`（書くとき。不合格なら書かない） |
| `converters[].id` | str | ✅ | - | 主キー |
| `converters[].run` | list[str] | ✅ | - | 標準入力に文書の YAML、標準出力に Markdown を返すコマンド |
| `converters[].cache` | bool | - | `true` | `false` の行の変換は、変換の結果を控えず（控えがあっても読まず）、文書を開くたびにスクリプトを動かす。本文の外のファイルを読む変換で使う。`validators[]`・`generators[]` は持たない |
| `generators[].id` | str | ✅ | - | 主キー |
| `generators[].run` | list[str] | ✅ | - | 書き込んだ文書のパスを引数に受けるコマンド |

`run` の先頭のコマンドは、`/` を含めば配信元のフォルダからのパス、含まなければ PATH から引き、PATH に無ければ dev-docs を動かしている Python の環境の `bin` から引きます。
スクリプトは 1 回ごとに `script_timeout_sec` の制限時間があります。
超えたスクリプトは止めて失敗として返します。

### nav

文書の画面の種類のタブとサイドバーの構成です。
`nav` が無ければ、文書の行ごとにタブを作り、`auto: {document: 行の id, group_by: '@folder'}` でフォルダごとに束ねます。

<!-- table: data -->

| キー | 型 | 説明 |
| --- | --- | --- |
| `nav.tabs[]` | list | 画面上部のタブの並び |
| `nav.tabs[].title` | str | タブに出す名前 |
| `nav.tabs[].items[]` | list | サイドバーの項目。`group`・`page`・`auto` のどれか |
| `….group` | str | サイドバーの見出し。子の `items[]` を持ち、入れ子にできる |
| `….page` | str | ページの文書。1 ファイルだけの行は `documents[].id`、複数ファイルの行の 1 つは `{行の id}/{文書の ID}` |
| `….auto` | obj | 行の文書をページとして並べる。`document` に行の ID、`group_by` でメタデータごとにグループにする。`document` を省くと全ての行の文書を対象にする |
| `….auto.group_by` | str | 項目のパス（`tags.lang`・`kind` 等）か `'@folder'`。`'@folder'` は、行の `paths` の glob のワイルドカードより前のフォルダを起点に、フォルダごとの入れ子の group にする。各フォルダの `index.yaml` の文書を先頭に並べ、起点の直下の文書は group に入れない。管理用の YAML の行の文書は束ねない |
| `….auto.filter` | obj | `auto` で並べる文書を絞る条件。`search_docs` の `filter` と同じ書式（`and`・`or`・`not` の入れ子）。書かなければ対象の文書を全て並べる |
| `….title` | str | サイドバーに出す名前の上書き。既定は文書の名前 |

<!-- /table -->

同じタブで手で書いた `page`（`group` の中を含む）が指す文書は、`auto` の結果から除きます。
`auto.filter` がどの文書にも当たらないときは、起動時と `check_project` が警告します。
`filter` の書式が誤っているときは、そのタブを空にして違反として返します。
`nav` は管理の MCP の `write_nav` でも書けます。

```yaml
nav:
  tabs:
    - title: 規約
      items:
        - auto: {document: rules, group_by: tags.lang}
    - title: MCP
      items:
        - auto:
            filter:
              and:
                - {field: tags, op: eq, values: [mcp]}
                - not: {field: tags, op: eq, values: [設計]}
    - title: 設計書
      items:
        - group: アーキテクチャ
          items:
            - page: architecture
```

## バージョンの移し替え

端末の設定と `dev-docs.yaml` の `version` を、dev-docs が読めるバージョンと比べます。
結果は `current`（同じ）・`old`（古い）・`newer`（新しい）で、管理の MCP の `status`・`check_project` で見られます。

`old` の設定は `dev-docs migrate` で移し替えます。
`version` より新しく、dev-docs が読めるバージョン以下の手順を古い順に当て、`version` を上げます。
手順は dev-docs のパッケージに入れ、`src/dev_docs/migrations/{settings|dev-docs}/{バージョン}/steps.yaml` に置きます。
`newer` の設定は移し替えず、dev-docs を更新します。

オプション・終了コード・手順の書き方は [CLI](./CLI.md)、更新の手順は [dev-docsを更新する](../使い方/dev-docsを更新する.md) にあります。

## 雛形

| ファイル | 内容 |
| --- | --- |
| `templates/settings.yaml` | 端末の設定の雛形。`/dev-docs:global-setup` が端末の設定の元にする。`settings.schema.yaml` の検証に通る |
| `templates/dev-docs.yaml` | 配信元に置く `dev-docs.yaml` の雛形。`dev-docs.schema.yaml` の検証に通る。プロンプトの行（`prompts`）と、`dev-docs prompt-doc` を呼ぶ `converters[]` の行（`prompt-doc`）を持つ |
| `templates/files.schema.yaml` | 管理用の YAML のスキーマ |
| `templates/prompt.schema.yaml` | プロンプトの YAML のスキーマ。knowledge の `schemas/prompt.schema.yaml` のコピー |

`/dev-docs:setup` が `content/prompts/` を見つけた配信元に書く行は次のとおりです。
`content/prompts/` の YAML 1 ファイルが 1 つの文書になり、`dev-docs prompt-doc`（[CLI](./CLI.md)）が変数の表・テンプレート・例のセクションを持つ Markdown にします。

```yaml
documents:
  - id: prompts
    paths: [content/prompts/**/*.yaml]
    title: プロンプト
    schema: schemas/prompt.schema.yaml
    converter: prompt-doc
    metadata:
      name: name
      description: description
      tags: tags
converters:
  - id: prompt-doc
    run: [dev-docs, prompt-doc]
nav:
  tabs:
    - title: プロンプト
      items:
        - auto: {document: prompts, group_by: kind}
```

`nav` の `group_by: kind` は、サイドバーをプロンプトの `kind` ごとにまとめます。
