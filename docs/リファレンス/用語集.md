# 用語集

配信元・作業中の配信元・種類（kind）・バージョンなどの用語

<!-- table: data -->

| 用語 | 意味 |
| --- | --- |
| 配信元 | `dev-docs.yaml` を置いたフォルダ 1 つ。dev-docs が文書を配る単位で、端末の設定の `sources[]` の 1 行が 1 つの配信元に当たる |
| 配信元の ID | 配信元の主キー。端末の設定の `sources[].id`（省略時は `dev-docs.yaml` の `name`）で、画面の API のパス（`/_api/sources/{source}/...`）と文書の MCP の引数 `source` に使う |
| 端末の設定 | `~/.config/dev-docs/settings.yaml`。Git の外に置き、配信元の一覧と権限・待ち受け・状態の置き場所を持つ |
| 配信元の設定 | `dev-docs.yaml`。配信する文書・検査・変換・画面の構成（#17）・説明を持つ。複数の YAML に分けると、端末の設定の `sources[].config` に並べた順にマージする |
| 作業場所 | エージェントが作業しているフォルダ（`cwd`）。権限の判定と書き込みの先を決める |
| 作業中の配信元 | 作業場所を含む配信元のフォルダのうち一番深いもの。`source` を省いた呼び出しが指す |
| scope | 配信元を使える作業場所の glob。`scope.read` は読める作業場所、`scope.write` は読み書きできる作業場所 |
| ワークツリー | Git の配信元の作業ツリー。配信元の設定の `worktrees` に当たるものだけを読み書きの先にできる |
| クローン本体 | ワークツリーでない、リポジトリの元の作業ツリー。Git の配信元では書き込まない |
| 文書 | 配信する 1 件の単位。`documents[].paths[]` に当たった 1 ファイル、または `records` の配列の 1 要素 |
| 種類（kind） | 文書の行（`documents[]` の 1 行）の ID。書き込みでスキーマと新しい文書の置き場所を決める。検索ではメタデータの 1 つとして絞る |
| スキーマ | 種類ごとの文書の構造を定める YAML。書き込みで変更後の文書を検査する |
| 検査（validator） | 配信元が持つスクリプト。書き込みの前などに文書を検査し、違反の一覧を返す |
| 変換（converter） | 文書の YAML を Markdown にする処理。既定はスキーマ駆動で、種類ごとに配信元のスクリプトに替えられる |
| 生成（generator） | 書き込んだ後に流す配信元のスクリプト |
| バージョン | 文書の内容のハッシュ（短縮）。`write_docs`・`delete_docs` の `expected_version` に渡して、読んだ後の変更を検知する |
| 設定のバージョン | 端末の設定と `dev-docs.yaml` の `version`。サーバーが読めるバージョンと比べて、古い設定の配信元を検出する |
| リビジョン | 読む時点。ブランチ・コミット・タグを `ref` で指し、省くと `default_ref` |
| 会話キー | `session_id` と `agent_id`。同じ会話で一度返した内容を、2 回目から省くために使う |
| タグ | 文書の分類。1 つの文書に複数付き、検索の絞り込みと `group_by` に使う |
| 関連（related） | 文書が別の文書を指す参照。`type` に関係の種類を持ち、`trace_related` でたどる |
| 共通のメタデータ | 文書の種類によらず、検索・関連のたどり・画面が同じように読むキー。`id`・`name`・`description`・`tags`・`related`・`status` とエイリアスのキー。行の `metadata` で、文書の列から取る（`ref`）か行の全文書に同じ値を入れる（`custom`）かを決める |
| 既定のメタデータ | 行の `defaults[]` で、`paths[]` の glob に当たる文書に付けるメタデータ。上から順に重ね、最後に文書自身のメタデータを重ねる |
| 管理用の YAML | YAML でない文書（ソースコードなど）のメタデータを `files[]` に 1 ファイル 1 行で持つ YAML。`records: files`・`body_file: path` の行で配信する |
| 文書の MCP | `/mcp` の 1 つの接続先で、6 つのツールを出す |
| 管理用プラグイン | Claude Code のプラグイン `dev-docs`。`.mcp.json`（文書の MCP・管理の MCP）・SessionStart と PreToolUse のフック・スキルを配り、ユーザースコープで入れる |
| 管理の MCP | `/_admin/mcp` の接続先で、`status`・`reload`・`restart`・`update`・`check_project`・`try_convert` の 6 つのツールを出す。`127.0.0.1` だけで待ち受け、作業場所では絞らない |
| 移し替え | 端末の設定と `dev-docs.yaml` を、新しい `version` の書き方に書き換えること。`dev-docs migrate` が手順を古い順に当てる |
| 索引の同期 | 管理用の YAML の行と範囲のファイルが合っていること。管理用の YAML に無いファイル・ファイルが無い行・`ref` の列が無い文書の件数が 0 なら合っている |
