# CLI

dev-docs serve と dev-docs migrate のサブコマンド・引数・終了コード

## 共通

`dev-docs` コマンドは `serve` と `migrate` の 2 つのサブコマンドを持ちます。
`dev-docs --version` で dev-docs のバージョンを表示します。

## dev-docs serve

端末の設定を読み、検証に通った配信元を 1 プロセス・1 ポートで、画面の API・文書の MCP（`/mcp`）・管理の MCP（`/_admin/mcp`）に配信します。
引数は持たず、環境変数で変えます。

| 環境変数 | 既定 | 説明 |
| --- | --- | --- |
| `DEV_DOCS_CONFIG` | `~/.config/dev-docs/settings.yaml` | 端末の設定のパス |
| `DEV_DOCS_PORT` | 端末の設定の `port`（既定 `8781`） | 待ち受けのポート。設定の `port` より優先する |

```bash
DEV_DOCS_CONFIG=/tmp/x/settings.yaml DEV_DOCS_PORT=8781 dev-docs serve
```

標準出力に、待ち受けたアドレスと配信している配信元の ID を出します。
検証に失敗した配信元は外して待ち受け、`{id}: {キーのパス}: {理由}` をエラーログに記録します。

| 終了コード | 意味 |
| --- | --- |
| 2 | 端末の設定が無い、またはスキーマに違反する。標準エラーに `{ファイル}: {キーのパス}: {理由}` を全て出す |
| 3 | ポートが使用中。標準エラーにポートの番号と、`DEV_DOCS_PORT` で変えられることを出す |

待ち受けた後は、停止の合図まで終わりません。
同じポートで待ち受けられるプロセスは 1 つだけで、後から起動したプロセスは終了コード 3 で終わります。

## dev-docs migrate

端末の設定か配信元の `dev-docs.yaml` の `version` を、dev-docs が読めるバージョンと比べ、移し替えの手順を古い順に当てます。
対象の `version` より新しく、dev-docs が読めるバージョン以下の手順を全て当て、新しいスキーマで検証してから 1 回だけ書き込みます。
動いているサーバーには反映しません。
端末の設定を移し替えたら `restart`、配信元の設定を移し替えたら `reload` を呼びます。

<!-- table: data -->

| オプション | 既定 | 説明 |
| --- | --- | --- |
| `--plan` | 適用する | 当てる手順の一覧を出して終わる。書き換えない |
| `--record` | - | 手順を当てず、`version` だけを今のバージョンに書き換える。手で移し替えたときに使う。`--plan` とは併用しない |
| `--source` | `DEV_DOCS_CONFIG` が指す端末の設定 | 配信元の `dev-docs.yaml` のパス。渡すとその配信元の設定を対象にする |
| `--allow-destructive` | 破壊的な手順があれば止める | キーの削除など、値を捨てる手順も当てる |

<!-- /table -->

```bash
dev-docs migrate --plan
dev-docs migrate --source ~/repo/sample/dev-docs.yaml
```

`--plan` は当てる手順を `{バージョン}: {手順の説明}` の 1 行ずつで出し、破壊的な手順には `[destructive]` を付けます。
適用は、当てた手順とバックアップのパスを出します。
バックアップは適用の前に必ず取り、同じフォルダへ `{ファイル名}.bak-{時刻}` で残します。成功しても消しません。

端末の設定は動いているサーバーと同じファイルなので、書き換えの前後でファイルの中身を比べ、変わっていたら書かずに失敗とします。

<!-- table: data -->

| 終了コード | 意味 | 動き |
| --- | --- | --- |
| 0 | 正常（当てる手順が無いときも含む） | - |
| 2 | 対象の設定が無い・YAML として読めない・`version` が無い | 何も書き換えず、バックアップも作らない |
| 4 | 手順の途中で失敗した、または当てた結果が新しいスキーマに違反した | ファイルに触らず、失敗した手順と理由を標準エラーに出す |
| 5 | 当てる手順に破壊的なものがあり、`--allow-destructive` が無い | ファイルに触らず、破壊的な手順を標準エラーに出す |
| 6 | 対象の `version` が dev-docs が読めるバージョンより新しい | dev-docs の更新を案内する |

<!-- /table -->

終了コード 3 は `dev-docs serve` のポート使用中に使うため、`migrate` は使いません。

### 移し替えの手順

手順はパッケージに入れ、`src/dev_docs/migrations/{settings|dev-docs}/{バージョン}/steps.yaml` に置きます。
`settings` は端末の設定、`dev-docs` は配信元の設定を、そのバージョンへ上げる手順です。
`steps.yaml` は `steps:` の下に、次のキーを持つ行を並べます。

| キー | 説明 |
| --- | --- |
| `op` | `rename`（キーの改名）・`add`（無いキーだけを既定値つきで追加）・`delete`（キーの削除。破壊的な手順） |
| `path` | キーのパス。ドットで結び、配列の要素の子は `sources[].scope` のように書く |
| `to` | 新しいキー。`rename` のときだけ。同じ親の下のキー名 |
| `value` | 既定値。`add` のときだけ。キーが既にあれば書き換えない |
| `description` | `--plan` に出す 1 行の説明 |

`rename` は同じ位置で改名し、コメントを残します。
改名先のキーが既にあるときは失敗とします。
