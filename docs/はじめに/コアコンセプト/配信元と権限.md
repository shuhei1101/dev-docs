# 配信元と権限

配信元・作業中の配信元・scope による権限・ワークツリーへの読み替え・設定のマージの仕組み

## 配信元

配信元は、`dev-docs.yaml` を置いたフォルダ 1 つで、dev-docs が文書を配る単位です。
Git のリポジトリの直下のほか、リポジトリの中の任意のフォルダや、Git 管理外のフォルダも配信元にできます。

配信元が持つのは `dev-docs.yaml`・文書の YAML・スキーマ・検査と変換のスクリプトだけで、サーバーのコードもプラグインも持ちません。
dev-docs の 1 つのプロセスが、端末の設定の `sources[]` に並べた配信元をすべて配ります。

| 入口 | 内容 |
| --- | --- |
| 文書の MCP | `/mcp` の 1 つ。配信元は引数 `source` で指す |
| 画面の API | `/_api/sources/{配信元の id}/docs`（文書の取得）・`/_api/settings/sources`（端末の設定の取得）など。JSON のキーは camelCase（`defaultRef`・`updatedAt` など）で、エラーは `application/problem+json`。画面（文書の画面・設定画面・見つからない画面）はこの API を呼び、同じポートの `/` で開く |

## 作業場所と作業中の配信元

エージェントが呼び出した作業場所（`cwd`）が、権限の判定と読み書きの先を決めます。
`cwd` は管理用プラグインのフックが文書の MCP の引数に入れるので、エージェントが指定した値は使いません。

作業中の配信元は、`cwd` を含む配信元のフォルダのうち一番深いものです。
文書の MCP の `source` を省くと、作業中の配信元を指します。

## scope による権限

端末の設定の `sources[].scope` に、その配信元を使える作業場所を glob で並べます。

| キー | 意味 |
| --- | --- |
| `scope.read` | この配信元を読める作業場所 |
| `scope.write` | この配信元を読み書きできる作業場所。省略すると配信元のフォルダだけ |

- `/**` を付けないパスは、そのフォルダだけに当たる
- `/**` を付けると、中のフォルダにも当たる
- `scope.write` に当たる作業場所は、その配信元を読むこともできる
- どちらにも当たらない作業場所からは、その配信元を使えない

当たらない配信元を指した呼び出しは断り、今の作業場所から使える配信元の一覧を返します。
この一覧は `describe` を引数なしで呼んだ結果と同じです。

`scope.write` は極力小さくします。
Git 管理外の配信元は、書き込みの先が 1 か所に決まるので、広くしても構いません。

### 作業範囲の外を参考に読む

`scope` に当たらない配信元も、`describe`・`search_docs`・`trace_related`・`list_changes` に `outside_scope: true` と `source`（ID 1 つ）を渡すと、作業範囲の外（参考）として読めます。
`scope.read` を広げずに、別の配信元の文書を一時的に参照するときに使います。

- 返す結果には「作業範囲の外（参考）」の表示が付く
- 外から読んだ呼び出しは、作業場所（`cwd`）と配信元の ID を要求のログに残す
- `source` に配列・`*` を渡したときと、引数なしの `describe()` の一覧には、作業範囲の外の配信元を含めない

端末の設定の `sources[].outside_read` を `false` にした配信元は、`outside_scope: true` でも読めません。
既定は `true` です。
`outside_read` が `true` の配信元を `outside_scope` なしで指して断られたときは、エラーの直し方が `outside_scope: true` を案内します。

## ワークツリーへの読み替え

配信元の設定の `worktrees` は、その配信元のワークツリーの場所の glob です。
既定は `[./.claude/worktrees/*]` で、リポジトリの外に置いたワークツリーは絶対パスで記載します。
相対パスは、メインのリポジトリの直下（`git rev-parse --git-common-dir` の親）から数えます。
端末の設定がワークツリーの `dev-docs.yaml` を指していても、ほかのワークツリーに当たります。

`cwd` が `worktrees` に当たるワークツリーの中なら、次のように扱います。

- `scope` の判定では、配信元のフォルダにいるものとみなす
- 読み書きは、そのワークツリーの同じ相対パスの設定と文書に向ける

ワークツリーを追加・削除しても、端末の設定は変えません。

読み書きのツールは `worktree`（ワークツリーのパス）の引数も受けます。
`worktrees` に当たるパスだけを受け、当たらないパスは断ります。
エージェントがクローン本体で起動してワークツリーをパスで指して作業するときは、`worktree` を指定します。

## 書き込みの先

| 配信元 | 書き込みの先 |
| --- | --- |
| Git の配信元 | ワークツリーだけ。書く先がクローン本体になるときは断る |
| Git 管理外の配信元 | `scope.write` に当たれば、そのフォルダ |

dev-docs は commit しません。
変更を当てた後の文書が、配信元のスキーマと `validators[]` に通ったときだけ、ファイルを書き換えます。

## 読むリビジョン

| 読み方 | リビジョン |
| --- | --- |
| `ref` を省く（画面の API・MCP の Git の配信元で、作業中の配信元以外） | 配信元の `default_ref`（既定 `develop`） |
| `ref` を指す（画面の API の `ref` クエリ・MCP の `ref`） | 指したブランチ・コミット・タグ |
| 作業中の配信元を MCP で読む | 呼び出した作業場所の作業ツリー |
| Git 管理外の配信元 | フォルダをそのまま読む。`ref` は使えない |

## 設定のマージ

1 つの配信元の設定は、複数の YAML に分けられます。
端末の設定の `sources[].config` に並べた順に読み、マージした結果が配信元の設定のスキーマを満たせば有効です。
ファイル名に決まりはありません。

| 値の種類 | マージの仕方 |
| --- | --- |
| 値（`name`・`default_ref` など） | 後のファイルの値で上書きする |
| オブジェクト（`nav` など） | キーごとに再帰的にマージする |
| テーブル（`documents[]`・`validators[]`・`converters[]`・`generators[]`） | `id` が同じ行は後のファイルの行で上書きし、新しい `id` の行は追加する |
| 値の配列（`worktrees[]` など） | 後のファイルの配列で置き換える |

Git の中に共通の設定を置き、その環境だけの設定を Git の外に置いて配列の後ろに並べる、という使い方ができます。
先頭のファイルのフォルダが、配信元のフォルダになります。

キーの一覧は [設定](../../リファレンス/設定.md) にあります。
