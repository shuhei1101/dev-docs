# 文書のメタデータ

メタデータの対応・既定の重ね方・名前の既定・管理用の YAML の仕組み

## 共通のメタデータ

文書の種類によらず、検索・関連のたどり・画面は同じキーのメタデータを読みます。
共通のキーは `id`・`name`・`description`・`tags`・`related`・`status` と、エイリアスのキー（`alias_type`・`aliases`・`command`・`cwd`・`url`・`avoid`・`skill`・`tool`・`path`・`port`・`replacement`）です。

文書の行（`documents[]`）の `metadata` で、キーごとに値の取り方を決めます。

| 取り方 | 記載 | 値 |
| --- | --- | --- |
| `ref` | `{type: ref, field: 列名}` | 文書の列から取る。入れ子の列は `meta.summary` のように `.` でつなぐ |
| `custom` | `{type: custom, value: 値}` | 行の全文書に同じ値を入れる |

`metadata` に書かなかったキーは、同じ名前の列の `ref` になります。

## 既定の重ね方

行の `defaults[]` は、`paths[]` の glob に当たる文書に共通のメタデータを付けます。
上の要素から順に重ね、最後に文書自身のメタデータを重ねます。

| キー | 重ね方 |
| --- | --- |
| `tags`・`related` | 和集合 |
| ほかのキー | 後に重ねた値が優先 |

`body_file` のある要素は、`body_file` が指すファイルのパスで glob に当てます。

## 名前の既定

重ねた後も `name` が空の文書は、ファイル名から拡張子を除いた名前になります。
`records` の要素は `body_file` が指すファイルの名前で、`body_file` が無ければ文書の `id` です。
検索・関連のたどり・画面の API は、この既定を入れた後の `name` を読みます。

## 管理用の YAML

ソースコードなど YAML でない文書は、タグや概要文を自分では持てません。
管理用の YAML の `files[]` に 1 ファイル 1 行で記載すると、行ごとに 1 つの文書として配信されます。

```yaml
files:
  - path: a.py
    tags: [auth]
  - path: b.py
    name: 部品 B
```

文書の行は `records: files`・`body_file: path` で管理用の YAML を指します。
文書の `id` は `body_file` が指すファイルの拡張子を除いたパス（`src/a`）で、本文はそのファイルの内容です。
`files[].path` の値は、メタデータのキー `path` に入ります。

キーの一覧とスキーマ `templates/files.schema.yaml` は [設定](../../リファレンス/設定.md) の「管理用の YAML」にあります。

### ずれの検出

メタデータは、文書の列や管理用の YAML が変わるとずれます。
サーバーは起動時と読み直しのときに、次のずれを数えて警告のログに残し、配信は止めません。

| ずれ | 内容 |
| --- | --- |
| `ref` の列の欠け | `metadata` に明示した `ref` の列が無い文書。書いていないキーの既定の `ref` は数えない |
| 索引に無いファイル | 管理用の YAML のフォルダの配下で、`files[]` に記載されていないファイル |
| ファイルが無い行 | `files[].path` が指すファイルが無い行 |
