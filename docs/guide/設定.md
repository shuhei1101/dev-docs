# 設定

端末の設定のキーと、画面が読む project-index.yaml のキーの一覧

設定は、dev-docs の端末の値（`${XDG_CONFIG_HOME:-~/.config}/dev-docs/settings.yaml`、Git の外）と、配信元の値（`project-index.yaml`）に分かれます。
dev-docs の端末の設定のスキーマは dev-docs が持ち、起動時に検証します。
配信元の設定と、端末の設定の `sources[]` は project-index が持ちます。キーの一覧は project-index の [設定](https://github.com/shuhei1101/project-index/blob/develop/docs/guide/%E8%A8%AD%E5%AE%9A.md) にあります。

## ファイル

| ファイル | 管理する値 |
| --- | --- |
| `${XDG_CONFIG_HOME:-~/.config}/dev-docs/settings.yaml` | dev-docs の端末の値（クローンの場所・待ち受け・project-index の接続先・状態の置き場所） |
| `project-index.yaml`・`project-index.local.yaml` | 配信元の値（配信する文書・検査・変換・画面のタブとサイドバーの構成・説明）。project-index が読む |

## 環境変数

| 環境変数 | 型 | 既定 | 説明 |
| --- | --- | --- | --- |
| `DEV_DOCS_CONFIG` | str | `${XDG_CONFIG_HOME:-~/.config}/dev-docs/settings.yaml` | 端末の設定のパス |
| `DEV_DOCS_PORT` | int | 端末の設定の `port` | 待ち受けのポート。設定の `port` より優先する |
| `XDG_CONFIG_HOME` | str | `~/.config` | `DEV_DOCS_CONFIG` が無いときに端末の設定を探すフォルダの親。空の文字列か相対パスは未設定として扱う |
| `DEV_DOCS_STATE_DIR` | str | 端末の設定の `state_dir` | 状態の置き場。端末の設定の `state_dir` より優先する |
| `XDG_STATE_HOME` | str | `~/.local/state` | `DEV_DOCS_STATE_DIR` と `state_dir` が無いときの状態の置き場の親。空の文字列か相対パスは未設定として扱う |

## 端末の設定 settings.yaml

反映の列は、変えた後に何が要るかを表します。

<!-- table: data -->

| キー | 型 | 必須 | 既定 | 説明 | 反映 |
| --- | --- | --- | --- | --- | --- |
| `version` | str | ✅ | - | 設定のバージョン（`"2"` 以下）。古ければ `dev-docs migrate` で移し替える | 再起動 |
| `clone` | str | ✅ | - | dev-docs のクローンの場所。管理用プラグインのフックが `dev-docs serve` を起動するクローン | 即時 |
| `port` | int | - | `8781` | 画面・画面の API・管理の MCP を待ち受ける 1 つのポート | 再起動 |
| `bind` | str | - | `127.0.0.1` | 待ち受けるアドレス | 再起動 |
| `project_index` | str | - | `http://127.0.0.1:8786` | 文書・検索・リビジョン・配信元の状態を問い合わせ、`sources[]` の保存を依頼する project-index のアドレス | 再起動 |
| `state_dir` | str | - | `${XDG_STATE_HOME:-~/.local/state}/dev-docs` | 表の列の設定を置くフォルダ | 再起動 |
| `log_dir` | str | - | `{state_dir}/logs` | project-index につながらないことと警告のログを書くフォルダ | 再起動 |
| `sources[]` | list | - | - | `version: "1"` の端末の設定の配信元の行。`dev-docs migrate` が project-index へ移し、同じ id で内容の違う行だけが残る。配信には使わず、起動と `status` が行の ID を知らせる | 再起動 |

<!-- /table -->

```yaml
version: "2"
clone: /home/me/repo/dev-docs
project_index: http://127.0.0.1:8786
```

## 画面が読む project-index.yaml のキー

`project-index.yaml` のうち、画面の表示を決めるキーです。
project-index が読み、dev-docs の画面は project-index の読み取り API で取得します。

### 種類のスキーマの表示のキーワード

`converter` を持たない行の YAML の文書は、種類のスキーマの次のキーワードに沿って画面の本文にします。
キーワードは項目のスキーマに記載します。

<!-- table: data -->

| キーワード | 値 | 説明 |
| --- | --- | --- |
| `title` | str | 見出し・表の列名・項目の名前 |
| `x-heading` | str | 項目の前に置く見出し |
| `x-shape` | `body` / `table` / `sections` / `list` / `diagram` / `attributes` | 項目の表し方。`diagram` は図と閉じた元データの表、`attributes` は「項目 / 値」の表 |
| `x-key` | str | `sections` の要素の見出しにするキー |
| `x-diagram` | `flowchart` / `dataflow` / `architecture` / `state` / `er` | `x-shape: diagram` の図の種類。どれも mdmark の map で描く。`er` は `erDiagram`（列を持たない実体は同じ文書の `tables[]` の列で補う）、`state` は `stateDiagram-v2`、それ以外は `flowchart` にする |
| `x-hidden` | bool | `true` の項目と表の列を本文に出さない |

<!-- /table -->

### nav

文書の画面の種類のタブとサイドバーの構成です。
`nav` が無ければ、文書の行ごとにタブを作り、`auto: {document: 行の id, group_by: '@folder'}` でフォルダごとに束ねます。

<!-- table: data -->

| キー | 型 | 説明 |
| --- | --- | --- |
| `nav.tabs[]` | list | 画面上部のタブの並び |
| `nav.tabs[].title` | str | タブに出す名前 |
| `nav.tabs[].items[]` | list | サイドバーの項目。`group`・`page`・`auto` のどれか |
| `….group` | str | サイドバーの見出し。子の `items[]` を持ち、入れ子にできる |
| `….page` | str | ページの文書。1 ファイルだけの行は `documents[].id`、複数ファイルの行の 1 つは `{行の id}/{文書の ID}` |
| `….auto` | obj | 行の文書をページとして並べる。`document` に行の ID、`group_by` でメタデータごとにグループにする。`document` を省くと全ての行の文書を対象にする |
| `….auto.group_by` | str | 項目のパス（`tags.lang`・`kind` 等）か `'@folder'`。`'@folder'` は、行の `paths` の glob のワイルドカードより前のフォルダを起点に、フォルダごとの入れ子の group にする。各フォルダの `index.yaml` の文書を先頭に並べ、起点の直下の文書は group に入れない。管理用の YAML の行の文書は束ねない |
| `….auto.filter` | obj | `auto` で並べる文書を絞る条件。`search_docs` の `filter` と同じ書式（`and`・`or`・`not` の入れ子）。書かなければ対象の文書を全て並べる |
| `….title` | str | サイドバーに出す名前の上書き。既定は文書の名前 |

<!-- /table -->

同じタブで手で書いた `page`（`group` の中を含む）が指す文書は、`auto` の結果から除きます。
`auto.filter` がどの文書にも当たらないときは、project-index の配信元の検査が警告します。
`filter` の書式が誤っているときは、そのタブを空にして違反として返します。
`nav` は project-index の管理の MCP の `write_nav` でも書けます。

```yaml
nav:
  tabs:
    - title: 規約
      items:
        - auto: {document: rules, group_by: tags.lang}
    - title: MCP
      items:
        - auto:
            filter:
              and:
                - {field: tags, op: eq, values: [mcp]}
                - not: {field: tags, op: eq, values: [設計]}
    - title: 設計書
      items:
        - group: アーキテクチャ
          items:
            - page: architecture
```

## バージョンの移し替え

端末の設定の `version` を、dev-docs が読めるバージョンと比べます。
結果は `current`（同じ）・`old`（古い）・`newer`（新しい）で、管理の MCP の `status` で見られます。

`old` の設定は `dev-docs migrate` で移し替えます。
`version` より新しく、dev-docs が読めるバージョン以下の手順を古い順に当て、`version` を上げます。
手順は dev-docs のパッケージに入れ、`src/dev_docs/migrations/settings/{バージョン}/steps.yaml` に置きます。
`newer` の設定は移し替えず、dev-docs を更新します。
配信元の設定の `version` の移し替えは project-index で行います。

オプション・終了コード・手順の書き方は [CLI](./CLI.md)、更新の手順は [dev-docsを更新する](./dev-docsを更新する.md) にあります。

## 雛形

| ファイル | 内容 |
| --- | --- |
| `templates/settings.yaml` | 端末の設定の雛形。`/dev-docs:global-setup` が端末の設定の元にする。`settings.schema.yaml` の検証に通る |

配信元の設定（`project-index.yaml`）・管理用の YAML・プロンプトの雛形とスキーマは project-index が持ちます。
