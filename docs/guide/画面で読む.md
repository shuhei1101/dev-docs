# 画面で読む

文書の画面で配信元の文書を読み、コメントを渡し、設定画面で配信元を追加する手順

## 画面を開く

サーバーを起動し（[配信元を配信する](./配信元を配信する.md)）、ブラウザで `http://127.0.0.1:{port}/` を開きます。
既定のポートは `8781` です。
画面は、配信元の文書・検索・リビジョンを要求ごとに project-index から取得します。

| 画面 | URL |
| --- | --- |
| 文書の画面 | `/{配信元の ID}/{文書のパス}?rev={リビジョン}&base={比較元}`。文書のパスを省いた `/{配信元の ID}` は、配信元のトップ（一番左のタブの一番上の文書） |
| 設定画面 | `/_settings` |

`/` は配信中の配信元の先頭のトップへ移り、配信中の配信元が無ければ設定画面へ移ります。
無い配信元・リビジョン・文書の URL は、URL を変えずに見つからない画面を出します。
見つからない画面は、見つからなかったものと、配信元のトップ・設定画面へのリンクを出します。
project-index につながらないときは、文書の画面は画面全体に、設定画面は配信元の一覧の場所に「project-index に接続できませんでした」の表示と、接続先・理由・`再読み込み` を出します。project-index を起動してから `再読み込み` を押します。

## 文書を読む

トップバーで読む配信元とリビジョンを選びます。
文書の画面は、種類のタブ・サイドバー・パンくず・本文・目次で 1 文書を読みます。

<!-- table: data -->

| やりたいこと | 操作 |
| --- | --- |
| 配信元を切り替える | トップバーの配信元のメニューで選ぶ。選んだ配信元のトップを開く |
| リビジョンを切り替える | トップバーのリビジョンのメニューで、ブランチ・タグ・最近の commit から選ぶ。同じ文書を `rev` に指したリビジョンで開く。`rev` を省くと配信元の `default_ref` を読む |
| 文書の種類を切り替える | 種類のタブを押す。`nav` に並べた順に出て、そのタブの一番上の文書を開く |
| 文書を開く | サイドバーの文書を押す。`rev` と `base` を保ったまま開く |
| 階層に戻る | パンくずの配信元の ID かタブ名を押す |
| 見出しへ移る | 本文の右端の目次の線を指すかフォーカスして目次を出し、見出しを押す。本文の幅が 48rem 未満のときは、本文の上の帯の `目次を表示` を押して目次を出す |
| 明暗を切り替える | トップバーの明暗のボタンを押す。ブラウザに保存する |

<!-- /table -->

種類のタブとサイドバーは、スクロールしても画面に残ります。
画面幅が 48rem 未満のときは、サイドバーを文書の一覧のドロワーで開きます。

本文の変換に失敗した文書は、本文の代わりに変換できなかった理由と次にすることを出します。
直したら `再読み込み` を押します。

### タグの式で絞った一覧を開く

`project-index.yaml` の `nav` の `auto` に `filter` を書いたタブは、その条件に当たる文書だけをサイドバーに並べます。
条件は `search_docs` の `filter` と同じ書式で、`and`・`or`・`not` を入れ子にできます（[設定](./設定.md) の「nav」）。
よく使う絞り込みをタブにしておくと、タブを押すだけで絞った一覧を開けます。
タブは管理の MCP の `write_nav` でも追加・修正できます。

### 図を操作する

設計書の図（フロー図・データフロー・構成図・状態遷移図・ER 図・シーケンス図）は、mdmark の map で描きます。

<!-- table: data -->

| やりたいこと | 操作 |
| --- | --- |
| グループの中だけを見る | グループのタイトルを押す。右上の戻るボタンか Esc で外へ戻る |
| グループを閉じる・開く | グループの開閉のボタンを押す |
| ノード・テーブルとつながる線を強調する | ノード・テーブル・線を押す。ほかが薄くなる |
| 状態遷移・シーケンスを順に追う | 図の下の帯の前へ・次へ・自動で進めるを押す |
| ER 図のテーブルの列を畳む | テーブルの開閉のボタンを押す |

<!-- /table -->

### 本文の用語のツールチップを見る

配信元に `alias_type` を持つ documents の行があると、本文の語のうち、その行の文書の `name` か `aliases` に当たる語にツールチップが付きます。
語にポインタを載せるかフォーカスすると、用語の名前と `description` が出ます。
`alias_type` が `doc` の文書は、文書の別名（関連文書）として出ます。
`alias_type` を持つ行が無い配信元の文書は、ツールチップを付けずに描きます。

## 検索する

Ctrl+K（macOS は ⌘K）か `/` で検索のダイアログを開きます。
トップバーの検索のボタンからも開けます。
語を入れると、開いている配信元・リビジョンの文書を、件数と一致した箇所つきで並べます。
結果を選ぶと、`rev` を保ったままその文書を開きます。
Esc を 1 回押すと閉じます。

`?` でショートカットの一覧を開きます。
`/` と `?` の 1 文字のショートカットは、設定画面のキーボードのセクションで切り替えます。

## 差分を見る

Git の配信元では、リビジョンの間の差分を見られます。

<!-- steps -->

1. トップバーのリビジョンのメニューで、比較を始める。
   開いているリビジョンが `default_ref` 以外なら `default_ref` を、`default_ref` なら最近の commit の 2 件目を比較元にする。
2. 本文の上の差分の案内で、`比較元` と `比較先` を選ぶ。
   選ぶと、URL の `base` と `rev` が変わる。
3. サイドバーの文書と本文で、比較元からの変化を確かめる。
   サイドバーの文書には追加・変更・削除のマーカーが付く。
   本文では、比較元から変わった箇所が強調される。
4. `差分の強調を解除` を押して、比較先の通常の表示に戻す。

<!-- /steps -->

## コメントを渡す

本文の文字列を選んでコメントを保存し、まとめてコピーするか、GitHub の Issue にします。
コメントは、ブラウザのタブの `sessionStorage` に保存します。
再読み込みしても残り、タブを閉じると消えます。
サーバーには送信しません。

<!-- steps -->

1. 本文の文字列を選び、出たコメントのボタンを押してコメントを入力し、保存する。
   コメントのパネルが開き、一覧とトップバーの件数に加わる。
2. コメントのパネルで、コピーや起票に含めるコメントを選ぶ。
   追加したコメントは選んだ状態になる。`すべて選択` でまとめて選べる。
3. `選択 {件数} 件をコピー` を押す。
   選んだコメントを一覧の順に、配信元の ID・リビジョン・文書のパス・見出し・引用・本文でクリップボードへコピーする。
4. 起票するときは `Issue を作成` を押す。
   選んだコメントの全文をクリップボードへコピーしてから、GitHub の Issue の作成画面を別のタブで開く。

<!-- /steps -->

`Issue を作成` は、`project-index.yaml` の `github.repository` を記載した配信元だけに出ます。
起票するラベルは `github.issue_labels[]` に記載します（[設定](./設定.md)）。
Issue の作成画面の URL が長さの上限を超えるときは、本文の末尾を切り詰めて開きます。
全文はクリップボードに残ります。

## 設定画面を使う

トップバーの歯車で設定画面（`/_settings`）を開きます。
project-index の端末の設定の `sources[]` を、project-index が返した配信元ごとの状態とともに並べます。
追加・編集・削除は project-index の端末の設定へ保存を依頼し、project-index が配信元を読み直します。

| 状態 | 意味 |
| --- | --- |
| 配信中 | 配信している。配信元の ID を押すと、その配信元のトップを開く |
| 配信停止 | project-index が検証で外した。理由が状態の下に出る |
| 無効 | `enabled` が `false` |
| 再読み込み待ち | 設定ファイルにはあるが、まだ読み直していない |

配信元を追加するには、次の手順を行います。

<!-- steps -->

1. `配信元を追加` を押す。
2. ダイアログに入力する。
   配信元の ID は英小文字・数字・ハイフンで入力する。
   設定ファイルは `project-index.yaml` のパスを 1 行に 1 つ入力する。
   読み取りの範囲は必須、書き込みの範囲は任意で、どちらも作業場所の glob を 1 行に 1 つ入力する。
   `配信` のスイッチを外すと、設定を残したまま配信を止める。
   `範囲の外から参照できるようにする` のスイッチを外すと、読み取りの範囲に当たらない作業場所からは参照できなくなり、一覧の ID の下に `範囲の外から参照できません` が出る。
3. `追加` を押す。
   スキーマに通ると project-index が端末の設定を保存し、配信元を読み直す。
   通らないときはダイアログを開いたまま、保存の失敗のまとめと項目のエラーを出す。

<!-- /steps -->

設定画面を開いた後に他のプロセスが端末の設定を変更していたときは、保存・削除せずに `他の変更があったため保存できませんでした`（削除は `削除できませんでした`）を出し、一覧を最新の内容にします。
入力した値はダイアログに残るので、内容を確認してもう一度保存します。
編集・削除していた配信元が他のプロセスに削除されていたときは、`配信元が削除されたため保存できませんでした` を出し、保存できません。

編集は一覧の鉛筆のボタン、削除はごみ箱のボタンで行います。
削除は、project-index の端末の設定から配信元の行を削除して配信から外します。
配信元のフォルダと文書は削除しません。

## スマホで使う

幅 360px 以上の画面を扱います。
スマホで使える操作は、読む・検索・コメントのコピーまでです。
設定画面の編集は、PC で行います。
