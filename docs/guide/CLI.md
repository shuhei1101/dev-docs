# CLI

dev-docs serve・dev-docs migrate のサブコマンド・引数・終了コード

## 共通

`dev-docs` コマンドは `serve`・`migrate` のサブコマンドを持ちます。
`dev-docs --version` で dev-docs のバージョンを表示します。
`files`・`prompt-doc` と、配信元の設定の移し替えは [project-index](https://github.com/shuhei1101/project-index) のコマンドです。

## dev-docs serve

端末の設定を読み、1 プロセス・1 ポートで画面・画面の API・管理の MCP（`/_admin/mcp`）を配信します。
配信元の文書・検索・リビジョンは、端末の設定の `project_index` の project-index に要求ごとに問い合わせます。
引数は持たず、環境変数で変えます。

| 環境変数 | 既定 | 説明 |
| --- | --- | --- |
| `DEV_DOCS_CONFIG` | `${XDG_CONFIG_HOME:-~/.config}/dev-docs/settings.yaml` | 端末の設定のパス |
| `DEV_DOCS_PORT` | 端末の設定の `port`（既定 `8781`） | 待ち受けのポート。設定の `port` より優先する |
| `XDG_CONFIG_HOME` | `~/.config` | `DEV_DOCS_CONFIG` が無いときに端末の設定を探すフォルダの親。空の文字列か相対パスは未設定として扱う |
| `DEV_DOCS_STATE_DIR` | 端末の設定の `state_dir` | 状態の置き場。端末の設定の `state_dir` より優先する |
| `XDG_STATE_HOME` | `~/.local/state` | `DEV_DOCS_STATE_DIR` と `state_dir` が無いときの状態の置き場の親。空の文字列か相対パスは未設定として扱う |
| `DEV_DOCS_PROMPTS_DIR` | クローンの直下の `content/prompts/` | 管理の MCP のツールの description のプロンプトの YAML を読むフォルダ |

```bash
DEV_DOCS_CONFIG=/tmp/x/settings.yaml DEV_DOCS_PORT=8781 dev-docs serve
```

標準出力に、待ち受けたアドレスと、project-index が配信している配信元の ID を出します。
project-index につながらないときも待ち受けを続け、つながらなかったアドレスと、project-index を起動する案内を標準エラーとエラーログに出します。その間、画面の API は 503 を返します。
端末の設定に前のバージョンの `sources` が残っていると、行の ID を警告のログに出します。

| 終了コード | 意味 |
| --- | --- |
| 2 | 端末の設定が無い、またはスキーマに違反する。標準エラーに `{ファイル}: {キーのパス}: {理由}` を全て出す |
| 3 | ポートが使用中。標準エラーにポートの番号と、`DEV_DOCS_PORT` で変えられることを出す |
| 4 | プロンプトの YAML が無い・読めない・スキーマに違反する・描画できない。標準エラーに `{ファイル}: {キーのパス}: {理由}` を全て出す |

待ち受けた後は、停止の合図まで終わりません。
同じポートで待ち受けられるプロセスは 1 つだけで、後から起動したプロセスは終了コード 3 で終わります。

## dev-docs migrate

端末の設定の `version` を、dev-docs が読めるバージョンと比べ、移し替えの手順を古い順に当てます。
対象の `version` より新しく、dev-docs が読めるバージョン以下の手順を全て当て、新しいスキーマで検証してから 1 回だけ書き込みます。
動いているサーバーには反映しません。
移し替えたら `restart` を呼びます。

<!-- table: data -->

| オプション | 既定 | 説明 |
| --- | --- | --- |
| `--plan` | 適用する | 当てる手順の一覧を出して終わる。書き換えない |
| `--record` | - | 手順を当てず、`version` だけを今のバージョンに書き換える。手で移し替えたときに使う。`--plan` とは併用しない |
| `--project-index` | `http://127.0.0.1:{PROJECT_INDEX_PORT}`（`PROJECT_INDEX_PORT` が無ければ 8786） | `sources` を移す先の project-index のアドレス。端末の設定の `project_index` にも書く |
| `--allow-destructive` | 破壊的な手順があれば止める | キーの削除など、値を捨てる手順も当てる |

<!-- /table -->

```bash
dev-docs migrate --plan
dev-docs migrate --project-index http://127.0.0.1:8786
```

`--plan` は当てる手順を `{バージョン}: {手順の説明}` の 1 行ずつで出し、破壊的な手順には `[destructive]` を付けます。
適用は、当てた手順とバックアップのパスを出します。
バックアップは、全ての手順を当てて検証に通った後、書き込む前に同じフォルダへ `{ファイル名}.bak-{時刻}` で残します。成功しても消しません。
失敗して書き込まないときは、ファイルにもバックアップにも触りません。

端末の設定は動いているサーバーと同じファイルなので、書き換えの前後でファイルの中身を比べ、変わっていたら書かずに失敗とします。

<!-- table: data -->

| 終了コード | 意味 | 動き |
| --- | --- | --- |
| 0 | 正常（当てる手順が無いときも含む） | - |
| 2 | 対象の設定が無い・YAML として読めない・`version` が無い | 何も書き換えず、バックアップも作らない |
| 4 | 手順の途中で失敗した、当てた結果が新しいスキーマに違反した、または project-index が端末の設定の取得・保存を受け付けなかった | ファイルに触らず、失敗した手順と理由を標準エラーに出す。project-index が受け付けなかった行は `{ID}: {理由}` で出す |
| 5 | 当てる手順に破壊的なものがあり、`--allow-destructive` が無い | ファイルに触らず、破壊的な手順を標準エラーに出す |
| 6 | 対象の `version` が dev-docs が読めるバージョンより新しい | dev-docs の更新を案内する |
| 7 | `sources` を移す先の project-index につながらない、または保存の応答が制限時間を超えて保存を確認できない | ファイルに触らず、つながらなかったアドレスと、project-index を起動してからやり直す案内を標準エラーに出す。保存を確認できないときは、保存が後から反映されうることも出す |

<!-- /table -->

終了コード 3 は `dev-docs serve` のポート使用中に使うため、`migrate` は使いません。

### 移し替えの手順

手順はパッケージに入れ、`src/dev_docs/migrations/settings/{バージョン}/steps.yaml` に置きます。
`steps.yaml` は `steps:` の下に、次のキーを持つ行を並べます。

<!-- table: data -->

| キー | 説明 |
| --- | --- |
| `op` | `rename`（キーの改名）・`add`（無いキーだけを既定値つきで追加）・`delete`（キーの削除。`value` が無いときだけ破壊的な手順）・`lift`（値の引き上げ）・`unwrap`（値の取り出し）・`export_sources`（`sources` の行を project-index へ移す） |
| `path` | キーのパス。ドットで結び、配列の要素の子は `sources[].scope` のように書く。末尾の `*` は親の辞書の全てのキー。`export_sources` は `sources` |
| `to` | 新しいキー。`rename` では同じ親の下のキー名、`lift` では親の辞書を持つ辞書の下のキー名 |
| `value` | `add` では既定値（キーが既にあれば書き換えない）、`delete` では削除する値（値が一致するときだけ削除する） |
| `match` | `lift`・`unwrap` で、値が辞書でこのキーと値を全て持つときだけ当てる。無ければ辞書の値に当てる |
| `take` | `lift`・`unwrap` で、辞書の値から取り出すキー。`unwrap` で辞書がこのキーを持たないときは元のキー名を使う |
| `description` | `--plan` に出す 1 行の説明 |

<!-- /table -->

`rename` は同じ位置で改名し、コメントを残します。
改名先のキーが既にあるときは失敗とします。

### 端末の設定の sources の移し替え

`version: "2"` の手順は、project-index の端末の設定を取得し、その行に端末の設定の `sources` の行を加えて 1 回で保存し、`project_index` を書き足します。
保存には取得したときの内容のバージョンを添え、取得した後に project-index の端末の設定が変わっていれば保存しません（終了コード 4）。
この手順は破壊的ではありません。

行は配信元の ID で照らします。
ID は `id`、省いた行は `config` の配信元の設定を重ねた `name` です。

| project-index の端末の設定 | 端末の設定の行 |
| --- | --- |
| 同じ ID の行が無い | 加えて保存し、`sources` から除く |
| 同じ ID で同じ内容の行がある | 移した行として `sources` から除く |
| 同じ ID で内容の違う行がある | `sources` に残し、ID を標準出力に出す。project-index で行を直してから、残った行を手で消す |
| ID を求められない（`id` を省き、`name` も読めない） | `sources` に残し、`config` を標準出力に出す |

保存の応答が制限時間を超えたときは、端末の設定を取得し直し、加えた行が全てあれば保存したとして続けます。
保存は 1 回なので、project-index が受け付けなかったときは project-index の端末の設定も書き換わりません。
保存では project-index の端末の設定の既存の行も書き直されます。行のコメントは消え、文字列の `config` は配列になり、`id` を省いた配信中の行には `id` が書き足されます。
保存を確認できずに終了コード 7 で止まったときは、保存が後から反映されることがあります。やり直すと、保存済みの行は移した行として扱います。
