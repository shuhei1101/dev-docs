# 画面で参照する

文書の画面で配信元の文書を参照し、コメントを送信し、設定画面で配信元を追加する手順

## 画面を開く

サーバーを起動し（[配信元を配信する](./配信元を配信する.md)）、ブラウザで `http://127.0.0.1:{port}/` を開きます。
既定のポートは `8781` です。
画面は、配信元の文書・検索・リビジョンを要求ごとに project-index から取得します。

| 画面 | URL |
| --- | --- |
| 文書の画面 | `/{配信元の ID}/{文書のパス}?rev={リビジョン}&base={比較元}`。文書のパスを省いた `/{配信元の ID}` は、配信元のトップ（一番左のタブの一番上の文書） |
| 設定画面 | `/_settings` |

`/` は配信中の配信元の先頭のトップへ移り、配信中の配信元が無ければ設定画面へ移ります。
無い配信元・リビジョン・文書の URL は、URL を変えずに見つからない画面を出します。
見つからない画面は、見つからなかったものと、配信元のトップ・設定画面へのリンクを出します。
project-index につながらないときは、文書の画面は画面全体に、設定画面は配信元の一覧の場所に「project-index に接続できませんでした」の表示と、接続先・理由・`再読み込み` を出します。project-index を起動してから `再読み込み` を押します。

## 文書を参照する

トップバーで参照する配信元とリビジョンを選びます。
文書の画面は、種類のタブ・サイドバー・パンくず・本文・目次で 1 文書を参照します。

<!-- table: {"kind": "data"} -->

| やりたいこと | 操作 |
| --- | --- |
| 配信元を切り替える | トップバーの配信元のメニューで選ぶ。選んだ配信元のトップを開く |
| リビジョンを切り替える | トップバーのリビジョンのメニューで、ブランチ・タグ・最近の commit から選ぶ。同じ文書を `rev` に指したリビジョンで開く。`rev` を省くと配信元の `default_ref` を参照する |
| 文書の種類を切り替える | 種類のタブを押す。`nav` に並べた順に出て、そのタブの一番上の文書を開く |
| 文書を開く | サイドバーの文書を押す。`rev` と `base` を保ったまま開く |
| グループを折りたたむ・開く | サイドバーのグループの見出しを押す。開いている文書を含むグループと、差分の表示中に変化のある文書を含むグループは開いて始まる |
| サイドバーを閉じる・開く | サイドバーの上端の閉じるボタンを押す。閉じると本文がサイドバーの幅だけ広がり、本文の左上の開くボタンで閉じる前の幅で開く。ブラウザに保存する |
| サイドバーの幅を変える | サイドバーと本文の境目をドラッグする。境目にフォーカスして ← → でも変えられ、ダブルクリックで既定の幅に戻る。ブラウザに保存する |
| 階層に戻る | パンくずの配信元の ID かタブ名を押す |
| 見出しへ移る | 本文の右端の目次の線を指すかフォーカスして目次を出し、見出しを押す。本文の幅が 48rem 未満のときは、本文の上の帯の `目次を表示` を押して目次を出す |
| 図から文書へ移る | 本文の Mermaid の図（クラス図など）で、`click` に `id:` の参照を記載したノードを押す。参照が指す文書を `rev` を保ったまま開く |
| 明暗を切り替える | トップバーの明暗のボタンを押す。ブラウザに保存する |

<!-- /table -->

種類のタブとサイドバーは、スクロールしても画面に残ります。
画面幅が 48rem 未満のときは、サイドバーを文書の一覧のドロワーで開きます。
検索から除外される文書（`project-index.yaml` の `documents[].search_exclude` に該当する文書）は、サイドバーに残したまま文字を薄くし、検索から除外のアイコンを付けます。

本文の変換に失敗した文書は、本文の代わりに変換できなかった理由と次にすることを出します。
修正したら `再読み込み` を押します。

### タグの式で絞った一覧を開く

`project-index.yaml` の `nav` の `auto` に `filter` を記載したタブは、その条件に該当する文書だけをサイドバーに並べます。
条件は `search_docs` の `filter` と同じ書式で、`and`・`or`・`not` を入れ子にできます（[設定](./設定.md) の「nav」）。
よく使用する絞り込みをタブにしておくと、タブを押すだけで絞った一覧を開けます。
タブは管理の MCP の `write_nav` でも追加・修正できます。

### 図を操作する

設計書の図（フロー図・データフロー・構成図・状態遷移図・ER 図・シーケンス図）は、mdmark の map で描きます。

<!-- table: {"kind": "data"} -->

| やりたいこと | 操作 |
| --- | --- |
| グループの中だけを確認する | グループのタイトルを押す。右上の戻るボタンか Esc で外へ戻る |
| グループを閉じる・開く | グループの開閉のボタンを押す |
| ノード・テーブルとつながる線を強調する | ノード・テーブル・線を押す。ほかが薄くなる |
| 状態遷移・シーケンスを順に追う | 図の下の帯の前へ・次へ・自動で進めるを押す |
| ER 図のテーブルの列を畳む | テーブルの開閉のボタンを押す |

<!-- /table -->

### 本文の用語のツールチップを確認する

配信元に `alias_type` を持つ documents の行があると、本文の単語のうち、その行の文書の `name` か `aliases` に該当する単語にツールチップが付きます。
単語にポインタを合わせるかフォーカスすると、用語の名前と `description` が出ます。
`alias_type` が `doc` の文書は、文書の別名（関連文書）として出ます。
`alias_type` を持つ行が無い配信元の文書は、ツールチップを付けずに描きます。

## 検索する

Ctrl+K（macOS は ⌘K）か `/` で検索のダイアログを開きます。
トップバーの検索のボタンからも開けます。
単語を入れると、開いている配信元・リビジョンの文書を、件数と一致した箇所つきで並べます。
結果を選ぶと、`rev` を保ったままその文書を開きます。
検索から除外される文書は既定の結果に出さず、件数の後ろに除外した件数を出します。
`検索から除外した文書も含める` のスイッチを入れると、除外される文書も結果に並べ、`検索から除外` のバッジを付けます。
一致した文書が全て検索から除外される文書のときは、`検索から除外した文書を含めると N 件あります。` と案内します。
Esc を 1 回押すと閉じます。

`?` でショートカットの一覧を開きます。
`/` と `?` の 1 文字のショートカットは、設定画面のキーボードのセクションで切り替えます。

## 差分を確認する

Git の配信元では、リビジョンの間の差分を見られます。

<!-- steps -->

1. トップバーのリビジョンのメニューで、比較を始める。
   開いているリビジョンが `default_ref` 以外なら `default_ref` を、`default_ref` なら最近の commit の 2 件目を比較元にする。
2. 本文の上の差分の案内で、`比較元` と `比較先` を選ぶ。
   選ぶと、URL の `base` と `rev` が変わる。
3. サイドバーの文書と本文・目次で、比較元からの変化を確認する。
   サイドバーの文書には追加・変更・削除のマーカーが付く。
   本文では、比較元から変わった箇所が強調される。
   右端の目次では、中身が変わったセクションの項目に変更のマーカーが付く。
4. `差分の強調を解除` を押して、比較先の通常の表示に戻す。

<!-- /steps -->

## コメントを送信する

本文の文字列を選んでコメントを保存し、まとめてコピーするか、GitHub の Issue にします。
コメントは、ブラウザのタブの `sessionStorage` に保存します。
再読み込みしても残り、タブを閉じると消えます。
サーバーには送信しません。

<!-- steps -->

1. 本文の文字列を選び、出たコメントのボタンを押してコメントを入力し、保存する。
   コメントのパネルが開き、一覧とトップバーの件数に加わる。
2. コメントのパネルで、コピーや起票に含めるコメントを選ぶ。
   追加したコメントは選んだ状態になる。`すべて選択` でまとめて選べる。
3. `選択 {件数} 件をコピー` を押す。
   選んだコメントを一覧の順に、配信元の ID・リビジョン・文書のパス・見出し・引用・本文でクリップボードへコピーする。
4. 起票するときは `Issue を作成` を押す。
   選んだコメントの全文をクリップボードへコピーしてから、GitHub の Issue の作成画面を別のタブで開く。

<!-- /steps -->

`Issue を作成` は、`project-index.yaml` の `github.repository` を記載した配信元だけに出ます。
起票するラベルは `github.issue_labels[]` に記載します（[設定](./設定.md)）。
Issue の作成画面の URL が長さの上限を超えるときは、本文の末尾を切り詰めて開きます。
全文はクリップボードに残ります。

## 設定画面を使用する

トップバーの歯車で設定画面（`/_settings`）を開きます。
project-index の端末の設定の `sources[]` を、project-index が返却した配信元ごとの状態とともに並べます。
追加・編集・削除は project-index の端末の設定へ保存を依頼し、project-index が配信元を再読み込みします。

| 状態 | 意味 |
| --- | --- |
| 配信中 | 配信している。配信元の ID を押すと、その配信元のトップを開く |
| 配信停止 | project-index が検証で除外した。理由が状態の下に出る |
| 無効 | `enabled` が `false` |
| 再読み込み待ち | 設定ファイルにはあるが、まだ再読み込みしていない |

配信元を追加するには、次の手順をします。

<!-- steps -->

1. `配信元を追加` を押す。
2. ダイアログに入力する。
   配信元の ID は英小文字・数字・ハイフンで入力する。
   設定ファイルは `project-index.yaml` のパスを 1 行に 1 つ入力する。
   読み取りの範囲は必須、書き込みの範囲は任意で、どちらも作業場所の glob を 1 行に 1 つ入力する。
   `配信` のスイッチを除外すると、設定を残したまま配信を止める。
   `範囲の外から参照できるようにする` のスイッチを除外すると、読み取りの範囲に該当しない作業場所からは参照できなくなり、一覧の ID の下に `範囲の外から参照できません` が出る。
   `読み書きの方法` は `自動`・`Git`・`ディスク` から選ぶ。`自動` はフォルダが Git の作業ツリーの中なら Git、外ならディスクで読み書きする。コミットしないフォルダは `ディスク` を選ぶ。
   一度 `Git` か `ディスク` を保存した配信元は、編集で `自動` に戻せない。
3. `追加` を押す。
   スキーマに通ると project-index が端末の設定を保存し、配信元を再読み込みする。
   通らないときはダイアログを開いたまま、保存の失敗のまとめと項目のエラーを出す。

<!-- /steps -->

設定画面を開いた後に他のプロセスが端末の設定を変更していたときは、保存・削除せずに `他の変更があったため保存できませんでした`（削除は `削除できませんでした`）を出し、一覧を最新の内容にします。
入力した値はダイアログに残るので、内容を確認してもう一度保存します。
編集・削除していた配信元が他のプロセスに削除されていたときは、`配信元が削除されたため保存できませんでした`（削除は `削除できませんでした`）を出し、保存・削除できません。

編集は一覧の鉛筆のボタン、削除はごみ箱のボタンで行います。
削除は、project-index の端末の設定から配信元の行を削除して配信から除外します。
配信元のフォルダと文書は削除しません。

## メタデータを参照・編集する

トップバーの `メタデータ` でメタデータの画面（`/{配信元の ID}/_metadata`）を開きます。
配信元の用語集・エイリアス・タグ・rule-inject の索引・配信元の設定・管理用の YAML を、種類ごとのタブの表で並べます。
表の上の入力欄で行を絞り込めます。

| タブ | 編集 |
| --- | --- |
| 用語集・エイリアス・タグ・rule-inject の索引・管理用の YAML | 直コミットを許可した種類の文書の行だけ編集できる（[直コミットの設定](設定.md#メタデータの画面から直コミットする設定)）。許可していない行は参照のみ |
| 配信元の設定 | 参照のみ |

rule-inject の索引のタブは、配信元の設定に `id: rule_index` の行が無いと、追加する行の案内を出します。

編集した変更はすぐにはコミットせず、編集中の変更としてブラウザのタブに残ります。
変更をまとめて直コミットするには、次の手順をします。

<!-- steps -->

1. 表のセルを編集する。行の追加・削除もできる。
   セルを押すと、押した文字の位置から入力できる。
   トップバーの `編集中` のボタンに、編集中の変更の件数が出る。
2. `編集中` のボタンを押してパネルを開く。
   変更ごとの `元に戻す` で、その変更だけを取り消せる。
3. `差分確認` を押し、コミットする前の差分を確認する。
4. `コミット` を押し、開いたダイアログで `コミットの説明` を入力して `コミット` を押す。
   検査に合格すると、変更が 1 つのコミットになって配信元のブランチへプッシュされ、パネルが空になる。

<!-- /steps -->

コミットできなかったときは、編集中の変更が理由と一緒にパネルに残ります。
参照した後に他の変更で文書が変わっていた・検査に通らなかった変更は、変更ごとに理由が出ます。
内容を修正するか取り消してから、もう一度コミットします。
project-index につながらなかったときは `再試行` を押します。

編集を始めた後にほかの変更でブランチが進んでいても、同じ文書のほかの項目だけが変わっていれば、衝突せずにコミットします。
修正した項目がほかの変更で変わっていた・文書が削除されていたときは、修正を編集を始めたときのコミットからのブランチに残し、既定のブランチにはコミットしません。
パネルに、残したブランチ・衝突した理由と、衝突したときのスクリプト（[直コミットの設定](設定.md#メタデータの画面から直コミットする設定)）が作成した PR が出て、ブランチに残した変更は編集中の変更から除かれます。
スクリプトが失敗した・登録されていないときは、その旨が出ます。
`差分確認` の時点で衝突するときは、コミットすると修正がブランチに残ることと、変更ごとの理由が出ます。

編集を始めたときのコミットが使用できないときは、`最新の内容で続ける` を押します。
最新の内容を再取得し、編集中の変更を残したまま送信できます。
最新の値が変更前の値と違う変更は取り消され、パネルに一覧が出ます。

## 文書の本文を編集する

文書の画面のタイトルの右の `編集` で、文書の本文の編集を始めます。
`編集` は、本文を直コミットできる文書（[直コミットの設定](設定.md#メタデータの画面から直コミットする設定)）を既定のブランチで開いたときだけ出ます。

| 方式 | 対象 | 編集 |
| --- | --- | --- |
| 表示した場所で修正 | YAML の文書 | 項目の右の鉛筆のボタンで、その場の入力欄・選択肢・表のセルの入力欄を出す。Markdown の項目は画面の横のパネルのエディタとプレビューで修正する |
| ファイル全体 | YAML の文書・Markdown の文書 | 元のファイルの内容をエディタで書き換え、横のプレビューで描いた結果を確認する。YAML として解析できないときは、エディタの上に行と列と理由が出る |

YAML の文書は、タイトルの右の `表示した場所で修正`・`ファイル全体` で方式を切り替えます。
一方の方式の変更があるときは、その変更をコミットするか元に戻すまで、もう一方の方式に切り替えられません。
`編集を終了` で参照の表示へ戻ります。編集中の変更は残ります。

本文の変更もメタデータの変更と同じ編集中の変更に入り、トップバーの `編集中` のボタンで開くパネルに並びます。
差分確認とコミットの手順は、メタデータを参照・編集するときと同じです。
パネルの本文の変更の行を押すと、その文書を編集の表示で開きます。

## スマホで使用する

幅 360px 以上の画面を扱います。
スマホで使用できる操作は、参照する・検索・コメントのコピーまでです。
設定画面の編集は、PC で行います。
