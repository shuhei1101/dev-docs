# 要件

## 要望

文書を書くエージェントが、書く前に次の 2 つを判定フローチャートで決められるようにする（D-110 の ① と ③）。
2 つとも `docs/使い方/` の利用者向けのページ（Markdown）として置き、front matter の `tags` で dev-docs の検索から引けるようにする。
rule-inject では注入しない。

| 判定フローチャート | 終わりの条件 |
| --- | --- |
| 新しく作るか修正するか | 書く前に `search_docs` でタグ・エイリアス・全文の順に同じ話題の文書を引き、主題が同じなら既存を修正する、一部が重なるなら既存にセクションを追加するか関連（`related`）を張る、重ならなければ新しく作る、のどれかに行き着く |
| どの documents の行に入れるか | 文書が既存の行（`documents[]` の 1 行 = 種類（kind））のスキーマ・`paths[]`・検査に収まるかを判定し、収まればその行、収まらなければ新しい行（新しいスキーマ）を作る条件に行き着く。判定に使うキーは [#14](https://github.com/shuhei1101/dev-docs/issues/14) で入った `metadata`・`defaults[]`・`records`・`body_file` と [docs/リファレンス/設定.md](https://github.com/shuhei1101/dev-docs/blob/develop/docs/%E3%83%AA%E3%83%95%E3%82%A1%E3%83%AC%E3%83%B3%E3%82%B9/%E8%A8%AD%E5%AE%9A.md) の `documents[]` の表に揃える |

エイリアスで引く手順は、`search_docs` の用語の検索（`name` と `aliases` の値で照合する）を作る [#11](https://github.com/shuhei1101/dev-docs/issues/11) の本文の仕様に合わせて書く。
図は規約『判定フローチャート』（knowledge の `markdown-flowchart`）の書き方に従う。

置き場所は判定フローチャート『ドキュメント配置判定』で、プロジェクトを使う人（dev-docs で文書を書くエージェント）が読む・引いて調べる一覧ではない・利用者が行う操作（文書を書く）の手順、として `docs/使い方/` にした。
形式は『データ化判定』で、公開するページとして Markdown にした。
