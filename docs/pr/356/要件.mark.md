# 要件

## 要望

- `project-index.yaml` の `design-schemas` の参照を全て `v12.0.0` へ上げ、全ての設計書が新規のスキーマの検査に合格する
  - `v12.0.0` のスキーマで検査して不合格になるのは、画面設計書（`docs/screen/SCR-155-1`〜`SCR-155-4`）と部品設計書（`docs/component/CMP-155-1`〜`CMP-155-4`）の 8 件だけ（2026-11-28 時点の develop。ほかの種類の設計書は合格する）
- 画面設計書 4 件を、新規の欄で記載し直す
  - 画面全体: `screen_type`・`leave_guard` を記載し、画面全体で保持する状態を `retained_state` に記載する（`shell` の画面は必須）
  - 要素: アイコン（`icon`・`label_display`・`accessible_name`・`tooltip`）・狭い幅の出し方（`narrow`）・保持する状態（`retained_state`。入力・選択・タブ・サイドバー・ペイン・開閉・一覧と表は必須）・ペイン（`pane`）・タブ（`tabs`）・表（`table` と列の `sortable`・`filterable`・`pinnable`・`hideable`）・閉じ方とフォーカス（`close`・`initial_focus`・`return_focus`）・押した後の振る舞い（`disabled_reason`・`confirm`・`feedback`・`toggle_state`）・URL の履歴（`history`・`resets`）・ショートカット（`shortcut`）を、該当する要素に記載する
  - 変わった欄: `table_column` の `sorting` を `sortable`・`filterable` と `table.default_sort` に分け、`io`・`align`・`initial_state` の値を英語の enum にする
- 部品設計書 4 件を、新規の欄で記載し直す
  - `persisted_state`・`states[].viewport` を記載し、`accessibility` を `label_display`・`accessible_name_arg`・`keyboard`・`rules` のオブジェクトにする
  - 引数の型などの値を英語の enum にする
- 欄の決まり（`x-rules`）は、knowledge のテンプレート『画面設計』『部品設計』（`template-screen-design`・`template-component`）と、そこが参照する規約に従う
- 記載し直す途中で、今の実装の振る舞いが欄の決まり・規約に合わない箇所（保持すべき状態が抜けている・スプリッターが無い・アイコンで足りるラベル など）に気づいたら、設計を規約に合う側へ修正し、`frontend/` の実装と単体テスト・結合テストまで合わせる
  - 修正した箇所は、画面設計書・部品設計書と、実装するモジュール構成の設計書に反映する
- デザインスタイル選定・画面一覧・画面遷移・モック作成は行わない
  - 判定フローチャート『モック要否』: 画面の追加・削除と画面遷移の変更は無く、修正する見た目は欄の決まりと規約が決める（作る人が決める余地が無い）。デザイン方針 `docs/design-policy.md` があり、見た目の方向は変えない
