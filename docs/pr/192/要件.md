# 要件

## 要望

- `docs/flowchart/` の YAML のうち `visibility: public` の文書から、GitHub Pages の公開ページを生成する
- 2 文書（[新しく作るか修正するかの判定](https://github.com/shuhei1101/dev-docs/blob/864aae2/docs/flowchart/flowchart-new-or-modify.yaml)・[documentsの行の判定](https://github.com/shuhei1101/dev-docs/blob/864aae2/docs/flowchart/flowchart-documents-row.yaml)）を `visibility: public` にし、「使い方」の目次の表から開けるようにする
- 生成したページの文書の ID への参照（`](id:flowchart-documents-row)`）は、公開ページどうしのリンクになる
- `develop` へ push するたびに、手で生成し直さずに公開ページが新しくなる

公開ページのビルドは、GitHub Actions のワークフロー（`.github/workflows/pages.yml`）で行う。

| 工程 | 内容 |
| --- | --- |
| 生成 | 生成のスクリプト（[MOD-192-1](../../module/MOD-192-1.py.yaml)）が公開の判定フローチャートを `docs/guide/{ID}.md` へ書き出す。生成物は commit しない |
| 描画 | `actions/jekyll-build-pages` が `docs/` を今の `docs/_config.yml` のまま描く（今の公開ページと同じ GitHub Pages の既定のテーマ。`docs/_theme/` は読み込まれていない） |
| 配信 | `actions/deploy-pages` が `github-pages` の環境へ配信する |
| 目次 | `docs/guide/使い方.md` の目次の表に、生成するページの行を commit しておく |

Pages の設定の `build_type` を `legacy` から `workflow` へ切り替える作業は、`反映作業/index.yaml` に記載する。

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 上の表の方式 | 公開ページの URL と見た目が今のまま。生成物を commit しない | Pages の設定の切り替えが要る |
| B | legacy のビルドのまま、生成した Markdown を commit する（lefthook の pre-commit で生成し直す） | Pages の設定を変えない | 同じ中身の原本と生成物が 2 つ並ぶ。フックを実行しない commit で生成物が古くなる |
| C | knowledge の `pages.yml`・`build_pages.py` と同じく、mdmark の `build` で公開の文書を 1 枚の HTML にまとめて配信する | mermaid が図になり、knowledge と同じ方式になる | 公開ページの URL と見た目が変わる。Pages の設定の切り替えも要る |

採用: A

公開ページの URL と見た目を変えずに、原本の YAML だけから公開ページを作れる。

`未確定`: 生成したページの判定フローの図（mermaid）の描き方（決める工程: 承認確認でユーザーに確認する）

今の公開ページは `docs/_theme/` を読み込まず、mermaid を含むページ（[コアコンセプト-管理用プラグイン](https://shuhei1101.github.io/dev-docs/guide/%E3%82%B3%E3%82%A2%E3%82%B3%E3%83%B3%E3%82%BB%E3%83%97%E3%83%88-%E7%AE%A1%E7%90%86%E7%94%A8%E3%83%97%E3%83%A9%E3%82%B0%E3%82%A4%E3%83%B3.html)）もコードのまま描かれている。

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 今の公開ページで描ける範囲にとどめる（mermaid はコードのまま・「使い方」の目次の表から開く）。テーマの取り込みは [#74](https://github.com/shuhei1101/dev-docs/issues/74) に任せる | この PR の範囲が要望（2 文書を「使い方」から参照できる）に収まる | 判定フローが図として表示されない |
| B | この PR で `_config.yml` から `_theme/` を Jekyll に繋ぎ、mermaid を図として描く | 判定フローが図として表示される | スコープ外にした #74 と重なり、全公開ページの見た目が変わる |
| C | ビルドの方式を上の案 C（mdmark の `build`）に選び直す | mermaid が図になり、knowledge と同じ方式になる | 公開ページの URL が変わる |

推奨: A

Issue #173 の要望は 2 文書を「使い方」から参照できることで、図の描画とテーマの取り込みは今の公開ページでも満たしていない別の論点のため。
