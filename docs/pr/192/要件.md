# 要件

## 要望

- GitHub Pages の公開ページを、mdmark の `build` でまとめた 1 枚の HTML にする（確認ログのユーザーの回答。knowledge の `pages.yml`・`build_pages.py` と同じ方式）
- 1 枚にまとめるのは、`docs/guide/files.yml` の `visibility: public` の Markdown と、`docs/flowchart/` の YAML のうち `visibility: public` の文書から生成した Markdown
- 2 文書（[新しく作るか修正するかの判定](https://github.com/shuhei1101/dev-docs/blob/864aae2/docs/flowchart/flowchart-new-or-modify.yaml)・[documentsの行の判定](https://github.com/shuhei1101/dev-docs/blob/864aae2/docs/flowchart/flowchart-documents-row.yaml)）を `visibility: public` にし、文書の一覧で「使い方」の文書の後に並べる
- 判定フローの図（mermaid）は、mdmark の mermaid のコードブロックとして図で描かれる
- 生成したページの文書の ID への参照（`](id:flowchart-documents-row)`）は、1 枚の中のリンクになる
- `develop` へ push するたびに、手で生成し直さずに公開ページが新しくなる

公開ページのビルドは、GitHub Actions のワークフロー（`.github/workflows/pages.yml`）で行う。

| 工程 | 内容 |
| --- | --- |
| 生成 | 生成のスクリプト（[MOD-192-1](../../module/MOD-192-1.py.yaml)）が公開の文書を分類（はじめに・使い方・リファレンス）の順に一時フォルダへ並べ、判定フローチャートを `{ID}.md` に変換する |
| まとめ | 同じスクリプトが `npx` で mdmark の `build` を実行し、`index.html` を出力のフォルダ（`_site`）に配置する。生成物は commit しない |
| 配信 | `actions/deploy-pages` が `github-pages` の環境へ配信する |

Pages の設定の `build_type` を `legacy` から `workflow` へ切り替える作業は、`反映作業/index.yaml` に記載する。
公開ページの URL は、今の `/{分類}/`・`/guide/{ファイル名}.html` から、`/` の 1 枚の中の `#/{文書}` に変わる（確認ログのユーザーの回答で受け入れた）。
