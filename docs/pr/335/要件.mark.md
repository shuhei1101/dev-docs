# 要件

## 要望

文書の画面から、どの種類の文書の本文も編集して直コミットできるようにする。

- 文書の画面に編集のボタンを配置し、Markdown の文書と、種類ごとのスキーマを持つ YAML の文書の本文を編集できる
- YAML の文書は種類ごとの個別の対応を持たず、スキーマの型から編集の部品を選ぶ。本文の表に出ている値は、その表の上で修正できる
- 規約（`items[].body`）・プロンプト（`parts[].texts[]`。MCP の instructions・ツールの description を含む）・エージェントフロー・単語の対応表の行を、文書の画面から修正できる
- 編集した内容はメタデータの画面と同じ編集中の変更に溜め、同じ編集中のパネル・差分確認・コミットの確認を経て、配信元ごとに 1 つのコミットで project-index の書き込みの API へ送信する。検査に合格しない変更は、送信の前の差分確認で項目のパスと理由を出す
- 画面から編集できる範囲（配信元・種類）は、project-index の端末の設定の `sources[].direct_commit.write_api_kinds` で切り替える。dev-docs の側では絞らない
- [メタデータの取得](https://docs.shuhdev.com/dev-docs/docs/interface/IF-155-28.yaml?rev=develop)・[編集中の変更の直コミット](https://docs.shuhdev.com/dev-docs/docs/interface/IF-155-29.yaml?rev=develop) の、修正できるキーの種類ごとの絞り込みと「規約の本文・テンプレート・スキーマは画面から書き換えない」の記載を削除する
- 配信元の設定で `body: false` の種類の本文と、SQLite の表の行の種類は、project-index が書き込みを断るため、編集のボタンを出さない
- project-index の書き込みの API は `@body`・項目のパスへの `set`・`text_edits`・`replace` を既に受けるため、project-index の変更は要らない。設計で要ると分かったときは project-index の Issue として切り出す
- 編集の方式は、ファイル全体の編集（元のファイルをエディタで開いて書き換える）と、表示した場所での修正（YAML の変換で各ブロックに元の項目のパスの目印を埋め、スキーマの型から選んだ部品で修正する）の両方を入れる。Markdown の文書はファイル全体の編集だけを持つ
