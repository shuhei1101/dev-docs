## 変更方針

<!-- table: {"kind": "data"} -->

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 文書の取得 | 編集のために、元のファイルの内容・種類のスキーマ・文書のバージョンと項目ごとのバージョン・編集できるか（`write_api_kinds`・`body: false`・SQLite の行）を返却する | ファイル全体の編集と表示した場所の修正の両方に使用する |
| 変換の目印 | YAML の変換で、表示したブロックと表の行・セルに元の項目のパスの目印を埋める | YAML の文書だけ。Markdown の文書は目印を持たない |
| 直コミットの要求 | 編集中の変更に文書の本文の変更（項目のパスへの `set`・`@body`・ファイル全体の `replace`）を加え、メタデータの変更と同じ要求で 1 つのコミットにして送信する | 配信元ごとに 1 回の送信のまま |
| 修正できるキー | 種類ごとのキーの絞り込みを削除し、元のキーへ戻せるかと編集できる種類かだけを確認する。「規約の本文・テンプレート・スキーマは画面から書き換えない」の記載を削除する | メタデータの取得・直コミットの両方 |
| 検査と差分 | 送信の前の差分確認（`dryRun`）で、project-index の検査の違反を変更と項目のパスごとに返却する | 今の 422 の変換を本文の変更にも適用する |
| 編集できる範囲 | project-index の端末の設定の `write_api_kinds` を参照し、文書の取得とメタデータの取得の `editable` に反映する。dev-docs の側では絞らない | - |
| エラー返却 | 衝突・検査の不合格・許可の無い種類の扱いは今の直コミットと同じ状態コードと `errors[]` で返却する | - |
| 既存機能への影響 | メタデータの画面の直コミットの要求と応答の互換を保つ | 結合テストで確認する |
