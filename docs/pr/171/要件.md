# 要件

## 要望

dev-docs 自身の `docs/` の文書を project-index の配信元にし、文書ごとの名前・概要文・タグで検索できるようにする。
起点 Issue の冒頭の取り消し（`defaults[]`・`metadata` の `custom`・documents の行の `type`・front matter を使用しない）を、Issue の `## やること` より優先する。

| 対象 | 要件 |
| --- | --- |
| 配信元の設定 | リポジトリの直下に `project-index.yaml` を作り、project-index の `schemas/project-index.schema.json` の検査に合格させる。`docs/` の YAML の設計書の種類ごと・目次（`index.yaml`）・`files.yml` ごとに documents の行を持たせる。`metadata` は列の対応（`name: title` など）だけにする |
| YAML の文書のメタデータ | 文書自身の列（`title`・`lead`・`tags` など）を `metadata` の対応で読ませる |
| Markdown のメタデータ | `docs/_root/files.yml`・`docs/guide/files.yml` と新しく作る `docs/mock/files.yml` の行に `name`・`description`・`tags` を記載する。管理用の YAML のファイル名は、既存の `files.yml` のまま使用する |
| タグ | knowledge の規約『文書のタグと description の記載』と『タグと用語の登録』に従う |
| PR #22 の 2 文書 | `docs/guide/新しく作るか修正するかの判定.md`・`docs/guide/documentsの行の判定.md` の front matter の `tags` を、管理用の YAML の行（YAML に変換するときは変換後の文書の列）へ移し、front matter を削除する |
| YAML への変換 | AI が参照する種類の Markdown を、種類ごとのスキーマを持つ YAML に変換する。変換した文書を参照しているリンク・目次を変換後のパスに合わせる |
| 確認 | project-index の `search_docs` で、配信元 `dev-docs` の文書がタグ・名前で見つかる |

`docs/` の Markdown は次のとおり。
YAML の設計書（`scenario`・`interface`・`module` など）は既に YAML にある。

| 文書 | 中身 | 読み手 |
| --- | --- | --- |
| `docs/guide/` の判定フローチャート 2 文書 | 文書を新しく作るか修正するか・documents の行の判定 | AI と利用者 |
| `docs/guide/` のほかの文書 | 公開ドキュメント（はじめに・使い方・リファレンス）。GitHub Pages に出す | 利用者 |
| `docs/design-policy.md` | 画面全体のデザインの方向性 | AI（デザインの工程） |
| 各フォルダの `README.md` | `index.yaml` から生成した目次 | 利用者 |
| `docs/mock/` の `index.md` | モックの目次 | 利用者 |

`未確定`: YAML に変換する文書の範囲（決める段: ドキュメント修正のレビュー）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 判定フローチャート 2 文書だけを YAML に変換し、判定フローチャートのスキーマを `schemas/` に追加する。ほかは Markdown のまま `files.yml` でメタデータを持たせる | AI が判断に使う文書だけが種類のスキーマで検査される。Pages に出す公開ドキュメントの URL と描画は変わらない | 判定フローチャートの公開ページを Pages に出すには、YAML から Markdown を生成する手段が要る |
| B | 変換せず、全て Markdown のまま `files.yml` でメタデータを持たせる | 変更が最も少ない | Issue の「AI が参照する種類を YAML に変換する」を満たさない |
| C | `docs/guide/` 全体を YAML に変換する | 公開ドキュメントも種類のスキーマで検査される | Jekyll で描く Pages のビルドを YAML から作り直す必要があり、この Issue の範囲を超える |

推奨: A

判定フローチャートは AI が文書を作る前の判断に使う手順で、Issue の変換の対象（設計書・規約・手順）に該当する。
公開ドキュメントは利用者が Pages で読み、AI が判断に使う規約・手順ではない。
