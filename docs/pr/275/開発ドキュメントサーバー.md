## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| フォルダ構成の設計書 | knowledge の `layout` のスキーマ（`project-index.yaml` の他の設計書の行と同じ `ref`）で、`write_docs` の `create` で作成する。`repository` は `shuhei1101/dev-docs` | ID は作業 PR の番号から `LAY-275-1` |
| エントリ | アーキテクチャ図のツリーを直下のエントリにし、モジュール構成のツリーをその配下のエントリ（`children`）へ移す。ツリーのコメントは `contents` へ写す | 言語の規約が配置を定めるフォルダ（`src/dev_docs/`・`frontend/src/`）にも `convention` を付けず、移したツリーを `children` に持つ（スキーマの `x-rules` とは食い違う） |
| 生成物・Git で管理しないもの | ツリーで生成物と記載されたエントリは `generated_from` を記載し、`.gitignore` の行を `gitignore` に記載する | - |
| `project-index.yaml` | `documents[]` に `id: layout` の行を追加する（`paths: ["docs/layout/*.yaml"]`・`exclude: [index.yaml]`・`schema` と `metadata` は他の設計書の行と同じ形）。`nav` の「設計書」の「全体」のグループに `page: layout` を追加する | - |
| `docs/layout/index.yaml` | フォルダの目次を作成し、`docs/index.yaml` に行を追加して README を生成し直す | 規約『ドキュメント管理』の新規ページ追加時の手順 |
| `notes` の「フォルダ構成」 | 移した後、各設計書の `notes` から「フォルダ構成」のキーだけを除く。他のキーは維持する | `notes` が空になる設計書は `notes` ごと除く |
| 検査 | `python -m ai_monitor.design_docs validate` を develop と作業ブランチで実行し、違反を比べる | - |
