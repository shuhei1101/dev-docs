# 要件

## 要望

dev-docs のフォルダ構成を、フォルダ構成の設計書 1 件へまとめる。

- knowledge のスキーマ `schemas/design/layout.schema.yaml`（`project-index.yaml` の他の設計書の行と同じ `ref`）で、`docs/layout/` にフォルダ構成の設計書を作成する
- `project-index.yaml` の `documents[]` に `layout` の行を追加し、フォルダ構成の設計書を配信する。`nav` の「設計書」のタブの「全体」のグループに、アーキテクチャ図と並べて配置する
- 次の設計書の `notes` の「フォルダ構成」のセクションのツリーを、フォルダ構成の設計書のエントリ（`entries[]`）へ移し、`notes` から除く
  - アーキテクチャ図 `ARCH-155-1`
  - モジュール構成 19 件（`MOD-155-120`・`MOD-155-193`・`MOD-155-194`・`MOD-155-195`・`MOD-155-196`・`MOD-155-198`・`MOD-155-199`・`MOD-155-202`・`MOD-155-204`・`MOD-155-205`・`MOD-155-207`・`MOD-155-213`・`MOD-155-75`・`MOD-155-76`・`MOD-155-77`・`MOD-155-78`・`MOD-155-80`・`MOD-192-1`・`MOD-266-1`）
- ツリーのコメント（フォルダ・ファイルに配置するもの）は、エントリの `contents` へ写す。ツリーに無いフォルダ・ファイルをエントリに追加するかは、フォルダ構成の設計書の `x-rules`（リポジトリの直下からの全てのフォルダとファイル）に合わせて設計の工程で決める
- AI Monitor の変換 `_move_layout` は実行せず、設計書を `write_docs` で記載する（変換は `docs/module/` の設計書を改名する不具合を持つ）

完了の条件:

- `docs/layout/` にフォルダ構成の設計書があり、`project-index.yaml` の `layout` の行から配信される
- 各設計書の `notes` に「フォルダ構成」のセクションが無い
- AI Monitor の設計書の検査（`python -m ai_monitor.design_docs validate`）で、develop に無かった違反が出ない
