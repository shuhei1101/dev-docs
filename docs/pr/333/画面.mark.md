## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 行の値の入力位置 | 行の値を押したとき、押した座標から値の中の文字の位置を求め、入力欄にフォーカスした後にその位置へ入力位置を合わせる。位置を求められないとき（キーボードの Enter・Space で始めたとき）は末尾にする | 求め方（差し替えのまま位置を指定するか、編集前から入力欄で表示するか）はモジュール構成設計で決める |
| メタデータの画面の幅 | 本文の `max-w-6xl` を解除し、画面の横幅から左右の余白を除いた幅にする（上限は設けない）。絞り込みの入力欄は `max-w-sm` のまま | - |
| サイドバーの開閉 | 画面幅 48rem 以上で、サイドバーを閉じる・開くボタンを配置する。閉じると本文がサイドバーの幅だけ広がる | ボタンの位置はモック作成で決める |
| サイドバーの幅 | サイドバーと本文の境目に、ドラッグで幅を変えるハンドルを配置する。キーボードの矢印キー（16px）・Home / End でも変え、ダブルクリックで既定の幅に戻す。最小 12rem・最大 30rem・既定 15rem | クリックだけの代わりの手段（幅のボタン）は持たない（ユーザーの判断。規約『操作とアクセシビリティ』の 2.5.7 から外れることを画面設計に記録する） |
| 開閉・幅の保存 | 明暗の設定と同じブラウザの設定（`localStorage` の `dev-docs:preferences`）に保存する | - |
| group の折りたたみ | group の見出しを開閉のボタン（山形のアイコンで開閉の状態を示す）にし、押すと配下の page を折りたたむ・開く。開いている文書か変化のマーカーを持つ page を含む group は開いた状態で始め、開いている文書が変わったときにも開く。入れ子の段の数は制限しない | `aria-expanded` を持たせる |
| 48rem 未満のドロワー | 開閉・幅は今のまま、group の折りたたみだけ同じにする | - |
| モック | 規約『モック画面構成』の「React のリポジトリ」のとおり、文書の画面とメタデータの画面の本体のストーリー（`doc-view-screen.stories.tsx`・`metadata-screen.stories.tsx`）に、サイドバーの開閉・幅・group の折りたたみ・行の値の編集の状態を追加する | `docs/mock/` は作らない |
| アクセシビリティ | 開閉のボタン・幅のハンドル・group の開閉のボタンを、キーボードで操作でき、読み上げ名を持つようにする | - |
| レスポンシブ対応 | 幅 390px で、文書の画面・メタデータの画面に横スクロールが出ない | - |
| 既存機能への影響 | 文書の一覧の現在地・変化のマーカー・ドロワーの開閉と、メタデータの表の編集・Esc での取り消しを今までどおりにする | - |

- Web の実装ガイドは `search_web_guidance` で splitter・disclosure・入力位置を検索し、`accessibility` を読んだ（開閉の状態を `aria-expanded` で示す・フォーカスの見た目を持つ）。実装は合っている

- マニフェスト・ロックファイル・CI 設定・ツール設定・スクリプトに触れないため、開発コマンドは書かない
