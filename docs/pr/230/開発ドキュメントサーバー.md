## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 性能（開き直し） | 配信元の設定・リビジョン・文書の一覧を同時に送信し、文書だけをその後に送信する。応答は dev-docs の中に控えない | 決定値は NFR-16（18 秒） |
| 性能（配信元ごとの最初の読み込み） | project-index が配信元ごとの最初の問い合わせで行うリビジョンの書き出しと文書の一覧の値の作成は、[shuhei1101/project-index#85](https://github.com/shuhei1101/project-index/issues/85) で扱う | dev-docs の側では速くできない |
| エラー返却 | 文書の取得全体に制限時間（NFR-15、70 秒）を置き、超えたら 503（`projectIndex.kind` が `timeout`）で打ち切る。project-index の 5xx は 502（`kind` が `failed`、理由は project-index の `detail`）にする | 問い合わせごとの 45 秒（NFR-14）だけでは、3 回順に待つと 135 秒まで延びる |

2 回目以降に開くときの短くし方は、案 B（問い合わせを同時に送信するだけにし、応答は持ち越さない）にした。
案 A（配信元の設定と文書の一覧の応答を、配信元と commit ごとに持ち越す）は、IF-155-10 の制約「dev-docs の中に控えない」（project-index が読み直した配信元と文書を、dev-docs を再起動せずに次の要求から返す）と合わない。
