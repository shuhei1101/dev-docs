# 要件

## 要望

- どの配信元を選んでも、最初の文書を表示し終えるまでの時間を、非機能要件の決定値以内に収める。決定値は計測値から決めて非機能要件に書く
- project-index が配信元ごとの最初の問い合わせで行う処理（リビジョンの書き出しと文書の一覧の値の作成）の遅さは [shuhei1101/project-index#85](https://github.com/shuhei1101/project-index/issues/85) で扱い、この PR は project-index の応答を待つ時間を短くする
- 確認は Issue の Playwright のスクリプト（`dd2.cjs`）で、14 件の配信元の最初の画面を、サーバーを起動し直した直後から 2 回ずつ開いて行う。2 回目は全てが決定値以内に開け、1 回目は開けなかったものも文書の取得の制限時間の中で理由が画面に出る
- 最初の文書を表示できないとき、画面に、読み込み中か失敗かと、失敗の理由を出す。読み込み中のまま待ち続ける状態を残さない

`未確定`: 表示できないときの理由の出し方（決める段: 画面設計・モック作成）

| 案 | 内容 |
| --- | --- |
| A | 既存の「project-index に接続できないときの表示」と同じ形の警告を、文書の取得の失敗の理由ごとの文言で出す |
| B | 読み込み中の表示の中に、待っている時間と、待っている問い合わせを出し、失敗したら警告に切り替える |

推奨: A

既存の 503 の表示と同じ形にすれば、利用者は理由と次にすることを同じ場所で読める。待っている問い合わせの名前は利用者の次の行動を変えない。
