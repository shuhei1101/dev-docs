# 要件

## 要望

- 配信元を 2 回目以降に開いたとき、最初の文書を表示し終えるまでの時間を、非機能要件の決定値以内に収める。決定値は計測値から決めて非機能要件に書く
- 1 回目も 2 回目以降も、文書の取得の制限時間の中で、本文か表示できない理由のどちらかが画面に出る
- 確認は Issue の Playwright のスクリプト（`dd2.cjs`）で、14 件の配信元の最初の画面を、サーバーを起動し直した直後から 2 回ずつ開いて行う。project-index の配信元ごとの最初の処理（リビジョンの書き出し）を終えた配信元の 2 回目が決定値以内に開け、どの回も文書の取得の制限時間の中で本文か理由が出る

`未確定`: 1 回目の表示を短くすることの扱い（決める段: ユーザーの確認）

1 回目だけ遅い原因は、project-index が配信元ごとの最初の問い合わせで行う処理（リビジョンの書き出しと文書の一覧の値の作成）で、[shuhei1101/project-index#85](https://github.com/shuhei1101/project-index/issues/85) で扱う。

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | この PR は 2 回目以降の短縮と、制限時間の中で理由を出すことまでにする。#225 は project-index#85 に依存させ、#85 が済むまで閉じない | dev-docs 側の修正を先にマージできる | #225 が閉じるまでの期間が #85 に左右される |
| B | project-index#85 を先に済ませ、この PR で 1 回目も 2 回目も決定値以内を確認する | Issue の要件のとおり 1 つの PR で確認できる | #85 が済むまでこの PR が止まる |
| C | 1 回目の短縮を #225 の要件から外し、#225 をこの PR で閉じる | 早く閉じられる | 利用者が報告した「1 回目に表示できない」が #85 の完了まで残る |

推奨: A

dev-docs 側の待ち（3 回を順に待つ・制限時間が問い合わせごと）はこの PR で修正でき、1 回目の遅さは project-index の処理なので #85 で修正するのが分担として合う。

- 最初の文書を表示できないとき、画面に、読み込み中か失敗かと、失敗の理由を出す。読み込み中のまま待ち続ける状態を残さない

`未確定`: 表示できないときの理由の出し方（決める段: 画面設計・モック作成）

| 案 | 内容 |
| --- | --- |
| A | 既存の「project-index に接続できないときの表示」と同じ形の警告を、文書の取得の失敗の理由ごとの文言で出す |
| B | 読み込み中の表示の中に、待っている時間と、待っている問い合わせを出し、失敗したら警告に切り替える |

推奨: A

既存の 503 の表示と同じ形にすれば、利用者は理由と次にすることを同じ場所で読める。待っている問い合わせの名前は利用者の次の行動を変えない。
