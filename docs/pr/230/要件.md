# 要件

## 要望

- 配信元を 2 回目以降に開いたとき、最初の文書を表示し終えるまでの時間を、非機能要件の決定値以内に収める。決定値は計測値から決めて非機能要件に書く
- 1 回目も 2 回目以降も、文書の取得の制限時間の中で、本文か表示できない理由のどちらかが画面に出る
- 確認は Issue の Playwright のスクリプト（`dd2.cjs`）で、14 件の配信元の最初の画面を、サーバーを起動し直した直後から 2 回ずつ開いて行う。project-index の配信元ごとの最初の処理（リビジョンの書き出し）を終えた配信元の 2 回目が決定値以内に開け、どの回も文書の取得の制限時間の中で本文か理由が出る
- 最初の文書を表示できないとき、画面に、読み込み中か失敗かと、失敗の理由を出す。読み込み中のまま待ち続ける状態を残さない
- 1 回目の表示を短くすることは、project-index が配信元ごとの最初の問い合わせで行う処理（リビジョンの書き出しと文書の一覧の値の作成）の修正で、[shuhei1101/project-index#85](https://github.com/shuhei1101/project-index/issues/85) で扱う。#225 は #85 に依存させ、#85 が済むまで閉じない（[確認ログ](https://github.com/shuhei1101/dev-docs/pull/230#discussion_r4579519925)）

表示できないときの理由は、既存の「project-index に接続できないときの表示」と同じ警告を、理由の種類（接続を断られた・応答が無かった・処理に失敗した）ごとの見出しと説明で出す（[確認ログ](https://github.com/shuhei1101/dev-docs/pull/230#discussion_r4580718694)）。
