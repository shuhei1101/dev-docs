# 要件

## 要望

フォルダ構成の設計書 `docs/layout/LAY-275-1.yaml` と、実態・`layout` のスキーマの `x-rules` との食い違いを解消する。

| Issue | 終わりの条件 |
| --- | --- |
| [#276](https://github.com/shuhei1101/dev-docs/issues/276) | `frontend/src/route-tree.gen.ts`・`frontend/src/shared/api/generated/` を Git で管理するかが決まり、`MOD-155-75` の `notes`・`LAY-275-1` の `generated_from.tracked`・実態（管理しない方針なら `.gitignore` と `.github/workflows/test.yml` の生成の step）が統一されている |
| [#277](https://github.com/shuhei1101/dev-docs/issues/277) | `LAY-275-1` の `migrations` の下の `dev-docs`・`{version}`・`steps.yaml` のエントリが、実体（`migrations/settings/` だけ）に合わせて削除されている |
| [#278](https://github.com/shuhei1101/dev-docs/issues/278) | `LAY-275-1` の `src/dev_docs/`・`frontend/src/` を `layout` のスキーマの `x-rules` に合わせるかが決まり、決めた形に統一されている。合わせる場合は、`children` から除外したファイルごとの説明の移し先が決まっている |

決定した内容（どちらもモジュール構成設計のレビューで確定。規約『ユーザー確認が必須な事項』の型に該当しない）:

| 論点 | 決定 | 理由 |
| --- | --- | --- |
| 生成物を Git で管理するか（#276） | 管理する。`MOD-155-75` の `notes` から管理方針の文を削除し、管理する理由と再生成の方法は `LAY-275-1` の `generated_from` だけに持たせる | [#36](https://github.com/shuhei1101/dev-docs/pull/36) から生成物は commit されていて、型検査・単体テスト・CI が生成の前提なしで動く。方針を 1 か所に持てば同じ食い違いが起きない |
| `src/dev_docs/`・`frontend/src/` を `x-rules` に合わせるか（#278） | 合わせる。`convention` で knowledge の Python・React のフォルダ構成の規約を指し、`children` を生成物・複製のエントリとその親のフォルダだけにする。ファイルごとの説明はファイルごとのモジュール構成の設計書の `description` が持つため移さない | スキーマの `x-rules` に従う。`migrations` の下のエントリも除外され、#277 の削除もこれに含まれる |

## 変更箇所の由来

| 対象箇所 | commit | 目的 | 変更回数 | 影響 |

| `MOD-155-75` の `notes` の生成物の「commit しない」 | [58048a5](https://github.com/shuhei1101/dev-docs/commit/58048a5)（`画面（文書・設定・見つからない画面）を React（Vite + shadcn/ui）の SPA で作る (#36)`） | 画面を作ったときに記載した。同じ commit で `route-tree.gen.ts`・`shared/api/generated/` を commit していて、記載した時点から実態と食い違っていた | 1 回（[#155](https://github.com/shuhei1101/dev-docs/pull/155) はファイルの移動だけ） | 「commit しない」を前提にした仕組み（`.gitignore`・CI の生成の step）は無く、記載を実態に合わせても壊れるものは無い |
