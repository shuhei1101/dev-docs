# 要件

## 要望

フォルダ構成の設計書 `docs/layout/LAY-275-1.yaml` と、実態・`layout` のスキーマの `x-rules` との食い違いを解消する。

| Issue | 終わりの条件 |
| --- | --- |
| [#276](https://github.com/shuhei1101/dev-docs/issues/276) | `frontend/src/route-tree.gen.ts`・`frontend/src/shared/api/generated/` を Git で管理するかが決まり、`MOD-155-75` の `notes`・`LAY-275-1` の `generated_from.tracked`・実態（管理しない方針なら `.gitignore` と `.github/workflows/test.yml` の生成の step）が統一されている |
| [#277](https://github.com/shuhei1101/dev-docs/issues/277) | `LAY-275-1` の `migrations` の下の `dev-docs`・`{version}`・`steps.yaml` のエントリが、実体（`migrations/settings/` だけ）に合わせて削除されている |
| [#278](https://github.com/shuhei1101/dev-docs/issues/278) | `LAY-275-1` の `src/dev_docs/`・`frontend/src/` を `layout` のスキーマの `x-rules` に合わせるかが決まり、決めた形に統一されている。合わせる場合は、`children` から除外したファイルごとの説明の移し先が決まっている |

`未確定`: 生成物を Git で管理するか（#276。決める段: モジュール構成設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 管理する。`MOD-155-75` の `notes` の「commit しない」を、管理する理由に書き換える | 型検査・単体テスト・CI が生成の前提（サーバーの OpenAPI の書き出し）なしで動く。`test.yml` は生成の step を持たず、今のまま通る | API・ルートを変えるたびに生成物の差分が commit に入る |
| B | 管理しない。`.gitignore` に追加して `git rm --cached` し、`test.yml` に生成の step を追加する | 生成物の差分が commit に入らない | CI と手元の型検査の前に `npm run api:generate`（OpenAPI の書き出しに Python の環境が要る）が要り、`実装` の工程が増える |

推奨: A

画面を作った [#36](https://github.com/shuhei1101/dev-docs/pull/36) から生成物は commit されていて、`LAY-275-1` の `generated_from.tracked` も管理する理由を記載している。食い違っているのは `notes` の 1 文だけで、記載を実態に合わせれば足りる。

`未確定`: `src/dev_docs/`・`frontend/src/` を `x-rules` に合わせるか（#278。決める段: モジュール構成設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 合わせる。`convention` で knowledge の Python・React のフォルダ構成の規約を指し、`children` を生成物・複製のエントリだけにする。ファイルごとの説明は、`used_by` が指すモジュール構成の設計書へ移す | スキーマの `x-rules` に従い、ファイルを追加するたびにフォルダ構成の設計書を修正せずに済む | 移し先のモジュール構成の設計書の修正が複数件になる |
| B | 今の形を保ち、`children` にファイルごとのツリーを持つ | 修正が無い | `x-rules` に違反したまま残り、ファイルを追加するたびにフォルダ構成の設計書の修正が要る |

推奨: A

[#275](https://github.com/shuhei1101/dev-docs/pull/275) で `x-rules` から除外したのは、#258 の要望（ツリーをエントリへ移す）を優先したためだけである。A では `migrations` の下のエントリも `children` から除外され、#277 の削除もこれに含まれる。
