## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| スキーマの参照 | `project-index.yaml` の `design-schemas/v8.4.0` を全て `design-schemas/v9.2.2` へ置き換え、管理用の YAML の `$schema` のタグも同じにする | 設計書の行だけを上げると、行ごとに版が分かれるため全て揃える |
| `refs` の書き換え | `write_docs` で 1 文書ずつ `refs` を消して関連の要素（`to`・`item`・`type`・`when`）を書く。`to`・`item` は今の参照から機械的に移し、`type`・`when` は参照元と参照先を読み、判定フローチャート『関連の張り方』で決める。`write_docs` が弾いた `ARCH-155-1`・`CMD-155-1`・`NFR-155-1`・`SCR-155-1` は YAML を直接編集した（[shuhei1101/project-index#175](https://github.com/shuhei1101/project-index/issues/175)） | 参照先の ID・項目のパスは変えない |
| `related.types` | `project-index.yaml` に `related.types` を宣言しない | `type` の値は knowledge の v9.2.2 のスキーマの `enum`（`requires`・`references`・`replaces`・`part_of`・`change_together`）が検査する。`files.yaml` の行の `see_also`・`implements`・`tests` も使用するため、宣言すると全ての種類を並べ直す必要がある |
| 関連のたどり | 最上位に `refs` を持つ設計書の行の `metadata` に `related: refs` を追加する | 追加しないと `trace_related` が設計書の `refs` をたどらない |
| 検査 | 書き換えの後に project-index の `check_project` で配信元 dev-docs を検査し、違反が 0 件になるまで直す | v9.2.2 で他に違反になる箇所があれば、検査に合格させる最小の修正だけを行う |
| 既存機能への影響 | 画面のサーバーの変換と `trace_related` で、書き換えた設計書の関連が表示され、たどれることを確かめる | コードは変えない |
