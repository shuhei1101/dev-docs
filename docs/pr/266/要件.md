# 要件

## 要望

AI Monitor の常駐サーバーの `restart_command` から呼ぶ、dev-docs の常駐サーバーを起動し直すスクリプトを `scripts/` に追加する。

| 項目 | 要件 |
| --- | --- |
| 呼び出し | AI Monitor が、稼働しているブランチ（develop）の作業ツリーを作業ディレクトリにして `bash -c {restart_command}` で実行する |
| 変化の判定 | 前回起動し直した commit と `HEAD` の間で、サーバーが実行時に参照するファイル（`src/`・`content/`・`templates/`・`pyproject.toml`・`uv.lock`・`.python-version`）が変わったかを `git diff` で判定する。前回の記録が無い・記録の commit が見つからないときは変わったものとして扱う |
| 依存の入れ直し | 変わったときは、`uv sync --frozen` で `.venv` を `uv.lock` どおりにそろえてから起動し直す |
| 起動し直し | `systemctl --user restart dev-docs.service` で起動し直し、成功したら起動し直した commit を記録する |
| 変わっていないとき | 依存を入れ直さず、起動し直さずに記録を `HEAD` へ進めて 0 で終わる |
| 終了コード | 成功は 0。依存の入れ直し・起動し直しに失敗したら 0 以外で終わり、記録を進めない（AI Monitor が `resident_server_restart_failed` を通知する） |
| 起動の確認 | AI Monitor が `health_url`（`http://127.0.0.1:8781/health`）の 2xx を確認する。スクリプトは待ち受けを待たない |
| 記録の置き場所 | 端末の設定の状態の置き場所（`${XDG_STATE_HOME:-~/.local/state}/dev-docs/`）のファイル |
| 文書 | 開発コマンドの管理作業に呼び方・効果・確認した記録を、アーキテクチャ図のフォルダ構成の `scripts/` の説明にこのスクリプトを追加する |

`未確定`: 変わっていないときに起動し直すか（決める段: モジュール構成設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 起動し直さずに 0 で終わる（先例 `bin/restart-resident` と同じ） | 文書だけの PR が develop に入るたびにサーバーを止めない | 実行時に参照するファイルの一覧から漏れたファイルの変更が有効にならない |
| B | 依存を入れ直さずに起動し直す | 一覧の漏れがあっても変更が有効になる | 文書だけの PR でも起動し直し、その間画面と MCP が止まる |

推奨: A

dev-docs は配信元の文書を project-index から読み、作業ツリーの `docs/` を実行時に参照しないため、一覧に挙げたファイル以外の変更で起動し直す必要が無い。
