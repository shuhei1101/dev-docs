# 要件

## 要望

テスト実行方法の層ごとに、判定フローチャート『テストの実行場所』で実行場所（`runner` / `local`）を決定し、`runner` の層を GitHub Actions の workflow で回せるようにする。

| 要件 | 終了の条件 |
| --- | --- |
| スキーマの参照 | `project-index.yaml` の設計書の行の `schema.ref` が、テスト実行方法の `location`・`run_runner` とインターフェース定義の workflow を持つ `design-schemas/v8.4.0` で、全ての文書の検査に合格する |
| 層の実行場所 | テスト実行方法の `run_all` が確定している層（単体（バック）・結合（バック）・結合（フロント）・単体（フロント）・lint）と、この作業 PR で `run_all` を記載する E2E テストの層が `location` を持ち、判定の根拠を計画書に記載している。lint と E2E テストは `local` |
| workflow | `runner` の層を `workflow_dispatch` だけで起動する workflow があり、層と結合テストのパスを入力で受け、入力を省いたときは層の全件を回す |
| workflow の設計 | workflow のインターフェース定義を作り、reviewer の合格を受けてから workflow のファイルを作る |
| ランナーでの実行 | `runner` の層が、テンプレート『テスト実行方法』の記載例と同じ呼び方の `run_runner` を持つ |
| 手元での実行 | `runner` の層も `run_all`・`run_one` の手元のコマンドを残す |
| lint | lint の層が actionlint と、`uses:` の `{owner}/{repo}@{バージョン}` が GitHub に実在するかの検査を含む |
| ランナーでの確認 | 規約『Git フックと CI で動かすもの』のとおり、マージの前に作業ブランチで workflow を `push` の契機を一時的に追加して起動し、成功を確認する。そのときのランナーの skip の件数が手元の全件実行と同じことを確認し、計画書の `## テスト結果` に実行の URL と件数を記録する。一時的に追加した `push` は、マージの前に除外する |

ユーザーのコメント（[#198 のコメント](https://github.com/shuhei1101/dev-docs/issues/198#issuecomment-6884758532)）では、workflow を作る作業 PR の中では手元の全件実行で回し、ランナーでの初回は develop へ入った後の作業 PR とされている。
この作業 PR のテストのログは手元の全件実行で取り、理由（workflow が develop に無く `workflow_dispatch` で起動できない）をログに記録する。
規約『Git フックと CI で動かすもの』（2026-11-17 改訂）が新規の workflow をマージの前に作業ブランチで動かすことを求めるため、その実行で skip の件数も照合する。
