# 要件

## 要望

`dev-docs migrate --project-index` の `sources` を移す手順で、次を満たす。

| 要件 | 終わりの条件 |
| --- | --- |
| 書き込みの応答が 45 秒を超えても止まらない | project-index の `POST /settings/sources` の応答に 45 秒を超えて 60 秒以内でかかる行があっても、移し替えが終了コード 0 で終わり、dev-docs の端末の設定から移した行が除かれる |
| 途中で失敗しても食い違いを残さない | 移し替えが終了コード 0 以外で止まったとき、project-index の端末の設定の `sources` が、その実行の前と同じ行の集まりになっている（dev-docs の端末の設定は今と同じく書き換えない） |
| `切り戻し.sh` が動く | [#183](https://github.com/shuhei1101/dev-docs/pull/183) の反映作業「端末の設定の移し替え」の `切り戻し.sh` が、`yaml` を参照できる Python で控えを参照し、その作業の実行で `dev-docs migrate` が作った控えだけを dev-docs の端末の設定へ書き戻す |

`未確定`: 書き込みの応答が 45 秒を超えたときの扱い（決める段: インターフェース定義設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 端末の設定の書き込みだけ、読み取りと別の制限時間にする。値は project-index の書き込みの後の読み直しの時間から規約『資源の値の決め方』で導く | dev-docs だけで修正できる | 読み直しの時間は配信元の数で伸び、導いた値もいずれ超えうる |
| B | 制限時間を超えたら `GET /settings/sources` で行の有無と内容を確認し、同じ行があれば追加済みとして続ける | 書き込みの時間に依存せず、dev-docs だけで修正できる | 書き込みが保存の前に止まっていた場合と区別するため、確認の手順が増える |
| C | project-index の書き込みを、保存した時点で応答し読み直しを待たない契約にする（shuhei1101/project-index へ起票する） | 書き込みの応答が速くなり、画面の保存も速くなる | 提供する側の変更を待つ。応答の時点で状態が返らなくなる |

推奨: B

書き込みの時間は project-index の配信元の数で変わり、待ちの値をどう決めても超えうる。保存した行は読み直しの前にファイルにあるため、確認すれば提供する側を待たずに続けられる。

`未確定`: 途中で失敗したときに project-index を元へ戻す方法（決める段: インターフェース定義設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | その実行で追加した行だけを project-index から取り除く（`PUT /settings/sources` で実行の前の行の集まりを送信する） | 実行の前と同じ状態へ戻る | PUT の応答も遅く、戻す途中でも打ち切られうる |
| B | 戻さず、追加した行の id と、もう一度実行すれば揃う案内を出す（同じ行は追加済みとして扱われる） | 処理が増えない | 再実行するまで食い違いが残り、要望の終わりの条件を満たさない |

推奨: A

要望が食い違いを残さないことを求めている。戻す PUT が打ち切られたときの扱いは、1 つ目の論点の決定に合わせる。
