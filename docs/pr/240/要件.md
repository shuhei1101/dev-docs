# 要件

## 要望

- mdmark を、既定では mdmark の develop の最新で参照する。次の 3 か所が対象
  - 画面が読み込む mdmark（`use-mdmark.ts` の `MDMARK_URL`・`MDMARK_CSS_URL`）
  - 結合テストが図を点検する CLI（今は `package.json` の `devDependencies`。`package-lock.json` が commit に解決するため、実行時に `npx -y github:shuhei1101/mdmark#{参照}` で取る形へ移す）
  - 公開ページをまとめる CLI（`scripts/build_pages.py` の `MDMARK_TAG`）
- 設定で、特定のバージョン（タグ・commit）を指定して固定できる。画面は設定で固定し、結合テストの CLI と公開ページのビルドはそれぞれの書き方で固定する（3 か所を 1 つの値で揃えることは求めない）
- mdmark のバージョンを上げるたびにコードの値を書き換える作業を無くす（`## 変更箇所の由来` の判定）
- mdmark の develop の壊れた変更への備え: 描画の確認は dev-docs の作業 PR のテストのときに行う。mdmark の develop のマージで画面が壊れてから気づくまでの間は、利用者が設定で mdmark のバージョンを固定して回避する。この扱いを NFR-12 の溢れたときに記載する
- develop の最新への切り替えは、[shuhei1101/mdmark#620](https://github.com/shuhei1101/mdmark/issues/620) で develop の最新を参照できる（develop の `dist/` が最新になる・`npx github:shuhei1101/mdmark#develop` で動く）ことを確かめてから行う

`未確定`: 設定のキーの置き場所と、画面へ渡す経路（決める段: インターフェース定義設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 端末の設定 `settings.yaml` にキー（例: `mdmark.version`。既定は develop の最新）を追加し、サーバーが画面へ渡す | ビルドし直さずに利用者が固定・解除できる | 画面の API か HTML へ値を渡す経路が増える |
| B | 画面のビルド時の値（Vite の環境変数）で持つ | サーバーの変更が要らない | 固定するたびに画面をビルドし直す |

推奨: A

ビルド済みの画面を配る dev-docs では、利用者がビルドし直さずに固定できる必要がある。
`package.json`・`build_pages.py` は端末の設定を読まないため、それぞれの固定の書き方は設計で決める。

`未確定`: develop の最新を追う方法（決める段: モジュール構成設計）

jsDelivr はブランチを CDN で 12 時間・ブラウザで 7 日キャッシュする（NFR-12 の外部の制約）。
`@develop` の URL を使うか、mdmark の側で動かすタグ・キャッシュの消去を使うかは、mdmark#620 の結論に合わせて決める。
