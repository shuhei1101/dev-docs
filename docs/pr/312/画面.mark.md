## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 固定の位置 | `index.css` で `@property --mdmark-sticky-top { syntax: "<length>"; inherits: true; initial-value: 0px; }` を登録し、`--mdmark-sticky-top` の計算値を px（`96px`）にする。値の式（`calc(var(--spacing) * 24)`）は変えない | mdmark の `script` の方式が計算値を `parseFloat` で読み込むため（`### 原因の切り分け`） |
| 確認 | 利用者の iPad で、表の見出し行が上端に隠れる時にだけ固定されることを確認する | この端末では WebKit を起動できない（`### 原因の切り分け`） |
| レスポンシブ対応 | iPad の縦・横の画面幅と、デスクトップの画面幅で、固定の位置が同じ下端に一致する | デスクトップの既存の振る舞いを変えない |
| 既存機能への影響 | 右側の目次のブロックの上端と目次から移った見出しの止まる位置（同じ `--mdmark-sticky-top` を使用する）が変わらない | - |

### 原因の切り分け

dev-docs の文書の画面（[docs/screen/SCR-155-1.yaml](https://docs.shuhdev.com/dev-docs/docs/screen/SCR-155-1.yaml?rev=develop)）の表を、Playwright の Chromium で、iPad Pro 11 の画面幅とタッチ（縦・横）とデスクトップの画面幅で測った。
mdmark は `develop`（[shuhei1101/mdmark#705](https://github.com/shuhei1101/mdmark/pull/705) を含む）を読み込んでいる。
`script` の方式は、`CSS.supports` の `animation-timeline` を偽にして再現した。

| 方式 | `--mdmark-sticky-top` の計算値 | 表の上端から 150px スクロールした後の見出し行の上端 |
| --- | --- | --- |
| `timeline` | `calc(.25rem * 24)` | 96px（トップバーと種類のタブの下端） |
| `script` | `calc(.25rem * 24)` | 0px（画面の上端。トップバーの下に隠れる） |
| `timeline` | `96px`（`@property` を登録） | 96px |
| `script` | `96px`（`@property` を登録） | 96px |

`script` の方式は、mdmark がスクロール連動のアニメーションを持たないブラウザ（iPadOS 18 以前の Safari など）で使用する。
mdmark はこの方式で `--mdmark-sticky-top` の計算値を `parseFloat` で読み込むため、登録していない変数の計算値 `calc(.25rem * 24)` を 0 として扱う。
mdmark の側の不具合は [shuhei1101/mdmark#789](https://github.com/shuhei1101/mdmark/issues/789) に起票した。

この端末では WebKit を起動できない（ライブラリが足りず、導入には sudo が要る）。
そのため、Issue の「画面の半分ほどの位置で固定される」事象そのものは再現していない。
iPadOS 26 以降の Safari が使用する `timeline` の方式では、Chromium は正しく留まった。
