## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| インターフェース定義 | `docs/interface/IF-155-27.yaml` を新規に作り、`pages.yml` の起動の条件・権限・同時実行・job と step の流れ・タイムアウトを、IF-155-26 と同じ書式で記載する | 制約・タイムアウトの値は今の `pages.yml` のまま記載し、変えない |
| フロー | 正常系（develop への push で配信して成功）・正常系（develop 以外のブランチ。配信を飛ばして成功）・異常系（公開の文書をまとめられない・成果物に YAML がある）の 4 つ | 異常系は `build` の job の step の失敗 2 か所に 1 つずつ |
| 配信の job の条件 | 規約『Git フックと CI で動かすもの』の「配信・公開するジョブは、配信してよいブランチだけで動かす」のとおり、`deploy` の job に `if: github.ref == 'refs/heads/develop'` を付ける | develop への push の振る舞いは変わらない。develop 以外のブランチの実行は、環境の規則で拒否されて失敗で終わっていたのが、`deploy` を飛ばして成功で終わるようになる |
| step の名前 | フローの図の step と E2E テストの突き合わせは workflow の step の `name` で行うため、`name` を持たない 6 つの step（`actions/checkout`・`actions/setup-node`・`astral-sh/setup-uv`・`actions/configure-pages`・`actions/upload-pages-artifact`・`actions/deploy-pages`）に、IF-155-27 の図の step の名前を付ける | step の振る舞いは変えない |
| E2E テスト | `flows[]` ごとに `tests/e2e/workflow/test_pages_yml.py` へテストの関数を作り、`tests/e2e/workflow/conftest.py` の fixture で起動する。正常系だけは起動せず、develop への push の直近の実行を `gh run list` で取得して確認する | 手元の E2E テストの層で回す。develop は [#285](https://github.com/shuhei1101/dev-docs/issues/285) の不具合で `build` の job が失敗するため、2 つの正常系は #285 の修正が develop へ入るまで pass しない |
| 同時実行 | `concurrency` の `group: pages`・`cancel-in-progress: false` のため、検証用のブランチの実行は develop の配信の実行と順に並ぶ。待機できるのは 1 件で、待機中の実行は後から来た実行に取り消されるため、検証用のブランチで起動するテストは 1 件ずつ起動し、終了を待ってから次を起動する | 待つ上限は conftest の値を使用する。develop への push と重なって `cancelled` になったときは、テストを起動し直す |
| 費用 | public のリポジトリの標準ランナーで回し、料金は発生しない | - |
