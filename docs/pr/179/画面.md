## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 列の表示のメニューの照合（#157） | 照合は変えず、全件実行で 4 件の pass を確かめる | fail した場合だけ mdmark v0.10.0 の画面に合わせて照合を直す |
| 時間切れの原因の特定（#170） | 全件実行を、端末の負荷（load average・`free -m`・ほかの全件実行の有無）とあわせて記録し、`search-dialog.spec.ts`・`topbar.spec.ts` の fail を再現する。Playwright の trace で、時間切れの時点でストーリーが描画を終えていないのか、Storybook の応答が遅れているのかを切り分ける | - |
| ストーリーの待ち方（#170） | `openStory` が、ストーリーの描画の完了まで待つようにする | 待つ対象は原因の特定の結果で決める |
| 並列度（#170） | 負荷が原因の場合、`playwright.config.ts` の `workers` に上限を置く | 上限の値は、全件実行で時間切れが出ない値を実測して決める |
| 期待値 | 単独で実行して pass する spec の期待値・待ち時間（`expect` 15 秒）は変えない | - |

#170 の原因の特定の結果。

| 項目 | 内容 |
| --- | --- |
| 再現 | 修正前の全件実行（4 workers）で、`search-dialog.spec.ts` の 7 件と `topbar.spec.ts` の `doc_view` が 15 秒の時間切れで fail した。実行中の load average は 13〜14（8 コア）、`free -m` の available は 7.2〜7.8GB、ほかの全件実行は 0 件 |
| 切り分け | Playwright の trace では、時間切れの時点の画面は Storybook のストーリーの準備中の表示のままで、部品のモジュールと事前バンドルした依存（`cmdk`・`lucide-react` 等）の取得に応答が無かった。Storybook の応答が遅れ、ストーリーは描画を始めていない |
| 原因 | `openStory` の `#storybook-root > *, #storybook-root` が空の `#storybook-root` に該当し、描画を待たずに終わっていた。spec ごとに最初に開くストーリーで、Storybook がモジュールを変換する時間を `expect` の 15 秒が負担していた |
| 修正 | `openStory` が描画の開始を待つ。待ちの上限はテストの `timeout`（60 秒）。依存の事前バンドルのキャッシュ（`node_modules/.cache/storybook`）を削除した全件実行で、`search-dialog.spec.ts` の `empty` は描画の開始を待って 36.4 秒で pass した |
| 並列度 | 修正後の全件実行は load average 20 前後でも全件 pass したため、`playwright.config.ts` の `workers` は変えない |
