# 要件

## 要望

文書の取得（`GET /_api/sources/{source}/docs`）が、同じ配信元の同じ commit の文書の一覧を、文書を開くたびに project-index から取り直さない。
dev-docs が受け持つのは、文書の一覧の取り直しと画面の API の応答の大きさで、project-index の文書 1 件の読み込みの時間は範囲に含めない。

- 一度取得した値つきの文書の一覧を、配信元と、リビジョンを解決した commit の組で保持し、同じ組の文書の取得では project-index へ文書の一覧を問い合わせない
- 差分の比較元のリビジョンの文書の一覧も、同じ保持から取得する
- 同じ組の文書の一覧を取得している間に届いた文書の取得（差分つきの取得と、画面が並行に送る比較元の取得）は、その問い合わせの結果を共有する
- ブランチを指したリビジョンは、ブランチが進んで別の commit に解決されたら、その commit の文書の一覧を取得する
- commit に解決できない配信元（読み書きの方法が `disk` の配信元）は、今までどおり文書の取得のたびに文書の一覧を取得する
- 画面の API の応答は、ブラウザが `Accept-Encoding` で受け付けると伝えた圧縮で返却する
- 確認の基準: 偽の project-index で、同じ配信元の同じ commit の文書を差分つきで 2 回開いたとき、2 回目の文書の一覧の問い合わせが 0 回になる。`Accept-Encoding: gzip` を付けた文書の取得の応答が gzip で返り、展開した本文が圧縮しないときと同じになる

保持する文書の一覧の数は、配信元と commit の組を最後に使用した順に上限まで保持し、超えたら最も前に使用した組を捨てる。上限は非機能要件の「保持する文書の一覧の数」（4 組）に配置する。
