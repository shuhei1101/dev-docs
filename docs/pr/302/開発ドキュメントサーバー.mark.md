## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 文書の一覧の保持 | 値つきの文書の一覧を、配信元と、リビジョンを解決した commit の組をキーにし、配信元の設定の応答のハッシュを添えてプロセスのメモリーに保持する。保持にあるときは設定のハッシュを比べ、違えば取り直す。表示側と差分の比較元の両方の取得で、この保持を使用する。同じ組の一覧を取得している間に届いた取得は、その問い合わせの結果を共有し、project-index へは 1 回だけ問い合わせる | 上限は非機能要件の「保持する文書の一覧の数」 |
| リビジョンの解決 | 文書の取得の始めに、指定のリビジョン（省略時は既定のリビジョン）を commit に解決してからキーにする。配信元の設定と同時に問い合わせているリビジョンの一覧の `branches[].commit`・`tags[].commit` で解決し、保持に無いときは解決した commit を `ref` に指して文書の一覧を問い合わせる | リビジョンの一覧の応答は ai-monitor で 0.17〜0.37 秒（2026-11-20 計測） |
| commit に解決できない配信元 | 読み書きの方法が `disk` の配信元と Git 管理外の配信元は保持せず、文書の取得のたびに一覧を取得する | - |
| 応答の圧縮 | 画面の API の応答を、ブラウザの `Accept-Encoding` に合わせて gzip で返却する | 圧縮する最小の大きさは、モジュール構成設計で決める |
| 性能 | 同じ配信元の同じ commit の 2 回目以降の文書の取得で、project-index への文書の一覧の問い合わせを 0 回にする | 結合テストで、問い合わせの回数を数える偽の project-index で確認する |
| 既存機能への影響 | 応答の内容（タブ・サイドバー・差分の項目・変わった文書のマーカー）は変えない | 既存の文書の取得の単体テスト・結合テストが pass することで確認する |
