# 要件

## 要望

`docs/` の文書（`docs/pr/`・`docs/mock/` を除く）を、Issue の必読の手順 A-5 の手順 1〜7 で移行する。

| 手順 | 終わりの条件 |
| --- | --- |
| 1. 棚卸し | `search_docs` で、Mermaid・接頭辞の無いタグ・不足した `description`・本文に生の文字で記載した ID と Issue 番号とパス・避ける単語を含む文書の一覧が揃っている |
| 2. 図の置き換え | 手で記載した Mermaid が、画面で mdmark の map の範囲として描かれている（YAML の文書は変換が囲み、Markdown の文書は元の文書で囲む） |
| 3. 文を表へ | 同じ属性を持つ項目が 2 件以上ある文・箇条書きが表になっている |
| 4. 文を削り、AI slop を修正する | 既出の言い直し・理由の説明・当たり前の注意が削られ、knowledge の規約『文章の書き方』の確認表と AI slop の単語の対応表に当たる箇所が無い |
| 5. メタデータの付け直し | `tags` を持つ文書のタグが接頭辞（`action:`・`topic:`・`tool:`）付きで `main` を 1 つ持つ。`description`（設計書は `lead`）が「何を定め、どんなときに読むか」の 1 文になっている。エイリアスと用語が判定フローチャートで判定され登録されている |
| 6. 本文に出さないものの移動 | 本文の検討事項の ID が関連のキーへ、Issue 番号・文書のパスがタイトル付きのリンクへ移っている |
| 7. 検査 | `write_docs` の検査と mdmark の `check` を通り、画面で描いた図が重ならず読める |

YAML の書き込みは `write_docs` で行う（引用符が書き換わる不具合は #91 で解消済み）。
