## 変更方針

<!-- table: {"kind": "data"} -->

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 一括操作 | 直コミットの要求に編集を始めたときのコミットを受け、project-index の書き込みの API へ `baseCommit` として送信する | - |
| 編集機能 | `update` の変更は、`expected_version` を、修正した列が戻る文書の最上位のキーだけの項目ごとのバージョンの辞書にして送信する。`delete` は今と同じ文書の全体のバージョン | 取得の方法は要件の `未確定` に従う |
| エラー返却 | 書き込みの API が衝突して 200 の `conflict` を返却したときは、残したブランチ・ブランチの起点・スクリプトの結果（PR の URL を含む）と、変更ごとの断った理由を画面へ返却する。`BaseCommitUnusableError` の 409 は理由を `detail` に入れて返却する | PR の URL の読み取り方は要件の `未確定`（スクリプト）に従う |
| 権限・認可 | dev-docs の `project-index.yaml` に `direct_commit`（`branch: develop` と許可する種類）を追加する | 種類は要件の `未確定` に従う |
| 運用 | 衝突したときのスクリプトを追加し、端末の設定の `sources[].direct_commit.on_conflict.command` と `write_api_kinds` を反映作業で登録する | 配置先と処理は要件の `未確定` に従う |
| 外部 API 制約 | 項目ごとのバージョンの取得の待ちは、非機能要件の project-index への問い合わせの制限時間を使用する | - |
| 既存機能への影響 | `baseCommit` を送信しない要求（ほかの呼び出し元）の扱いは変えない。衝突しないときの応答は今のまま | 既存の結合テストで確認する |
