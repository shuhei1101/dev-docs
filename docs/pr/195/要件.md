# 要件

## 要望

Pages を mdmark の `build` で描くようになった後に参照するものが無い、次のファイルを削除する。

| 対象 | 中身 |
| --- | --- |
| `docs/_config.yml` | Jekyll の設定（`exclude`） |
| `docs/_theme/` | AI Monitor のテーマ（`_layouts/`・`_includes/`・`_data/nav.yml`・`_data/nav.project.yml`・`assets/`・`search.json`・`llms.txt`） |
| `docs/guide/はじめに.md`・`使い方.md`・`リファレンス.md` | Jekyll の分類のトップページ（`permalink` を持つ） |
| `ai-monitor-theme.yaml` | `docs/_theme/` を取り込んだバージョンの記録 |

削除に合わせて次を修正する。

- `はじめに.md` にだけある `## dev-docs と project-index の分担` の表と続く 2 行を、`はじめに` の分類の `コアコンセプト-配信元と権限.md` へ移す
- `project-index.yaml` の `files_guide` の `exclude` から、削除した 3 つのトップページを除外する
- `schemas/files.schema.yaml` の `category` の説明から Jekyll の上タブ・分類のトップページを除き、公開ページの文書の一覧の並びにする

終わりの条件:

- `origin/develop` に上の 4 つの対象が無い
- `scripts/build_pages.py --out tmp/pages` が終了コード 0 で公開ページを作り、分担の表が `コアコンセプト-配信元と権限` のセクションとして入る
- dev-docs の配信元の検査で、`files_guide` の警告が増えない

AI Monitor のテーマは、Pages も他のファイルも参照しないため dev-docs に残さない。
[#74](https://github.com/shuhei1101/dev-docs/issues/74) から移した v0.4.0 のテーマの取り込みは実施しない。

`未確定`: AI Monitor の追従 Issue の「サイトのレイアウト」「配信設定」の行の受け取り方（決める工程: ドキュメント修正のレビュー）

記録の `ai-monitor-theme.yaml` が無い配布先でも、`import-site` は `source: copy` として扱い `docs/_theme/` を作り直す。
追従 Issue は配布元の `distribution.yaml` の分類から行を作るため、dev-docs が受け取らないことを記載する先を決める。

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | AI Monitor へ、テーマを受け取らない配布先の扱い（記録で受け取らないと宣言し、追従 Issue に行を出さず `import-site` が止まる）を Issue として起票し、dev-docs は削除だけをする | 配布物を選ぶ処理のある配布元で決まり、ほかの配布先も同じ扱いを使用できる | AI Monitor の対応が入るまでは、追従 Issue に 2 つの行が出る |
| B | dev-docs の `CLAUDE.md` に、追従 Issue の「サイトのレイアウト」「配信設定」の行は対象外とする旨を 1 行記載する | dev-docs だけで完結する | 毎ターン注入される `CLAUDE.md` が増え、配布元の変更に追従しない |

推奨: A

追従 Issue の行を決めるのは配布元の `distribution.yaml` で、受け取らない配布先の扱いも配布元が持つほうが、追従のたびに配布先で行ごとに対象外と判断せずに済む。
