# 要件

## 要望

`dev-docs serve` の起動と起動し直しを、次のとおりに修正する。

| 項目 | 要件 |
| --- | --- |
| 起動し直し | 管理の MCP の `restart`・`systemctl --user restart dev-docs.service`・セッション開始のフックのどれで起動し直しても、起動し直した後に `127.0.0.1:8781` を持つプロセスは 1 つで、その起動時刻が起動し直した時刻より後になる |
| 同時の起動 | `dev-docs serve` を同時に 2 回起動しても、待ち受けるプロセスは 1 つで、もう片方は 0 でない終了コードと、ポートを持っているプロセスの pid を含む理由を標準エラーに出して終わる |
| 常駐の仕組みとの重なり | 常駐の起動の仕組み（systemd --user の unit）が動いている端末では、セッション開始のフックが unit の外にプロセスを起動しない |
| 起動の繰り返し | 常駐の起動の仕組みが、ポートの使用中で終わった `dev-docs serve` を起動し直し続けない |

起動の仕組みを 1 つにする方法は、単一ユースケース設計のレビューで案 A に決めた。

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | global-setup が systemd --user の unit（ポートの使用中の終了コード 3 では起動し直さない）を作る。セッション開始のフックは、つながらないとき unit があれば `systemctl --user start` で起動し、unit が無い端末では今のとおり切り離して起動する | unit を止めれば配信するプロセスが必ず止まり、AI Monitor の `restart_command` を変えずに引き継げる | systemd が無い端末（macOS 等）では、フックが切り離して起動する経路が残る |
| B | `dev-docs serve` が状態の置き場のロックで 1 プロセスに絞り、起動し直すときは前のプロセスへ停止を求め、ポートが空いてから待ち受ける | 起動の仕組みによらず 1 つになる | 停止を求める経路が増え、同時の起動と起動し直しの見分けが要る |

採用: A

この端末の事象は unit の外で起動したプロセスが残ったことで起きており、起動の仕組みを unit に統一すれば、起動し直しと同時の起動の両方を systemd が 1 つに絞る。
