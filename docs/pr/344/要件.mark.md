# 要件

## 要望

- 画面の検索の結合テストで、一致した行の数のテストを `matchCount` を返却する project-index の commit（develop の `2588d67`）に固定した本物の project-index を相手にし、文書ごとの `matchCount` が本物の一致した行の数になることを確かめる
- 検索のダイアログの「一致した行の数」の並び順（多い順）と「一致 N 行」を、本物の project-index の応答で確かめる
- 外部 API『project-index の読み取り API』（API-155-1）の `GET /sources/{source}/search` の行と `verification` を、`2588d67` と照合した内容に書き換える
- 本物とモック（#340 の単体テスト・ストーリー・結合テストの固定の応答）の食い違い（キー名・型・数え方・`matchCount` を持たない文書の扱い）があれば、設計書から修正する

検索のダイアログを本物の応答で確かめる方法（結合テスト作成で案 A に決めた）

| 案 | 内容 |
| --- | --- |
| A | 本物の project-index を相手にした画面の検索の結合テストで得た応答を、検索のダイアログの結合テスト（`tests/integration/frontend/search-dialog.spec.ts`）の API の応答に使用し、並び順と「一致 N 行」を確かめる |
| B | 本物の project-index と開発ドキュメントサーバーを起動し、画面の結合テストから検索のダイアログを開いて確かめるテストを新規に作る |

推奨: A

画面の結合テストは全て API の応答を差し替えて動かしており、B は本物のサーバーを起動する仕組みを画面の結合テストに新規に作ることになるため。
