## 変更方針

<!-- table: {"kind": "data"} -->

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 検索の結果のスクロール | 結果の一覧の領域に高さの上限を持たせ、その中で縦にスクロールして返却した全件を参照できるようにする。返却する件数の上限は画面の検索の `limit` の上限（100）にし、超える件数は件数の文言で示す | 上限を超えたときの続きの表示方法は部品設計で決める |
| ダイアログの位置と大きさ | 画面の上寄り（上端から一定の余白）に出し、幅と高さを画面に合わせて広げる。スマホの幅では画面いっぱいにし、右上に閉じるボタンを出す | 値はモックの値（上端 `top-12`・最大の幅 `max-w-3xl`・最大の高さ `max-h-5/6`） |
| 結果の一覧の見た目 | カードをやめ、区切り線で区切った行で並べる（knowledge の規約『業務画面のUI要素』の「一覧の行」）。行は名前・配信元・パス・一致した箇所を持つ | - |
| 並び順 | 一致した行の数の多い順を既定にし、行に一致した件数を出す。名前の順へ並べ替えを選べるようにする | 一致した行の数は画面の検索の `items[].matchCount`。`null` の文書は数を出さず、一致した行の数の順では名前の順で後ろに並べる |
| 「検索から除外した文書も含める」 | スイッチを残し、文言を「配信元の設定で検索から除外した文書も含める」にする | モック作成でユーザーが選んだ案 A |
| 横断の検索 | 「この配信元」「全ての配信元」の範囲を切り替え、全ての配信元では結果の行に配信元の名前を出す。結果を選ぶとその配信元のその文書を開く | 画面が配信中の配信元ごとに画面の検索を呼ぶ。リビジョンは各配信元の `defaultRef`。配信していない配信元と検索が失敗した配信元は「検索できなかった配信元」に理由つきで出す |
| 差分の案内のラベル | 「比較元」「比較先」の文字色を、`bg-muted` の上でコントラスト 4.5:1 以上になる `text-foreground` 系の色にする | `detect_screen_issues` で確認する |
| 骨格の高さ | 文書の画面の骨格を表示領域の高さ（`100dvh`）に収め、本文とサイドバーの中だけがスクロールするようにする。ヘッダー・種類のタブの高さを除いた高さをサイドバーの `max-height` にする | メタデータの画面・設定画面・見つからない画面は、サイドバーを `sticky` で留めず、`min-h-screen` は中身が画面より長いときだけ画面全体でスクロールするため変えない（実装で `detect_screen_issues` と撮影で確認する） |
| サイドバーの省略 | page の名前と group の見出しを `truncate`（1 行・`…`）にし、省略した行は `title` かツールチップで全文を出す | 全文の表示方法は部品設計で決める |
| アクセシビリティ | 検索のダイアログの `combobox`・↑↓・Enter・Esc、件数の `role="status"`、範囲の切り替えのキー操作を保つ | - |
| レスポンシブ対応 | スマホの幅で、検索のダイアログが画面いっぱい、ドロワーの一覧も省略で 1 行になる | - |
| 既存機能への影響 | サイドバーの境目のドラッグ・閉じる・開く、ドロワーの一覧、本文の右側の目次の固定位置（`--mdmark-sticky-top`）を保つ | - |
