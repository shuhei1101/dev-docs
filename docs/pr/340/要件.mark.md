# 要件

## 要望

文書の画面の検索のダイアログ・差分の案内・画面の骨格の高さ・サイドバーの文書の一覧を、子 Issue ごとの終了の条件まで修正する。

| Issue | 終了の条件 |
| --- | --- |
| [#338](https://github.com/shuhei1101/dev-docs/issues/338) | 結果を全件スクロールして見られる。モーダルが画面の上寄りで結果を多く見られる大きさになる。結果の一覧がカードでなく区切り線か表の行で並ぶ。並び順の根拠が分かるか並べ替えを選べる。「検索から除外した文書も含める」の要否を見直し、残すなら何を含めるかが分かる文言になる。配信元を横断して検索でき、結果に配信元の名前が出る。キーボードでの移動・結果から文書を開くなど既存の機能を落とさない |
| [#334](https://github.com/shuhei1101/dev-docs/issues/334) | 差分の帯のラベルの文字色が、背景とのコントラスト 4.5:1 以上になる |
| [#337](https://github.com/shuhei1101/dev-docs/issues/337) | 文書の画面で画面全体の縦のスクロールバーが出ない（本文・サイドバーの中のスクロールとスマホの幅の表示はそのまま） |
| [#336](https://github.com/shuhei1101/dev-docs/issues/336) | サイドバーの文書の一覧の行とフォルダ・見出しなどほかの文字が折り返さず 1 行で出る。境目で広げられる最大の幅に収まらない名前は末尾が「…」で省略される。境目のドラッグ・ドロワーの一覧を落とさない |

- 検索の結果の一覧は、knowledge の規約『業務画面のUI要素』の「一覧の行」に沿って、区切り線か表の行で並べる
- 横断の検索は、開いている配信元だけの検索と切り替えられ、結果の行に配信元の名前を出す。結果を選ぶと、その配信元のその文書を文書の画面で開く
- 画面全体のスクロールバーは、文書の画面に加えて、同じ `min-h-screen` の骨格を持つメタデータの画面・設定画面・見つからない画面でも出ていないかを確認し、出ていれば同じ作業で修正する
- 差分の案内・検索のダイアログ・サイドバーの変更の後に、`detect_screen_issues` で `color-contrast` と横スクロールが出ないことを確認する

`未確定`: 横断の検索の取得の方法（決める工程: インターフェース定義設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 開発ドキュメントサーバーが配信中の配信元ごとに project-index の語での検索を呼び、結果をまとめて返却する | project-index を変えずに作れる | 配信元の数だけ問い合わせ、並べ替えの根拠（一致した行の数）を dev-docs で数える |
| B | project-index の HTTP の語での検索に配信元の横断と一致した行の数を加え、dev-docs はそれを呼ぶ | 1 回の問い合わせで横断でき、並べ替えの根拠を project-index が返却する | project-index の Issue と、そのリリースを待つ依存が増える |

推奨: A

project-index の HTTP の語での検索は配信元ごとで、結果は `page_path` の順に並び、一致した行の数を返さない（[#338 の受付のレビュー](https://github.com/shuhei1101/dev-docs/issues/338#issuecomment-7197861416)）。
dev-docs の中で完結すれば束の作業が別のリポジトリのリリースを待たずに済み、配信元の数は端末の設定の行の数に限られる。

「検索から除外した文書も含める」のスイッチは残し、文言を「配信元の設定で検索から除外した文書も含める」にする（[確認事項](https://github.com/shuhei1101/dev-docs/pull/340#discussion_r4711834633)）。
