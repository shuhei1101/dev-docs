# 要件

## 要望

AI Monitor の配布物を v0.3.0 から v0.4.0 へ追従する。
完了の条件は次のとおり。

- `ai-monitor-version.ini` の先頭行が `v0.4.0` になっている
- `project-index.yaml` の設計書の種別の行（`architecture`・`nonfunctional`・`scenario`・`interface`・`module`・`screen`・`component`・`config`・`api`・`library`・`test_procedure`・`dev_command`・`flowchart`・`index`）と管理用の YAML の行（`files_root`・`files_guide`・`files_mock`）の `schema` が、knowledge のスキーマの参照（`source: knowledge`・`path`・`ref: design-schemas/v8.1.0`）を指している。指す `path` は反映作業『各プロジェクトのスキーマの参照への移行』の `common.py` の `COPIES` の対応に従う
- `schemas/` に AI Monitor から配られたスキーマのコピー（設計書の種別のスキーマ・`common.schema.yaml`・`files.schema.yaml`・`phase.schema.yaml`）と、設計書の変換（`conversions/`）が無い
- AI Monitor の設計書の検査（`python -m ai_monitor.design_docs validate`）で、develop に無かった違反が出ない
- `pyproject.toml` の lint・型検査の除外に、削除した `schemas/conversions` を指す行が無い
- v0.3.0..v0.4.0 で変わった規約・判定フローチャート・チェックシート・テンプレートのうち、dev-docs の成果物が従っていない箇所が無い（改めて参照して見つけた箇所は、この PR で修正するかスコープ外へ回す）
- `反映作業/index.yaml` の配布先の反映作業が全て済になっている

`flowchart` の行は既に knowledge の参照（commit の SHA）を指しており、全ての行の `ref` を統一しないと検査がリビジョンの不一致で止まるため、`design-schemas/v8.1.0` へ統一する（2 つのリビジョンの間で `schemas/flowchart.schema.yaml` は変わっていない）。

knowledge の `design-schemas/v8.1.0` のスキーマに無いキーは、次のとおり移す。

| キー | 設計書 | 移し方 |
| --- | --- | --- |
| `issue` | シナリオ | 削除する（AI Monitor の変換 `design-schemas/v8.1.0` と同じ） |
| `introduced` | 部品設計・アーキテクチャ図の `subsystems[]` | 削除する |
| `functions[].callers`・`classes[].methods[].callers` | モジュール構成 | 削除する（AI Monitor の変換 `design-schemas/v8.1.0` と同じ） |
| `subsystems[].implementation` | アーキテクチャ図 | 削除する（knowledge が使用先の無いキーとして除外した） |
| `repository.layout` | アーキテクチャ図 | 本文のツリーを `notes` の「フォルダ構成」のセクションへ移す |
| `directory` | モジュール構成 | 本文のツリーを `notes` の「フォルダ構成」のセクションへ移す |

AI Monitor の変換（`python -m ai_monitor.design_docs convert --from v0.3.0 --to design-schemas/v8.1.0`）は実行しない。
変換は `repository.layout`・`directory` のツリーをフォルダ構成の設計書（`layout`）へ移そうとし、dev-docs の `project-index.yaml` に `layout` の行が無いため移し先を決められずに止まる。
変換は `docs/module/` の ID 名の設計書を物理ファイルのパス名へ改名する不具合も持つ（[shuhei1101/ai-monitor#3357](https://github.com/shuhei1101/ai-monitor/issues/3357)。open）。
書き込みのツール（`write_docs`）は `[{キー}]` を含む項目のパスを削除できないため、ruamel.yaml の往復編集でキーを移す。

`ARCH-155-1.yaml` の `line: reply` は、`design-schemas/v8.1.0` のアーキテクチャ図のスキーマが `line` の値に `reply` を許可するため残す。

反映作業『各プロジェクトのスキーマの参照への移行』の実行スクリプトは配信元の設定を `dev-docs.yaml` に決め打ちしており、`project-index.yaml` の dev-docs では前提確認で止まる（[shuhei1101/ai-monitor#3472](https://github.com/shuhei1101/ai-monitor/issues/3472)。open）。
この PR では、同じ書き換え（`common.py` の `rewrite`・`copies`）を `project-index.yaml` と `schemas/` に当て、確認スクリプトで結果を確認する（`project-index.yaml` を指す一時的な `dev-docs.yaml` のリンクを配置して実行し、実行した後に削除する）。
