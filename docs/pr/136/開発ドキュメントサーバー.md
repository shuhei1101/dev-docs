## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 起動直後の文書の MCP（#123） | 配信元を端末の設定の行ごとに読み込み、読み込み終えた行から配信する。要求は指す配信元の行の読み込みだけを待ち、待っている要求が指す行を先に読み込む | インターフェース定義『起動』の配信元の読み込みの単位 |
| 画面の文書の API（#123） | 文書の MCP と同じく、指す配信元の読み込みだけを待つ | 画面の設定の API は全ての行を待つ |
| `status` の同期の件数（#126） | 要求のたびに `check_sync` をかけず、裏で実行した検査（`SourceChecks`）の最後の結果を参照する。検査が済んでいない配信元は `sync: null` を返却する | `status` は `check_sync` を呼ばなくなるため、`documents/store.py` は変えない |
| `reload_config` の同期の件数 | `status` と同じ求め方にする | - |
| 性能 | 起動直後の文書の MCP の応答時間と、読み込みの後の `status` の応答時間を修正の前後で計測する | 計測のログを `テスト結果/` に配置する。決定値は非機能要件に記載しない（スコープ外） |
| 再起動の反映作業の待ち（#123） | `dev-docs-server-wait.sh loaded` は、管理の MCP の `status` が `loading: false` を返すまで待つ | `status` は読み込みを待たずに応答するため、1 回の要求を区切って送り直す処理を除く |
| 既存機能への影響 | 待ち受けを先に始める起動の順番（非機能要件『起動から接続を受け付けるまでの時間』）は変えない | - |

## 実装

開発コマンド『開発コマンド』の管理作業の節の 3（`loaded`）を、`status` が `loading: false` を返すまで待つ形に書き換えた。`verification` は `未確認` のまま残した。この実装を入れたサーバーへ走らせるには稼働中のサーバーの再起動が要り、ほかの作業のセッションが使うサーバーを止めるため。
