### #190

| 要件 | 終わりの条件 |
| --- | --- |
| バージョンの受け渡し | 端末の設定の取得（GET `/_api/settings/sources`）が project-index の内容のバージョンを `version` で返却し、端末の設定の保存（PUT `/_api/settings/sources`）が `expectedVersion` を受けて project-index の PUT `/settings/sources` に指定する |
| バージョンの送信 | 設定画面が、取得した `version` を保存の要求に `expectedVersion` として含めて送信する。設定画面は配信元の追加も `sources[]` の丸ごとの保存で行い、1 行の追加の要求（project-index の POST `/settings/sources`）を送信しないため、1 行の追加の終わりの条件も保存の要求で満たす |
| 409 の扱い | project-index が 409 を返却したとき、端末の設定の保存が 409 を返却する。設定画面は 409 を受けると端末の設定を取得し直し、ほかの書き換えが入ったことを利用者に示す |
| outsideRead の表示・変更 | 設定画面が配信元の行の `outsideRead` を表示し、配信元のダイアログで変更して保存できる。保存では project-index の PUT が受け付ける `outside_read` のキーで送信する |

`未確定`: 409 を受けたときの示し方（決める段: モック作成）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 開いているダイアログを閉じずに、ダイアログの中にほかの書き換えが入ったことと取得し直した旨を出し、もう一度保存させる | 入力した値を失わず、取得し直した一覧を確認してから保存し直せる | ダイアログの中の表示が増える |
| B | ダイアログを閉じ、一覧を取得し直して通知（トースト）を出す | 表示が簡単 | 入力した値が失われる |

推奨: A

409 は利用者の入力に誤りが無くても起きるため、入力をやり直させないほうがよい。

### #201

| 要件 | 終わりの条件 |
| --- | --- |
| ER 図 | スキーマ駆動の変換が、`x-diagram: er` の値を Mermaid の `erDiagram` にして `<!-- map -->` の範囲で出し、mdmark の map が操作つきの ER 図として描く |
| 状態遷移図 | スキーマ駆動の変換が、`x-diagram: state` の値を Mermaid の `stateDiagram-v2` にして `<!-- map -->` の範囲で出し、mdmark の map が遷移の再生つきの状態遷移図として描く |
| mdmark のバージョン | 画面が参照する mdmark（`MDMARK_URL`・`MDMARK_CSS_URL`）、結合テストで図を点検する mdmark の CLI（`package.json` の `devDependencies`）、公開ページのビルドが呼ぶ mdmark（`scripts/build_pages.py` の `MDMARK_TAG`）を `v0.13.0` にする |
| 廃止した図の部品からの移行 | mdmark の `v0.13.0` はフロー図の部品（`<!-- flow -->`）とシーケンス図の部品（`<!-- sequence -->`）を廃止し、描かずに書き方の警告にする。dev-docs がこの 2 つで出している図（`x-diagram` の `flowchart`・`dataflow`・`architecture` と、手で書く Mermaid の `flowchart`・`sequenceDiagram`）も `<!-- map -->` の範囲で出し、`v0.13.0` で書き方の警告にならない |

廃止した図の部品からの移行は #201 の本文に無いが、`v0.13.0` へ上げると今の図が描かれなくなるため、mdmark のバージョンを上げるこの作業に含める。
