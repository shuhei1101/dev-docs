# 作業範囲の外の配信元への参照で、1 回の要求の中の ref の解決とスキーマの読み込みを 1 回にし、大きい配信元でも時間切れにならないようにする

## 概要

エージェントが作業範囲の外の大きい配信元を `search_docs` などで参照しても、MCP の呼び出しが時間切れにならずに結果を受け取れるようにする。

## 背景

[#119](https://github.com/shuhei1101/dev-docs/issues/119) の不具合。
作業範囲の外の配信元は `default_ref` を `ref` にして参照するため、検索の点検が文書ごとに `row_schema` → `schema` → `read_root` → `resolve_ref` を通り、1 回の要求の中で git を文書の数の 2 倍起動する。
配信元 `ai-monitor`（1,467 文書）への `search_docs` は 53.8〜85.3 秒かかり、全プロジェクトのエージェントがほかのリポジトリの文書を参照するたびに時間切れになっている。
ユーザーの判断（[#1 の回答](https://github.com/shuhei1101/dev-docs/issues/1#issuecomment-6709429931)）で最優先にし、同じ `store.py` の `schema` を変える [PR #101](https://github.com/shuhei1101/dev-docs/pull/101) のマージを待たずに進める。
