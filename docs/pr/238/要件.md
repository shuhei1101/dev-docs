# 要件

## 要望

| 要件 | 終わりの条件 |
| --- | --- |
| 変換の表のマーカーの移行 | 変換（`render_table`・`render_attributes`・`_Builder.test_files`）が出す表のマーカーを mdmark の JSON の引数の記載（`<!-- table: {JSON のオブジェクト} -->`）で出し、変換した文書を `mdmark check` にかけた結果に `legacy_mark` が出ない |
| 表のキーの取り出しの追従 | 変換の後に表のキーのマーカーを取り除く処理（`service.py` の `_strip_table_keys`）が、JSON の記載の表のマーカーを挟んでも、表のキーのマーカーの値を表のキーにする |
| 画面の列の表示の追従 | 画面の列の表示の保存先の決め方（`tables.ts` の `findTables`・`columnTableKeys`）と、保存した隠す列の書き込み（`applyHiddenColumns`）が、JSON の記載の表のマーカーで今と同じに動く。前の記載方法のマーカー（`docs/` の Markdown の移行は #193）でも今の動きを保つ |
| 結合テストの期待値 | `tests/integration/server/test_get_document.py` の `test_normal_when_diagrams_checked` と IF-155-10 の期待値を、`mdmark check` のずれが 0 件に戻す |

前の記載方法から JSON への対応は、mdmark `v0.13.0` の [ER-477-2](https://github.com/shuhei1101/mdmark/blob/v0.13.0/docs/er/ER-477-2.yaml) の「今の引数との対応」に従う（`closed` → `collapse.open` の `false`、`+columns hide=列名` → `columns.{列名}.hidden` の `true`、`wide=列名` → `columns.{列名}.width.mode` の `"nowrap"`）。

## 変更箇所の由来

| 対象箇所 | commit | 目的 | 変更回数 | 影響 |
| --- | --- | --- | --- | --- |
| `service.py` の `TABLE_DATA_MARKER`（表のキーのマーカーの後に、`<!-- table: data -->` の行だけを挟めるようにする判定） | [60ef5ca](https://github.com/shuhei1101/dev-docs/commit/60ef5ca)（`汎用の開発ドキュメントサーバー（文書の MCP・設定・検査・変換と画面の API）を作る (#12)`） | 変換が出す表のマーカーが `<!-- table: data -->` だけだった時点で、表のキーのマーカーと表の間のマーカーを読み飛ばすために置いた | 1 回 | 後の [80f8fa2](https://github.com/shuhei1101/dev-docs/commit/80f8fa2)（#90）で `closed`・`+columns hide=`・`wide=` を足したマーカーは一致しないため、図の元データの表などは表のキーのマーカーの値ではなく `{種類}:table[{番号}]` が表のキーになっている。表のマーカーの行全体を読み飛ばす判定へ変えるのは、この目的を壊さない。図の元データの表の表のキーが変わるため、その表で保存済みの列の表示は引き継がれない |
| `markdown.py` の `render_table` の表のマーカーの引数（`closed`・`+columns hide=`・`wide=`） | [80f8fa2](https://github.com/shuhei1101/dev-docs/commit/80f8fa2)（`汎用の描画を表し方の規約に沿って修正する（図を mdmark の部品で描く・キーの羅列を表にする・コードブロックのずれ） (#90)`） | 図の元データの表を閉じて ID の列を隠し、説明の列を折り返さずに出すため、当時の mdmark の記法で引数を足した。空白を含む列名は、空白区切りの引数に書けないため除いた | 1 回 | JSON の記載へ移しても同じ表示を保つ。JSON では列名に空白を書けるため、空白を含む列名を除く理由は無くなる |
