# 要件

## 要望

AI Monitor の配布物を v0.4.0 から v0.5.0 へ追従する。
完了の条件は次のとおり。

- `ai-monitor-version.ini` の先頭行が `v0.5.0` になっている
- 直下の `mdmark.config.yaml` の `map.kinds` に AI Monitor の図のノードの種類（`external`・`script`・`data`・`start`・`question`・`action`・`result`）が、`map.lines` に線の種類（`-.->`・`==>`）が、反映作業『配布先の mdmark の設定へのノードの種類の記載』の `common.py` の `KINDS`・`LINES` と同じ値で記載されている（確認スクリプトが通る）
- v0.4.0..v0.5.0 で変わった規約・判定フローチャート・チェックシート・テンプレートのうち、dev-docs の成果物が従っていない箇所が無い（改めて参照して見つけた箇所は、この PR で修正するかスコープ外へ回す）
- `反映作業/index.yaml` の配布先の反映作業が全て済になっている

v0.4.0..v0.5.0 で変わった配布物と、dev-docs への適用は次のとおり。

| 変わった配布物 | 変更 | dev-docs への適用 |
| --- | --- | --- |
| 規約『ドキュメント管理』 | 表の種類・タブ・見出しの開閉のマーカーの引数を JSON のオブジェクトで記載する（`<!-- table: {"kind": "data"} -->`・`<!-- tabs: {"group": "os"} -->`・`<!-- section: {"open": false} -->`） | develop の `docs/` の Markdown と YAML の本文は既に JSON の記載方法で、修正する箇所は無い。旧記載方法はモック HTML（`docs/mock/pages/doc-view/56/`）だけに残る |
| 規約『フェーズ索引の網羅』 | 依存先待ちの待機を `wait_for_issues` で行う | エージェントの動きの変更で、dev-docs の成果物に該当する箇所は無い |
| テンプレート『PRドキュメント/対象システムの計画書』・チェックシート『レビュー観点 実装・テストコード』 | 結合テストの実行範囲を判定フローチャートで決め、計画書の `### 結合テストの実行範囲` の表にする | 以後の作業 PR の計画書が対象で、既存の成果物に修正する箇所は無い |
| 他の規約・テンプレート・チェックシート | 表のマーカーを JSON の記載方法へ書き換えただけ | 適用する箇所は無い |
| 配布先の反映作業 | 直下の `mdmark.config.yaml` の `map.kinds`・`map.lines` への図の種類の記載 | 配布元のスクリプトを `反映作業/配布先の mdmark の設定へのノードの種類の記載/` へコピーし、この PR のマージの前に実行する |

直下の `mdmark.config.yaml` は今の develop に無いため、反映作業の実行スクリプトが新規に作る。
公開ページのビルド（`scripts/build_pages.py`）が作る `mdmark.config.yaml` は一時フォルダの中のファイルで、直下のファイルとは重ならない。
