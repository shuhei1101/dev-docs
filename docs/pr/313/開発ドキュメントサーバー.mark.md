## 変更方針

<!-- table: {"kind": "data"} -->

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 閲覧機能 | 配信元のメタデータの種類ごとの一覧を返却する画面の API を加える。値は project-index の読み取り API（文書の一覧の `values`・`common_keys`、配信元の設定）から組み立て、dev-docs は配信元のファイルを直接読まない | rule-inject の索引の経路は要件の `未確定` に従う |
| 一括操作 | 画面が編集中の変更を配信元ごとに受け、project-index の書き込みの API へ `writes`・`deletes`・`message`（と差分確認のときの `dryRun`）を 1 回で送信する画面の API を加える | 1 回の送信が 1 つのコミットになる |
| エラー返却 | 書き込みの API の 403・409・422・502・504 を、画面が修正ごとに理由を出せる problem+json にして返却する | 状態コードごとの扱いはインターフェース定義設計で決める |
| 権限・認可 | 直コミットを許可する種類を、配信元の設定の `direct_commit.kinds[]` と project-index の端末の設定の `sources[].direct_commit.write_api_kinds` から返却する | 許可の判定そのものは project-index が持つ |
| 外部 API 制約 | 書き込みの API の待ちは、非機能要件の project-index への問い合わせの制限時間と、IF-38 の書き込みの期限から決める | 値は非機能要件と資源の値の決め方で導く |
