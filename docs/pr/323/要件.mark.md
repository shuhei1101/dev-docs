# 要件

## 要望

| 子 Issue | 終わりの条件 |
| --- | --- |
| [#321](https://github.com/shuhei1101/dev-docs/issues/321) | 本文の直コミットを断る種類（project-index の読み取り API の `GET /sources/{source}/config` の `directCommit.metadataOnlyKinds`）の文書について、メタデータの画面が本文（`@body`）の編集を出さない・無効にするなど、送信すると書き込みの API が 422 で断る操作を利用者がしないで済む表示になっている |
| [#318](https://github.com/shuhei1101/dev-docs/issues/318) | `documents[].search_exclude` に該当する文書（読み取り API の文書の一覧の `excluded`）を、画面のサイドバー・一覧で薄く表示するか隠し、画面の検索で該当する文書を探す手段（`include_excluded=true`）を持たせるかを画面設計で決めて実装している |

要件として次を満たす。

- 文書の取得のサイドバーの項目は、文書の一覧の `excluded` を持ち、画面は該当する項目を見分けられる表示にする
- 画面の検索は、既定では検索から除外される文書を除き、除いた件数を表示する。利用者の操作で除外される文書も含めて検索できる

`未確定`: #321 の扱い（決める工程: 承認確認。要件を変えるため利用者が決める）

今のメタデータの画面には、本文の直コミットを断る種類で書き込みの API が 422 で断る操作が無い。

- 本文の直コミットを断る（`direct_commit.kinds[].body: false`）のは `body_file` の本文のファイルだけで、`records` と `body_file` を持つ種類（管理用の YAML の `files` のタブ）にだけ効く。dev-docs・knowledge・rule-inject の `project-index.yaml` で `body: false` を付けた種類も、全てこの種類
- `files` のタブで修正できるのは概要（`description`）だけで、行の追加・削除はできない（[IF-155-28](https://docs.shuhdev.com/dev-docs/docs/interface/IF-155-28.yaml?rev=develop) の `canAdd`・`canDelete`、[IF-155-29](https://docs.shuhdev.com/dev-docs/docs/interface/IF-155-29.yaml?rev=develop) の制約「修正できるキー」）。タグのタブの修正もメタデータだけを書き換える
- 行の追加・削除ができる `terms`・`rules` は `body_file` を持たない

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | #321 は今の画面で達成済みとして、この作業 PR の要件から外し、#321 を達成済みで閉じる | 無い操作のための作業を作らない | 本文のファイルを書き換える操作を後で画面に足すときに、改めて対応が要る |
| B | 配信元の設定のタブの直コミットの列で、本文の直コミットを断る種類を「メタデータだけ」と表示し、サーバーは本文のファイルが変わる変更を送信の前に断る | 断る種類が画面で分かり、後で操作を足しても 422 を送らない | 今は起きない 422 のための表示と検査が増える |

推奨: A

#321 の終了の条件は「送信すると 422 で断る操作を利用者がしないで済む」で、今の画面はその操作を持たないため。

`未確定`: 検索から除外される文書のサイドバーでの表示（決める工程: モック作成）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 薄く表示する | 文書を開く手段を残したまま、除外されることが分かる | サイドバーの項目は減らない |
| B | 隠し、表示を切り替える操作を持たせる | サイドバーが短くなる | 切り替えの操作が増え、隠れた文書に気づきにくい |

推奨: A

除外は検索の結果を絞るための設定で、文書を参照できなくすることは求められていないため。
