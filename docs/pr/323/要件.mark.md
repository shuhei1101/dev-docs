# 要件

## 要望

| 子 Issue | 終わりの条件 |
| --- | --- |
| [#321](https://github.com/shuhei1101/dev-docs/issues/321) | 本文の直コミットを断る種類（project-index の読み取り API の `GET /sources/{source}/config` の `directCommit.metadataOnlyKinds`）の文書について、メタデータの画面が本文（`@body`）の編集を出さない・無効にするなど、送信すると書き込みの API が 422 で断る操作を利用者がしないで済む表示になっている |
| [#318](https://github.com/shuhei1101/dev-docs/issues/318) | `documents[].search_exclude` に該当する文書（読み取り API の文書の一覧の `excluded`）を、画面のサイドバー・一覧で薄く表示するか隠し、画面の検索で該当する文書を探す手段（`include_excluded=true`）を持たせるかを画面設計で決めて実装している |

要件として次を満たす。

- メタデータの取得は、行の文書の種類が `metadataOnlyKinds` にあれば、本文の列を直コミットできない列として返却する。メタデータの列は今までどおり `writeApiKinds` で決める
- メタデータの画面は、本文の直コミットを断る種類の行で本文を編集する操作を受け付けず、編集できない理由を表示する。編集中の変更の直コミットに本文の変更が含まれる要求は送信しない
- 文書の取得のサイドバーの項目は、文書の一覧の `excluded` を持ち、画面は該当する項目を見分けられる表示にする
- 画面の検索は、既定では検索から除外される文書を除き、除いた件数を表示する。利用者の操作で除外される文書も含めて検索できる

`未確定`: 本文の直コミットを断る種類の本文の表示（決める工程: モック作成）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 本文のセルを表示し、編集を無効にして理由をツールチップで出す | 本文を参照できて、編集できない理由が分かる | 無効のセルが並ぶ |
| B | 本文の列を出さない | 表が短くなる | 本文を表で参照できず、なぜ無いかが分からない |

推奨: A

本文の値は参照できたほうが行の確認に役立ち、編集できない理由がその場で分かるため。

`未確定`: 検索から除外される文書のサイドバーでの表示（決める工程: モック作成）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 薄く表示する | 文書を開く手段を残したまま、除外されることが分かる | サイドバーの項目は減らない |
| B | 隠し、表示を切り替える操作を持たせる | サイドバーが短くなる | 切り替えの操作が増え、隠れた文書に気づきにくい |

推奨: A

除外は検索の結果を絞るための設定で、文書を参照できなくすることは求められていないため。

`未確定`: 画面の検索で除外される文書を探す操作（決める工程: モック作成）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 検索のダイアログに除外した件数と「除外した文書も含める」の切り替えを出す | 除外した文書があることと探す手段が結果と同じ場所で分かる | ダイアログの UI 項目が増える |
| B | 検索の操作を持たせず、除外した件数だけを表示する | UI 項目が増えない | 除外した文書を検索で探せない |

推奨: A

#318 が検索で該当する文書を探す手段を持たせるかを問うており、件数だけでは探せないため。
