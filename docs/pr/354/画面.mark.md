### 機能の突き合わせ

今の部品の機能を、[表をカスタム要素で描く](https://docs.shuhdev.com/mdmark/docs/interface/IF-793-1.yaml?rev=develop) と [部品をカスタム要素で使用する](https://docs.shuhdev.com/mdmark/docs/カスタマイズ-部品をカスタム要素で使用する.mark.md?rev=develop) の指定・イベントと突き合わせた結果。

<!-- table: {"kind": "data"} -->

| 箇所 | 今の機能 | カスタム要素での扱い | 保てるか |
| --- | --- | --- | --- |
| メタデータの種類の表 | 行ごとの編集の可否（直コミットを許可していない行・削除予定の行は編集できない） | `columns[].editable` は列の単位で、行の単位の指定が無い | 保てない |
| メタデータの種類の表 | 行の要素の id（レビュー中のパネルの行を押すと表の行へ移る） | 行に id・属性を付ける指定が無い。先頭の列の `render` が返却する要素に id を付ければその要素へは移れるが、移る先が行でなくセルの中の要素になり、`<mdmark-table>` が持つ行のフォーカス（↑↓で移る行）と一致しない | 保てない |
| メタデータの種類の表 | 削除予定の行の取り消し線・半透明 | 行に class を付ける指定が無い。全ての列の `render` が `row.key` で削除予定かを見て、セルの中身に class を付ければ描ける | 保てる（`render` で代わりに描く） |
| メタデータの種類の表 | 未コミットのセルの背景 | セルに class を付ける指定が無い。`render` の要素はセルの余白まで塗れず、セル全体の背景は描けない | 保てない |
| メタデータの種類の表 | 行追加の入力行（ID と列の入力・ID の入力チェックとエラーの表示・キャンセル） | `mdmark-row-add` は押したことの通知だけで、行のキー（ID）は編集できる列にならない | 保てない |
| メタデータの種類の表 | 行の中の編集（Enter・フォーカスの移動で確定、Esc で取り消し） | `columns[].editable` と `mdmark-cell-edit`（`preventDefault` で戻す） | 保てる |
| メタデータの種類の表 | 削除・元に戻すのボタン、文書の列の文書の画面へのリンク | `columns[].render` が返却した要素 | 保てる |
| メタデータの種類の表 | 画面の検索欄での絞り込み・空の表と一致なしの案内 | 画面が `rows` を絞って指定し、案内は表の外に出す | 保てる |
| 配信元の一覧の表 | 配信元の画面へのリンク・範囲の外から参照できない旨・設定ファイルの並び・状態のバッジ・編集と削除のボタン | `columns[].render` が返却した要素（行のキーは行の位置） | 保てる |
| YAML の項目の表のセル | 全てのセルが入力欄で、入力するたびに編集中の変更に入る | `columns[].editable` のセルを押して入力欄にし、確定したときに `mdmark-cell-edit` で入れる | 保てる（入力の始め方と変更に入る時点が変わる） |
| コメントのパネル | 文書をまたいだ溜めたコメントの一覧・選択・コメントの箇所への移動・修正・削除・コピー・Issue の起票 | `<mdmark-comments>` は要素の中の本文へコメントを付ける要素で、一覧・選択・コピー・起票を持たない。本文へのコメントは既に `mount` の機能 `comments` で付けている | 保てない |

### 置き換えで機能が保てない箇所の論点

`未確定`: メタデータの種類の表の置き換え方（決める段: 部品設計の前に利用者へ確認する）

保てない 4 つの機能（行ごとの編集の可否・行の要素の id・未コミットのセルの背景・行追加の入力行）は、`<mdmark-table>` の指定・イベントを増やさないと保てない。
mdmark（別のリポジトリ）の変更が要るため、規約『複数リポジトリのAPI契約』のとおり、契約を mdmark 側に配置し、この PR はモックで先に作る。

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | mdmark へ、行の単位の指定（行の編集の可否・行の要素の属性・行とセルの class）と、行追加で行のキーを入力して検査する機能の入出力を記載した提供する側の Issue を起票する。この PR は、その入出力に沿ったモックと付け替えのインターフェースで `metadata-table.tsx` を置き換え、本物の mdmark につなぐ作業は dev-docs に起票した Issue で行う | 失われる機能が無い。この PR が mdmark の公開を待たない | mdmark に追加する指定の入出力を先に決める手間がかかる |
| B | 4 つの機能を失うことを受け入れて置き換える | mdmark の変更が要らない | レビュー中のパネルから行へ移れない・参照のみの行を編集できてしまうなど、今の操作が壊れる |
| C | メタデータの種類の表は置き換えの対象から除外する | mdmark の変更が要らない | knowledge の規約『共通コンポーネント規約』の決まりから外れた表が残る |

推奨: A

起点 Issue #348 の注意事項が mdmark 側に機能を追加して置き換える流れを前提にしており、planner『設計』も別のリポジトリの変更が要るときはモックを前提に続けると決めているため。

`未確定`: コメントのパネルの扱い（決める段: 部品設計の前に利用者へ確認する）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 置き換えの対象から除外し、溜めたコメントの一覧として残す（本文へのコメントは既に mdmark の機能 `comments` で付けている） | 今の機能を全て保てる。mdmark の変更が要らない | 起点 Issue #348 が挙げた候補の 1 つを置き換えない |
| B | mdmark へコメントの一覧の部品の入出力を記載した提供する側の Issue を起票し、この PR はモックでコメントのパネルを置き換え、本物につなぐ作業は dev-docs に起票した Issue で行う | コメントの表示が全て mdmark にそろう | 一覧・選択・コピー・起票は dev-docs 固有の操作で、汎用の部品にする範囲を新規に決める必要がある |

推奨: A

knowledge の規約『共通コンポーネント規約』の対応表で `<mdmark-comments>` の対象は本文へのコメントで、本文は既に mdmark で付けているため。
