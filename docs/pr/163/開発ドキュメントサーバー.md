## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 機能の分け方 | 文書の MCP・配信元の読み込みと検査・変換・書き込み・管理の MCP のうち配信元を扱うツールを project-index へ移し、開発ドキュメントサーバーには画面の配信・画面の API・設定画面の API を残す | 移す・残すの境界はインターフェース定義設計で 1 件ずつ決める |
| 画面の API | 文書・検索・リビジョン・表の列の取得を、project-index の API を呼び出す構造に付け替える。画面に返却するスキーマは変えない | project-index の API はインターフェース定義設計で決める |
| 配信元の一覧 | `sources[]` を project-index が持ち、設定画面は project-index の端末の設定の API で参照・更新する | [要件](./要件.md) |
| 既定のファイル名 | 雛形・設計書・使い方の例・`CONFIG_FILE` を `project-index.yaml`・`project-index.local.yaml` にする | 今の `dev-docs.yaml` の移行は `未確定`（[要件](./要件.md)） |
| #119 の修正 | ref の解決とスキーマの読み込みを 1 回の要求の中で繰り返さない処理と、所要時間を確認するテストを dev-docs から除外する | 移行と、#119 の 3 つの要求での所要時間の測り直しは [project-index#14](https://github.com/shuhei1101/project-index/issues/14) で行い、この計画書のテスト結果に project-index#14 の PR の記録へのリンクを記載する |
| 依存 | 移す機能だけが使用する依存を `pyproject.toml` から除外する | 入れ方・起動に影響するため、`dev-docsを入れる`（SC-155-2）を影響するユースケースに挙げた |
| 既存機能への影響 | 文書の MCP を dev-docs から除外するため、今の端末の Claude Code の MCP の接続先を project-index へ付け替える反映作業が要る | 反映作業は設計で接続先と手順を決めてから記載する |
