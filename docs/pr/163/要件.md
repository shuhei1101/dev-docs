# 要件

## 要望

文書とソースコードの索引・検索・書き込みの MCP と配信元の読み込みを project-index へ移し、dev-docs をそれを使用する画面のサーバーにする。
配信元の設定の既定のファイル名を `project-index.yaml`・`project-index.local.yaml` にする。

| 要件 | 終わりの条件 |
| --- | --- |
| 索引・検索・書き込みの MCP の切り出し | 文書の MCP（`describe`・`search_docs`・`trace_related`・`list_changes`・`list_match_words`・`write_docs`・`delete_docs`）と、配信元の読み込み・検査・変換が dev-docs から除外されている。project-index 側の提供は [project-index#14](https://github.com/shuhei1101/project-index/issues/14) が担い、dev-docs を入れずに project-index だけを入れた端末で文書の MCP を使用できる |
| 画面のサーバーの付け替え | dev-docs の画面のサーバーが、配信元の文書・検索・リビジョンを project-index の読み取り API から付け替え口で取得し、今と同じ画面を表示する。この作業 PR は project-index#14 に記載した入出力に沿ったモックで確認し、本物へつなぐ作業は [#164](https://github.com/shuhei1101/dev-docs/issues/164) が担う |
| 配信元の一覧の共有 | 端末の設定の `sources[]` を dev-docs と project-index の両方が同じ内容で参照する。設定画面で配信元を追加・停止・削除すると、project-index にも反映される |
| 既定のファイル名 | dev-docs の雛形・設計書・使い方の例の既定のファイル名が `project-index.yaml`・`project-index.local.yaml` になっている。名前で探す処理（`CONFIG_FILE`）は project-index へ移し、名前と移行方法は project-index#14 で決める |
| #119 の修正の引き継ぎ | #119 の修正（1 回の要求の中で ref の解決とスキーマの読み込みを繰り返さない）と、その所要時間を確認するテストを、処理と一緒に移行している。移行と、#119 の本文の表と同じ 3 つの要求（配信元 `ai-monitor` への name の絞り込み・`view: count`・body の正規表現）での所要時間の測り直しは、処理を受け入れる project-index#14 で行う。この PR には project-index#14 の PR の記録へのリンクを記載する |

今の各リポジトリの `dev-docs.yaml` の移行方法（移行の間は両方の名前を探すか、改名だけにするか）は、名前で配信元の設定を探す処理（`CONFIG_FILE`・`write_nav`・`check_project`）ごと project-index へ移したため、[project-index#14](https://github.com/shuhei1101/project-index/issues/14) で決める。dev-docs 側で変えるのは、雛形・設計書・使い方の例のファイル名だけにする。

端末の設定の `sources[]` は project-index が持ち、dev-docs の設定画面は project-index の端末の設定の API で参照・更新する。
提供する側の契約（[project-index#14](https://github.com/shuhei1101/project-index/issues/14)）がこの構造で起票されており、配信元の行をバージョンつきで追加・変更・削除する API（[project-index#10](https://github.com/shuhei1101/project-index/issues/10)）も計画されている。

この作業 PR は project-index#14 の入出力に沿ったモックで作り、マージは project-index#14 が project-index の develop に入った後にする。
文書の MCP は AI Monitor のエージェントが毎ターン使用するため、使用できない期間を作らない。
