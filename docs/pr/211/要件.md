# 要件

## 要望

- 画面のサーバーの付け替え口は、文書の一覧を `common_keys=true` で呼び、各文書の `metadata` を、一覧のメタデータ（`id`・`kind`・`name`・`description`・`tags`・`visibility`）に `documents[].commonKeys` を重ねたものにする
- 文書の取得は、`metadata` を一覧のメタデータに `metadata.commonKeys` を重ねたものにする
- 共通のキーを自前で組み立てる処理（`features/documents/fields.py` の `with_row_metadata` と、それを呼ぶ `features/view/document.py` の 2 か所）を削除する
- 画面の API の入出力と、画面に出る共通のキーの値は変えない
- 端末で動いている project-index（127.0.0.1:8786）は、2026-11-14 時点で文書の一覧の `common_keys=true` に `commonKeys` を返している。反映作業では、dev-docs のサーバーを起動し直す前に、`commonKeys` が返ることを疎通確認で確かめる

`未確定`: 絞り込みが共通のキーかを決める `METADATA_KEYS`（`features/filter/fields.py` の項目の値・使える項目）の扱い（決める段: モジュール構成設計）

| 案 | 内容 |
| --- | --- |
| A | `METADATA_KEYS` を残し、絞り込みの共通のキーの名前の一覧として使い続ける |
| B | `METADATA_KEYS` を削除し、文書の `metadata` にあるキーを共通のキーとして扱う |

推奨: B

A は project-index だけで共通のキーが増えたときに、そのキーの絞り込みが `metadata` ではなく文書の値を見て食い違いが残るため。
