## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| タブ「設計書」の `モジュール構成 / …` の 3 グループ | `group: モジュール構成` の子の `group` にし、子の名前から `モジュール構成 / ` を除く | `auto` の `filter` は今のまま |
| タブ「コード」の `テスト / …` の 2 グループ | `group: テスト` の子の `group` にし、子の名前から `テスト / ` を除く | `auto` の `filter` は今のまま |
| 他のグループ | 判定フローチャート『サイドバーのグループの分け方』で分けるかと軸を判定し、分けるものは 2 階層まで入れ子にする | 判定の結果は『ドキュメント修正』で `## 実装` に記載する |
| 確認 | 修正した後の作業ブランチを dev-docs の画面で開き、各タブのサイドバーをスクリーンショットで撮る | 修正前と同じ文書がサイドバーに全て並ぶこと |

## 実装

| 項目 | 内容 |
| --- | --- |
| 判定フローチャートで分けると判定したグループ | タブ「コード」の `サーバー`（68 件）・`画面`（133 件）・`テスト`（164 件）。主題のタグを持たず（Q1 NO）、機能を表す項目も無い（Q2 NO）。管理用の YAML の行は `@folder` でグループ化されない（Q3）ため、フォルダの接頭辞の `filter` で、モジュール構成の機能の名前（`画面のAPI`・`変換`・`文書の画面` など）のグループに分けた |
| 分けないと判定したグループ | `インターフェース定義`（主題のタグが全て別の値で Q1 NO・機能を表す項目が無く Q2 NO）・`外部 API・外部ライブラリ`（同じ）・`シナリオ`・`画面設計`・`部品設計`・`モック`（件数が少なく、分けると 1 件ずつのグループになる） |
| 漏れの確認 | `src`・`frontend`・`tests` の管理用の YAML の全ての行が、ちょうど 1 つのグループに当たることを `filter` の照合で確認した（68・133・164 件） |
| 撮った画面の場面 | 作業ブランチの worktree の `project-index.yaml` を `storage.type: disk` で配信した一時の project-index と dev-docs の画面で撮影した。`設計書` タブの一番上と `モジュール構成 > 画面`（`1280x800`・`768x1024`）、`コード` タブの `サーバー` の機能のグループ・`テスト` の層のグループ（`1280x800`） |
| 撮った画面で確認したこと | タブは 7 件で規約の順のまま。入れ子は 2 階層まで。目次（`kind: index`）・内部のファイルは出ていない。パンくずに外側のグループが出ない不具合を見つけ、#349 で起票した |
