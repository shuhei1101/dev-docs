### タブとサイドバー（#229）

規約『開発ドキュメントのナビゲーション』に従い、`nav.tabs[]` を次の順で定義する。配信元に無いタブは置かない。

| 順 | タブ | 入れる文書 | サイドバーのグループ |
| --- | --- | --- | --- |
| 1 | はじめに | `docs/guide/` の `category: はじめに` | - |
| 2 | 使い方 | `docs/guide/` の `category: 使用方法` | - |
| 3 | 設計書 | 設計書の種類の行（アーキテクチャ図・非機能要件・シナリオ・インターフェース定義・モジュール構成・画面設計・部品設計・設定・外部API・外部ライブラリ・テスト実行方法・開発コマンド）・デザイン方針・モック | 種類（`group_by: kind` か種類ごとの `group`） |
| 4 | 規約 | 判定フローチャート | - |
| 5 | コード | `src/`・`frontend/`・`tests/`・直下の管理用の YAML の行とプロンプトの行 | サブシステム・テストの層・リポジトリの設定・プロンプト |
| 6 | リファレンス | `docs/guide/` の `category: リファレンス`（用語集を除く） | MCP とコマンド・設定 |
| 7 | 用語集 | `docs/guide/用語集.md` | - |

- 目次（`index` の行）はどのタブにも置かない。`auto` は目次を含まない行だけを `document` で指すため、`filter` の `not`（`kind` が `index`）は記載しない
- 読む人が参照しない内部のファイル（`docs/pr/`・ロックファイル・スクリーンショットなど）はタブとサイドバーに並べない

モジュール構成（149 件）は、名前の 1 段目（サブシステム）の前方一致の `filter` で「画面」「開発ドキュメントサーバー」「管理用プラグイン・開発用のスクリプト」のグループに分ける。
`auto.group_by` で共通のメタデータを指定する [#251](https://github.com/shuhei1101/dev-docs/issues/251) を待たずに書け、サブシステムが増えたときだけグループを追加する。

### 検索の対象とメタデータ（#257）

- 配信元のフォルダで `/project-index:setup` をもう一度実行し、Git 管理のファイルを推奨の範囲（`**/*`）で対象に入れる。管理用の YAML は直下の `files.yaml`（行 `root`）と `src/`・`frontend/`・`tests/` の `files.yaml` に置き、`docs/_root/files.yml` は直下の `files.yaml` へまとめて削除する
- 生成物（`src/dev_docs/screen/` の画面のビルド・`frontend/src/shared/api/generated/`・`route-tree.gen.ts`・`mockServiceWorker.js`）・ロックファイル・`index.yaml` から生成する `docs/**/README.md` は行の `exclude` で対象から外す
- `docs/pr/` は検索の対象に入れない（project-index 自身の見直し [shuhei1101/project-index#132](https://github.com/shuhei1101/project-index/pull/132) と同じ）
- `content/prompts/` は setup が書くプロンプトの行の文書として配信する。スキーマは setup の手順のコピー（`schemas/prompt.schema.yaml`）を作らず、プロンプトの YAML が既に指す `templates/prompt.schema.yaml` を指す
- コードの行に設計書への `implements`、テストの行にコードへの `tests` を記載する（向きは project-index の `schemas/files.schema.yaml`）
- 終わりの条件は、`check_project` の索引の同期の件数（管理用の YAML に無いファイル・ファイルが無い行・`metadata` の列が無い文書）が 0 で、設計書から `trace_related`（`direction: in`）で実装とテストをたどれること
