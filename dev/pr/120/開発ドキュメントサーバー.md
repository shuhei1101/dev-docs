## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 性能（ref の解決） | 1 回の要求の中では、読む場所ごとに `ref` を commit へ 1 回だけ解決し、`read_root`・`schema`・`_file_dates` は解決した commit を使用する。git の起動の回数を文書の数に比例させない | `Target.commit` に持たせ、『読む場所の解決』と画面の読む場所が作るときに解く |
| 性能（スキーマ） | `ref` を持つ読む場所のスキーマのキャッシュは、書き出したリビジョンのファイルの `stat` ではなく、commit と種類で検索する | [PR #101](https://github.com/shuhei1101/dev-docs/pull/101) が同じ `schema` を変えるため、後にマージする側で競合を解消する |
| 既存機能への影響 | ブランチ名の `ref` は要求ごとに解決し直し、`default_ref` に入った新しい commit は次の要求から有効にする。作業範囲の中の読む場所（`ref` が無い）とワークツリーの読む場所の結果は変えない | - |
| 性能（計測） | 修正の後に、配信元 `ai-monitor` への 3 つの要求（要件.md の表）の時間を直接 HTTP で測り、`## テスト結果` に記録する | 非機能要件には記載しない（要件.md の設計で決めた内容） |
