### #48 プロンプトの YAML への移し替え

| 要件 | 終わりの条件 |
| --- | --- |
| SessionStart の注入文 | `POST /_admin/session-context` の `context` を、プロンプトの YAML（`kind: hook`）を描画して作る。中身は使える配信元（ID・権限・説明）と警告と、使い分けは文書の MCP の instructions にある旨の 1 行だけにする |
| 注入文の字数 | `context` の上限（`CONTEXT_MAX_CHARS`）を 2,000 字から 1,000 字にする。超えたときの省き方（配信元の説明を省く → 配信元の行を末尾から減らして残りの件数を添える）は今のまま |
| 文書の MCP の instructions | プロンプトの YAML（`kind: instructions`）から読む。使う場面（`search_docs`・`trace_related`・`list_changes`・`write_docs`）と、grep・Read が向く場面を同じくらいの数で持ち、ツール間の順序と、今のタグの付け方の行（[#41](https://github.com/shuhei1101/dev-docs/issues/41) で入った行を含む）を持つ。4,096 字以内 |
| 移す使い方の行 | 今の注入文の使い方の 5 行（`SESSION_USAGE`）とタグの行（`TAG_GUIDE`）は instructions へ移し、注入文には置かない |
| ツールの description | 文書の MCP の 7 つのツールの description をプロンプトの YAML（`kind: tool`）から読む。何をする・いつ使う・いつ使わない・何を返さないを持つ。今の description にある引数の説明（[#40](https://github.com/shuhei1101/dev-docs/issues/40)・[#42](https://github.com/shuhei1101/dev-docs/issues/42)・[#43](https://github.com/shuhei1101/dev-docs/issues/43) で入った行を含む）は削除しない |
| 書き方 | 注入文・instructions・description に MUST・必ず・禁止の言い回しを使わない。書き分けは knowledge の規約『注入文の書き分けと書き方』（`claude-context-placement`）に従う |
| コードの役割 | コードは YAML を読んで描画するだけにし、文をコードに持たない。YAML は `templates/prompt.schema.yaml`（knowledge の `schemas/prompt.schema.yaml` のコピー）で検査する |

プロンプトの YAML はリポジトリ直下の `content/prompts/` に置く（モジュール構成設計で確定。knowledge の規約『プロンプトファイル』の置き場所）。dev-docs はクローンの `.venv` で動かす入れ方（`/dev-docs:global-setup`）だけを持ち、wheel では配らない。

管理の MCP のツールの description も YAML へ移す（インターフェース定義設計で確定）。場面の書き足しは文書の MCP に絞り、管理の MCP は文を移して MUST・必ずが無いことを確かめるだけにする。文をコードに埋め込まない決定（D-190）は MCP を分けていない。

### #64 変換の結果をキャッシュしない指定

| 要件 | 終わりの条件 |
| --- | --- |
| 指定 | `converters[]` の行に任意のキー `cache`（真偽値。既定 `true`）を設ける。`validators[]`・`generators[]` には設けない |
| 指定した行 | `cache: false` の行の変換は、控えがあってもスクリプトを動かして標準出力を返し、控えを書かない |
| 指定しない行 | 今と同じく控えを使う |
| 設定のスキーマ | `schemas/dev-docs.schema.json` と `src/dev_docs/schemas/dev-docs.schema.yaml` の `converters[]` の行に `cache` を設ける |
| 使う側への連絡 | マージの後に shuhei1101/ai-monitor#3107 へ、使えるようになった旨と書き方を伝える |

キャッシュのキーに本文の外のファイルを含める案は採らない（task-reviewer の任意の指摘。含めるファイルの一覧のキーとハッシュの処理が加わる）。
`cache: false` の変換は文書を開くたびに動くので、変換の制限時間（`script_timeout_sec`）に収まるかを使う側（AI Monitor）が確かめる。
