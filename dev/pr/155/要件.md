# 要件

## 要望

dev-docs 自身の文書を `dev/` から移し、この PR のマージの後に `dev/` が残らない状態にする。
構成は [shuhei1101/ai-monitor#3307](https://github.com/shuhei1101/ai-monitor/pull/3307) の置き場所の規則（[モニター.md](https://github.com/shuhei1101/ai-monitor/blob/cc97586e6/dev/pr/3307/%E3%83%A2%E3%83%8B%E3%82%BF%E3%83%BC.md) の `### 種類のフォルダ`・`### 置き場所の規則`）に合わせ、1 回の PR で移す。

| 今 | 移した後 |
| --- | --- |
| `dev/設計書/{種別}/`（YAML の設計書） | `docs/{kind}/{ID}.yaml`。言語の規約を注入する種別（モジュール構成など）は `{ID}.{lang}.yaml` |
| `dev/設計書/デザイン方針.md` | `docs/design-policy.md` |
| `dev/コーディング規約/` | 削除（中身が空の目次だけ） |
| `dev/テンプレート/*.schema.yaml` | `schemas/{kind}.schema.yaml`（`common`・`index` を含む） |
| `dev/mock/`・`dev/pr/` | `docs/mock/`・`docs/pr/` |
| `docs/はじめに/`・`docs/使い方/`・`docs/リファレンス/` | `docs/guide/`（分類はメタデータ `category`。サブフォルダにあったものは `{サブフォルダ}-{ファイル名}`） |
| `dev/index.yaml`・`dev/README.md` | 削除し、行を `docs/index.yaml` へ合わせる |

`{kind}` は ai-monitor#3307 の種類のフォルダの名前を使用する。

| `dev/設計書/` の種別 | `{kind}` |
| --- | --- |
| シナリオ | `scenario` |
| インターフェース定義 | `interface` |
| モジュール構成 | `module` |
| 部品設計 | `component` |
| 画面設計 | `screen` |
| 設定 | `config` |
| ER図 | `er` |
| アーキテクチャ図 | `architecture` |
| 非機能要件 | `nonfunctional` |
| 外部API | `external-api` |
| 外部ライブラリ | `library` |
| 開発コマンド | `dev-command` |
| テスト | `test-procedure` |

満たす条件:

- 作業ブランチの直下の `dev/` は、この PR の PR ドキュメント `dev/pr/155/` だけ
- 種類のフォルダの中にサブフォルダが無い（束のフォルダ `docs/pr/{PR 番号}/`・`docs/mock/{画面}/` と、`_` で始まる Pages の共通レイアウトを除く）
- YAML の設計書が全て `id` を持ち、ファイル名が `{ID}.yaml`（または `{ID}.{lang}.yaml`）
- 設計書どうしの参照が `{ID}#{項目のパス}`（設計書だけを指すときは `{ID}`）で、パスの参照が残っていない
- ai-monitor#3307 の設計書の検証（`python -m ai_monitor.design_docs validate`）が、移す前と比べて誤りを増やさない
- `docs/_config.yml` の `exclude` に、`visibility` が `internal` の種類のフォルダ・文書と `pr/`・`mock/`・`generated/` が載り、Pages の成果物に出ない
- `README.md`・`CLAUDE.md`・アーキテクチャ図の `repository.layout` が移した後の置き場所を指す

`rules.yaml` は `dev/` の置き場所を指す記載を持たない（`rules: []`）ため変えない。

PR ドキュメントは、作業中は `dev/pr/155/` に配置する（ai-monitor の develop のツールが `dev/pr/` を参照するため）。
ai-monitor#3307 がマージされると、その反映作業『open の作業 PR の PR ドキュメントの移動』が `docs/pr/155/` へ移す。
マージは、レビューに合格した後にこのプロジェクトで行う。

設計書の ID は、ai-monitor の変換 `v0.4.0.py`（[shuhei1101/ai-monitor@1e44c6173](https://github.com/shuhei1101/ai-monitor/commit/1e44c6173)）の振り付け（種別の接頭辞と作業 PR の番号の連番。例 `MOD-155-1`）で振る。
[#74](https://github.com/shuhei1101/dev-docs/issues/74) の追従と同じ変換で、ID の構造を ai-monitor と統一するため。

設計書の Schema は、製品の Schema `schemas/dev-docs.schema.json` と同じ `schemas/` に `{kind}.schema.yaml` で並べる。
ai-monitor のツールが `schemas/{kind}.schema.yaml` を参照し、名前は重ならないため。
