# 文書のメタデータの対応づけ（metadata・defaults[]・管理用の YAML）と、文書の MCP の結果への場所と範囲の記載

## 概要

利用者はソースコードなど YAML でない文書も管理用の YAML でタグ・概要文を付けて配信でき、エージェントが文書の MCP で読んだルールは rule-inject で既読になる。

## 背景

束の親 [Issue #19](https://github.com/shuhei1101/dev-docs/issues/19) の要望で、子は [#14](https://github.com/shuhei1101/dev-docs/issues/14) と [#10](https://github.com/shuhei1101/dev-docs/issues/10)。
#14 は [#3](https://github.com/shuhei1101/dev-docs/issues/3) の後の話し合いで決めた文書のメタデータの持ち方（D-160〜D-166）で、`metadata`・`defaults[]`・`records`・`body_file` の読み込みは [PR #12](https://github.com/shuhei1101/dev-docs/pull/12) で入っている。
名前の既定・管理用の YAML のスキーマ・同期と `ref` の列の欠けの件数がまだ無い。
#10 は、rule-inject が文書の MCP の結果に載った場所と範囲で既読を決める（[shuhei1101/rule-inject#46](https://github.com/shuhei1101/rule-inject/issues/46)、D-124）のに合わせる。
今の結果は `<document>` に場所を持たないため、dev-docs で読んだルールを Read で読み直させられる。
