## 変更方針

<!-- table: data -->

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 名前の既定 | メタデータの `name` が空なら、ファイル名から拡張子を除いた名前を入れる。`records` の要素は `body_file` が指すファイルの名前、`body_file` が無ければ文書の `id` | 画面の API・`nav`・関連のたどりは重ねた後の `name` を読む（今の `name or id` の分岐は既定に寄せる） |
| 管理用の YAML のスキーマ | `templates/files.schema.yaml` に `files[]`（`path` 必須、`name`・`description`・`tags`・`related`・`status` 任意）を JSON Schema（Draft 2020-12）で書く | `records: files`・`body_file: path` の行の `schema` に指せる形にする |
| `ref` の列の欠け | `metadata` に明示した `ref` の `field` が文書に無い件数を、documents の行ごとに求める。書いていないキー（既定の `ref`）は数えない | 配信は止めない |
| 管理用の YAML の同期 | `records`・`body_file` の行ごとに、範囲のファイルのうち `files[]` に無い件数を求める | ファイルが無い行は `load` が返す `missing_body_file` の件数を使う。範囲は管理用の YAML のフォルダの配下から、YAML 自身と `SKIP_DIRS` を除いたもの |
| 起動時の検証 | 件数は配信元を受け取って求める関数にし、起動時と読み直しのときはその関数を呼んで 0 件でなければ警告をログに残す（配信元の状態には持たせない） | #4 の `check_project` は呼ばれるたびに同じ関数で求め直す |
| 結果の場所と範囲 | `search_docs`・`trace_related`・`list_changes` の結果の文書ごとに、配信元（ワークツリーを指したときはワークツリー）の直下と文書のパスを結んだ絶対パスと `scope` を載せる。markdown は `<document path="..." scope="...">`、json は各項目の `path`・`scope` | `body_file` のある要素は指したファイルのパス。範囲の決め方は要件の決めたとおり。`ref` を指した呼び出しと `list_changes` で `to` を渡した呼び出しには載せない |
| 返し済みの文書 | 本文・名前・概要文を `（この会話で返し済み）` に替えた文書には `path`・`scope` を載せない | - |
| json の `path` | 計算項目 `@path`（配信元の直下からのパス）とは別に、絶対パスを `path` に出す | メタデータのキー `path`（エイリアスのキー。管理用の YAML では `files[].path` の値が入る）と重ならないように、項目の `id`・`source` と同じ階層（`values` の外）に置く |
