# 要件

## 要望

documents の行の `metadata`・`defaults[]` で揃えたメタデータを文書の MCP・画面の API が使い、ソースコードなど YAML でない文書を管理用の YAML で配信する。
文書の本文を返すツールの結果に、返した文書ごとの場所と範囲を rule-inject の書式で載せる。
仕様の正本は子の Issue の必読の資料（A-25・A-26・A-28・A-36）で、ここでは終わりの条件を並べる。

<!-- table: data -->

| Issue | 終わりの条件 |
| --- | --- |
| [#14](https://github.com/shuhei1101/dev-docs/issues/14) | documents の行の `metadata`（`ref`・`custom`）と `defaults[]` を読み、重ねた後の値を検索・関連のたどり・画面の API が使う。`name` が空ならファイル名（`records` の行は `body_file` が指すファイルの名前、無ければ `id`）を使う。YAML でない文書を管理用の YAML（`files[]`）で配信し、スキーマ `templates/files.schema.yaml` を作る。エイリアスの元の行を `metadata` から読む（トップレベルの `aliases[]` は置かない）。`ref` が指す列の欠けと管理用の YAML の同期の件数を求める処理を起動時の検証に含める（件数を返す `check_project` は #4） |
| [#10](https://github.com/shuhei1101/dev-docs/issues/10) | 文書の本文を返すツールの結果に、返した文書ごとの場所（`documents[].paths` から解決した絶対パス）と範囲を、shuhei1101/rule-inject#46 の載せ方（markdown は `<document path="..." scope="...">`、json は各項目の `path`・`scope`）で載せる。返し済みのマーカーだけを返す文書には載せない |

<!-- /table -->

[#12](https://github.com/shuhei1101/dev-docs/pull/12) で入った次の部分は作り直さず、残りを足す。

- `metadata`（`ref`・`custom`）の解決と `defaults[]` の重ね合わせ（`resolve_metadata`・`apply_defaults`）。エイリアスのキーも `METADATA_KEYS` に入っている
- `records`・`body_file` の読み込みと、`body_file` が指すファイルが無い要素の `missing_body_file`
- 設定のスキーマの `documents[].metadata`・`defaults[]`。トップレベルの `aliases[]` は無い

インターフェース定義設計で次のとおり決めた。

- 結果に載せる範囲（`scope`）: 本文を切らずに返したら `full`、`max_chars_per_field` で切った本文・`snippets`・`body_file` の無い `records` の要素・`list_changes` の差分は `section`、本文を返さない一覧と `trace_related` は `summary`（全文を返したときだけ既読にする D-125 に合わせる）
- `ref`（過去のリビジョン）を指して読んだ文書: `path`・`scope` を載せない（既読は今のルールの本文を読んだことを表す D-126 に合わせる）。`list_changes` で `to` を渡したときも同じ
- 管理用の YAML の同期で比べる範囲: 管理用の YAML のフォルダの配下（下のフォルダを含む）のファイルから、管理用の YAML 自身と `SKIP_DIRS` を除いたもの（A-25 は範囲のキーを持たない）
