## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| バリデーション | スキーマと `validators[]` に通った文書の、`contentMediaType: text/markdown` を持つキーのうち操作の前と値が違うキーの値を `mdmark check --text -` に通し、種類が `diagram_invalid`・`syntax_warning` の行を項目のパス・`mdmark の {種類}（{行} 行目）`・内容の違反にする。1 件でもあれば書き込まない | ほかの種類（`unknown_mark` など）の行では止めない |
| 外部プロセスの呼び出し | `src/dev_docs/integrations/` に mdmark の CLI を呼ぶモジュールを新規作成し、`PATH` の `mdmark` を点検する値ごとに起動する。引数を配列で渡してシェルを通さず、`script_timeout_sec` を超えたら停止する | - |
| エラー返却（点検できないとき） | CLI が無い・制限時間を超えた・`ずれ {件数} 件` の行を出さずに終わったときは点検せずに書き込み、`results[].unchecked` にキーのパスと理由を入れる。1 回の呼び出しの中で CLI が無い・制限時間を超えた後は、残りの値も同じ理由で飛ばす | - |
| エラー返却 | 警告は既存の `ValidationFailedError` の違反として返す（`isError`）。`dry_run` でも返し、`atomic: false` では警告のあった操作の添字で返す | - |
| 既存機能への影響 | Markdown のキーを持たない文書・Markdown のキーを変えない操作は、今と同じ結果と応答時間にする（外部プロセスを起動しない） | - |
| 既存機能への影響（`delete_docs`） | `delete_docs` の参照の除外で書き換える文書は点検しない | 参照の行の除外は Markdown の値を変えないため |
| 性能 | 外部プロセスの制限時間は端末の設定の `script_timeout_sec` を使う | - |
| 外部ライブラリ | mdmark の CLI は npm のレジストリに公開されず、Node 24 以降で動く。外部ライブラリ『mdmark』に CLI の点検と、使うバージョン（mdmark#328 が入った develop 以降）を記載する | - |
