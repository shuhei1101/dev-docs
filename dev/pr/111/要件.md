# 要件

## 要望

`write_docs` の検査で、スキーマで Markdown と宣言したキーの値を mdmark の点検（`mdmark check --text`）に通し、描画時の書き方の警告（`diagram_invalid`・`syntax_warning`）が 1 件でもあれば何も書き込まずに、警告をキーのパスつきの違反として返す。
知らない印（`unknown_mark`。dev-docs が描画の前に展開する `<!-- embed: ... -->` を含む）・図の配置のずれ・見つからないファイルでは書き込みを止めない。

- 違反の内容は、mdmark の描画時の「書き方の警告」と同じ文言にする
- `dry_run: true` でも同じ点検を当て、違反を返す
- `atomic: false` では、警告のあった操作だけを失敗として添字つきで返し、他の操作は書き込む（他の検査の違反と同じ扱い）
- mdmark（Node）を呼ぶ外部プロセスの呼び出しを `src/dev_docs/integrations/` に新設する

設計で決めた内容（インターフェース定義『文書の書き込み』の `constraints`）:

| 論点 | 決めた内容 | 理由 |
| --- | --- | --- |
| Markdown と宣言したキーの見分け方 | JSON Schema の `contentMediaType: text/markdown` を持つ文字列のキー（`$ref`・`properties`・`items` をたどる） | 標準のキーワードで表せるものに独自の `x-` を作らない |
| 点検する値の範囲 | 操作を当てる前と値が違う Markdown のキー（`create` は値を持つ全てのキー） | 既存の文書の警告の修正を、関係の無い書き込みの前提にしない |
| 外部プロセスの起動の単位 | 点検する値ごとに `mdmark check --text -` を起動する | `mdmark check` の `--text`・`--key` は 1 回に 1 つの値だけを受ける。Markdown のキーを変えない操作では起動しない |
| mdmark の CLI が無い・制限時間を超えた・結果を出さずに終わったとき | 点検せずに書き込み、点検できなかったキーと理由を `results[].unchecked` に返す | 点検は書き込みの補助で、mdmark を入れていない端末での書き込みを止めない |
| mdmark の CLI の場所と制限時間 | `PATH` の `mdmark`。制限時間は端末の設定の `script_timeout_sec` | 設定のキーを増やさない。`dev-docs:global-setup` は `PATH` にあるかを確かめ、無ければ入れ方を案内する |

`mdmark check --text` は mdmark の develop にだけあり、v0.9.0 の master には無い。
mdmark の次のリリースが master へ入るまで、`npm install -g github:shuhei1101/mdmark` で入る CLI は `--text` を受けず、`write_docs` は点検できなかった理由を返して書き込む。

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| 配信元のスキーマへの `contentMediaType: text/markdown` の追加（AI Monitor のテンプレート `共通.schema.yaml` の `$defs/markdown`・knowledge の `schemas/` の本文のキー） | 各リポジトリの変更で、この PR で決めた宣言の書き方を前提にする。追加するまで、その配信元の書き込みでは mdmark を呼ばない | [shuhei1101/ai-monitor#3230](https://github.com/shuhei1101/ai-monitor/issues/3230)・[shuhei1101/knowledge#187](https://github.com/shuhei1101/knowledge/issues/187) |
| 既に警告を含む既存の文書の修正 | 要望に含まれない。点検するのは変えたキーの値だけで、既存の警告は変えたキーの書き込みのときにだけ問われる | 予定なし |
| `YAMLを直接編集した` の流れ（エディターで直接編集した YAML）への点検 | `write_docs` を通らない書き込みで、要望に含まれない | 予定なし |
| `write_docs` のツールの説明の結合テスト `test_normal_when_tool_description` の期待値と、インターフェース定義『文書の書き込み』の「ツールの説明」の制約が、#105 の文言の修正（「作成・削除・改名したら」）に追随していない | テストの期待値の誤りで、今回の要望に含まれない（develop でも fail する） | [#113](https://github.com/shuhei1101/dev-docs/issues/113) |
