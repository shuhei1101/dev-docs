## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 関連の種類の既定 | `related_types` の既定を `references`・`depends_on`・`see_also`・`implements`・`tests` にする | 設定で `related.types[]` を書いた配信元はその値のまま |
| 索引に無いファイルの数え方 | `unindexed_files` が、`SKIP_DIRS`・行の `exclude` に加えて除外の条件（生成物・ロック・バイナリ・ベンダーのコード・再エクスポートや空の `__init__`）に当たるファイルを数えない | 見分け方は `features/documents/indexable.py` の `is_excluded_file`（`要件.md` の `## 要望` の決定 A） |
| 辿らないフォルダ | 文書の収集・`unindexed_files`・`dev-docs files` の辿らないフォルダに `.claude/worktrees` を加える | setup の範囲の既定と揃える |
| 除外の条件の判定 | setup と `unindexed_files` が同じ判定を使えるよう、判定を 1 か所に置く。CLI のサブコマンド `dev-docs files` を加え、範囲の glob を受けて除外の条件に当たらないファイルを返す。setup は初回も 2 回目以降もこれを使う | インターフェース定義設計で決めた |
| 被参照の引き方 | `trace_related` のツールの説明に「設計書を起点に `direction: in` で呼び、`via.type` が `implements` の文書が実装のコード」を加える | 新しい引数・条件は加えない |
| 既存機能への影響 | `implements`・`tests` を `related.types[]` に書いていない配信元でも既定で通る。既存の 3 語の検査は変わらない | 索引に無いファイルの件数は除外の条件に当たる分だけ減る |
