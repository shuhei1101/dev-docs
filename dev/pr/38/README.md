# 管理用の YAML の列に入れる値をスキーマに記載し、implements・tests の関連と setup の除外の条件・関連の候補を追加する

## 概要

利用者とエージェントは、管理用の YAML（`files.yaml`）の各列に何を入れるかをスキーマの説明から IDE の補完で読めるようになる。
コードは `implements` で設計書を、テストは `tests` でコードを指せ、`/dev-docs:setup` が除外の条件で行を作って `implements`・`tests` の候補を出す。

## 背景

[Issue #34](https://github.com/shuhei1101/dev-docs/issues/34) の要望。
#32（PR #33）で Markdown・ソースコードのメタデータを管理用の YAML の行に置く形式（D-171）へ切り替えたが、行の各列に何を入れるかの決まりが無く、`related.types[]` の既定は `references`・`depends_on`・`see_also` だけで設計書との対応を書けない。
D-173〜D-177 で 1 行の単位・`description` の観点・関連の種類と向き・載せるファイルの判定・タグの観点を決めた。
setup が行を作ること自体と、漏れを `check_project` が知らせることは #32 で入っており、この PR はその上に除外の条件と関連の候補を加える（[着手の指示](https://github.com/shuhei1101/dev-docs/issues/34#issuecomment-6511055455)）。
