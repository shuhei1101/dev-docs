# 要件

## 要望

`dev/設計書/モジュール構成/開発ドキュメントサーバー/` の直下で機能名（`文書のストア.py.yaml` など）で並ぶ設計書を、テンプレート『モジュール構成』に合わせて置き直す。

- 要素の `container` が 2 種類以上ある 17 件を、`container` ごとの設計書（計 80 件）に分ける
- `container` が 1 種類の `スクリプトの実行.py.yaml` も、同じ置き場所の決まりへ移す
- `入口.py.yaml` は、`container` をコードの物理ファイルに合わせ（`DIST_NAME` は `__main__.py` ではなく `__init__.py`）、`__init__.py.yaml`・`__main__.py.yaml` の 2 件に分ける
- 置き場所は `開発ドキュメントサーバー/{container}.yaml`（既に物理ファイルごとになっている `features/admin/` などと同じ）
- 元の設計書の要素・`refs`・`notes`（分類全体の決まりを除く）は、`container` が一致する設計書へ内容を変えずに移す。`title`・`lead`・`diagrams`・`test_files` は物理ファイルごとに作り直す
- 分類ごとの束ねる設計書 `開発ドキュメントサーバー/分類/{分類名}.yaml` を作り、元の設計書の `lead`・`directory`・`diagrams` と分類全体の `notes`（共通の「例外の置き場所」）を移す。物理ファイルの設計書は `directory` を持たない
- 再エクスポートだけの `__init__.py`（`features/*/__init__.py`・`server/mcp/__init__.py`）は要素を持たないので設計書を作らない（`features/admin/` なども `__init__.py` の設計書を持たない）。`DIST_NAME` を定義する `src/dev_docs/__init__.py` は例外で、設計書を作る
- フォルダごとに `index.yaml`・`README.md` を作り、`開発ドキュメントサーバー/` と `features/` の目次を作り直す
- 元の設計書を指す参照（モジュール構成同士の `refs`・インターフェース定義の `notes`・設定の `refs`）を新しいパスへ書き換える

終わりの条件:

- `開発ドキュメントサーバー/` の配下のモジュール構成の設計書が、全て `container` 1 種類で、パスが `{container}.yaml` と一致する
- 書くツールの検査で「物理ファイルが 2 つ以上あります」が出ない
- 元の設計書のパス・名前を指す参照が残らない

## 影響するユースケース

なし（設計書の置き場所だけを変え、シナリオとコードは変わらない）
