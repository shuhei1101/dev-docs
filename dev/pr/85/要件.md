# 要件

## 要望

`dev-docs.yaml` の行の `metadata` に `{配列}[].{項目}`（例 `tags: tags[].name`）か `{配列}[{真偽値のキー}].{項目}`（例 `main_tags: tags[main].name`）の対応を持つ種類で、`write_docs` の `data`・`set`・`add_to`・`remove_from` のそのキーの値が文字列の配列でないとき、`TypeError` で落とさず `InvalidArgumentError` で返す。

- 違反の `path` は `operations[{添字}].{data / set / add_to / remove_from}.{共通のキー}`、`rule` は名前（文字列）の配列で渡すことを示す
- 検査は `expand_array_keys` の入口で 1 回だけ行い、`_rebuild`・`add_to` の追加・選んだ要素のキーの名前の照合（`known`）のどこにも型の違う値を届けない
- `data`・`set` に配列でなく文字列（例 `"scope:dev"`）を渡した場合も同じ違反にする（今は 1 文字ずつのタグに分かれて書かれる。`add_to`・`remove_from` の文字列 1 つは MCP の引数の検証で弾かれる）
- 受け付ける値（文字列の配列）と、その書き戻し方は変えない

終わりの条件:

- `tags` をオブジェクトの配列で渡した `create` が、`Error executing tool write_docs` ではなく引数の誤りの違反を返し、ファイルを書き換えない
- `main_tags`・`add_to`・`remove_from` の要素が文字列でない配列と、`data`・`set` の文字列 1 つの値でも同じ違反を返す
