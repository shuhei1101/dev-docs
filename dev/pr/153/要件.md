# 要件

## 要望

#131 の反映作業『dev-docs のサーバーの再起動』のスクリプトが、管理の MCP の `status` の応答を待ちきり、応答が空か打ち切られたときは理由を出して失敗する。

| 対象 | 終わりの条件 |
| --- | --- |
| `実行.sh` の再起動の前の配信元の一覧の取得 | `status` の打ち切りの秒数が、下の導き方の値になる。打ち切られたら `再起動の前の配信元: failed（status が {秒数} 秒で応答しない）`、応答が空なら `failed` と空だった旨を出して終了コード 1 で終わる。`ok（0 件）` にならない |
| `確認.sh` の `status` の取得 | 打ち切りの秒数と、打ち切り・空の応答のときの出力と終了コードは `実行.sh` と同じ。`端末の設定のパス` の判定へ進まない |
| #131 の `反映作業/index.yaml` の `説明` | 最長の実行時間を、変えた打ち切りの秒数で数え直した値にする |

- 打ち切りの秒数は、規約『資源の値の決め方』の下流を待つタイムアウト（実測の最大 + 50%）で導き、導出の元の実測と導き方をスクリプトのコメントに並べて記載する
  - 2026-11-09 の実測: 119 秒（tester）・126 秒・169 秒。169 秒 + 50% = 254 秒 → 255 秒
  - [PR #136](https://github.com/shuhei1101/dev-docs/pull/136) が先に develop へマージされたら、ドキュメント修正の時点の develop で測り直して再度導く
- `dry-run.log` を取り直す
- マージの後、[#112](https://github.com/shuhei1101/dev-docs/issues/112) で #131 の反映作業『dev-docs のサーバーの再起動』を実行し直す
