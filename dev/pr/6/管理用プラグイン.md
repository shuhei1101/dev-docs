成立（つなぎ直しが要る）。
Claude Code は SessionStart のフックと並んで MCP へ接続するため、サーバーが待ち受けるまでの約 6 秒（WSL の `/mnt/c` から `uv run` で起動）の間に接続を試みて `ECONNREFUSED` で失敗する（[claude-p-cold.json](https://github.com/shuhei1101/dev-docs/blob/980d789/poc/session-start-launch/claude-p-cold.json)）。
待ち受けた後に `/mcp` から Reconnect すると connected になり、ツールを呼べた。サーバーが既に動いているセッションでは最初からつながる（[claude-p-warm.json](https://github.com/shuhei1101/dev-docs/blob/980d789/poc/session-start-launch/claude-p-warm.json)）。
#4 の設計では、サーバーを起動したセッションで `/mcp` のつなぎ直しを利用者へ案内する前提にする。

核心部（[launch.sh](https://github.com/shuhei1101/dev-docs/blob/980d789/poc/session-start-launch/plugin/hooks/launch.sh)）:

```bash
if ss -ltn "sport = :${PORT}" | grep -q LISTEN; then
  echo "hook skip (port in use)" >> "$LOG"
else
  cd "$SERVER_DIR"
  setsid nohup uv run uvicorn server:app --host 127.0.0.1 --port "$PORT" >> "$LOG" 2>&1 < /dev/null &
fi
```

diff の見どころ: `hooks/hooks.json` の SessionStart が `launch.sh` を呼び、`.mcp.json` が `http://127.0.0.1:8781/alpha/mcp` を指す。`claude -p --strict-mcp-config` はプラグインの MCP も読み込まないため、確認には使えない。
