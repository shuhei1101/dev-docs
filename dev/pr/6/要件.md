# 要件

## 要望

dev-docs のリポジトリを、#3（サーバー本体）と #4（管理用のプラグイン）の着手を待たずに始められる状態にする。

- 初期構築: アーキテクチャ図（全体図・サブシステム一覧・外部システム連携）・非機能要件・テスト実行方法・開発コマンド・ドキュメントの骨格・ルール索引・README・CLAUDE.md を、構成方針と設計の資料（A-23・A-24・A-25・R-36）どおりに置く
- 構成方針: Python（uv・FastAPI・MCP の Python SDK の Streamable HTTP）。描画は mdmark。ai-monitor には依存しない。配布はクローン（PyPI に出さない）。設定は `DEV_DOCS_CONFIG`（既定 `~/.config/dev-docs/settings.yaml`）、ポートは `DEV_DOCS_PORT`（既定 8781）
- 複合ユースケース: A-23 のフローシナリオ S0〜S9 を、利用者が dev-docs を入れ、リポジトリを登録し、エージェントと利用者が文書を読み書きするまでの複合ユースケースとして書く
- パッケージの雛形: `pyproject.toml` と `uv.lock` で `uv sync --frozen` が通り、`src/dev_docs` の入口から `dev-docs --version` がバージョンを出し、`dev-docs --help` がサブコマンドの一覧を出して 0 で終わる。サブコマンドの中身（`serve` など）は #3
- マーケットプレイスの雛形: `.claude-plugin/marketplace.json` が `plugins/dev-docs/` を指し、`plugins/dev-docs/.claude-plugin/plugin.json` を置く。`claude plugin validate` が通る。フックと管理の MCP の中身は #4
- PoC: 1 プロセス・1 ポートで、パスごとに別の MCP サーバー（`/{name}/mcp`）をプロジェクトごとの instructions とツールの説明文で立て、Claude Code からプロジェクトごとに見分けられるか（D-107・D-108）と、SessionStart のフックが起動した直後のセッションで MCP につながるか（A-24 の 1）を確かめる

文書を置くフォルダ: ai-monitor の工程どおり `dev/`（設計書・テンプレート・pr）と `docs/`（公開）に分ける。構成方針の「`docs/` だけに置く」形には、dev-docs への移行（ai-monitor#2987）の後に移す（[確認ログ](./確認ログ.md)）
