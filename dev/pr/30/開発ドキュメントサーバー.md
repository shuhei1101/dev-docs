## 変更方針

<!-- table: data -->

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 正規表現の当たり方 | `_test` の `regex` のフラグに `re.MULTILINE` を加える（`case_sensitive` が `False` なら `re.IGNORECASE` も） | 検証（`check_filter`）の `re.compile` も同じフラグにそろえる |
| 抜粋を探す条件 | `_leaf_words` が集める語の文字列をやめ、`body`・`*` の条件（`op`・`values`・`case_sensitive`）を抜粋へ渡し、行ごとに条件と同じ判定で当たる行を探す | `ne`・`not_contains`・比較・`exists` は今と同じく抜粋の対象にしない |
| 抜粋の行番号と前後の行 | 当たった行と前後の行を、本文の行番号（1 始まり）つきの範囲で返す。前は `before`、後ろは `after`、省いたほうは `context_lines` | 重なる範囲をまとめ、先頭から `max_per_doc` 個を返すのは今と同じ。書式は `要件.md` の `未確定` |
| 画面の検索 | 行番号つきの範囲を返す処理と、画面の検索が使う文字列の配列へ戻す処理を分け、`screen_search` の `items[].snippets` の形式を保つ | 画面の検索は語の部分一致のまま |
| 結果の Markdown・JSON | `render.py` で抜粋の各行の頭に行番号を出す。json は抜粋ごとに行番号を持つ構造で出す | `_item_size` の文字数の数え方も抜粋の構造に合わせる |
| 説明 | `search_docs` のツールの説明と、`Condition.op`・`Snippets` の項目の説明（入力のスキーマ）に、`regex` が行単位で当たることと抜粋の行番号・`before`・`after` を書く | `docs/リファレンス/文書のMCP.md` も同じ内容に更新する |
| 既存機能への影響 | `context_lines` だけの呼び出しは今と同じ範囲を返す。`regex` は行単位になるので、`^`・`$` で値全体の先頭・末尾に当てていた式の当たり方が変わる（値全体の先頭・末尾は `\A`・`\Z` で書ける） | リリース前のため破壊的変更として扱わない（扱いの判断で合格済み） |
