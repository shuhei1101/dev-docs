# 要件

## 要望

`search_docs` の正規表現と抜粋（`snippets`）を、grep で普段やっている探し方に合わせる。
仕様の正本は起点 Issue の必読の資料（D-141〜D-143・A-33・L-86）で、ここでは終わりの条件を並べる。

<!-- table: data -->

| 対象 | 終わりの条件 |
| --- | --- |
| 正規表現の当たり方 | `op: regex` が値の各行に当たる（`^`・`$` が各行の先頭・末尾に当たる）。`body`・`*` を含む全ての項目で同じ |
| 抜粋の探し方 | 抜粋は条件と同じ判定で当たった行を探す。`regex` は正規表現、`eq`・`prefix`・`suffix`・`contains` は部分一致（今と同じ）、`case_sensitive` も条件と同じ。`op: regex` で当てた文書の抜粋が空にならない |
| 抜粋の行番号 | 抜粋の各行に本文の行番号（1 始まり）を付ける。markdown は行の頭、json は行ごとの番号 |
| 前後の行の数 | `snippets` に `before`・`after` を追加し、前と後ろの行の数を別に指定できる。`context_lines` は `before`・`after` を省いたときの両方の既定として残す（今の呼び出しはそのまま動く） |
| 説明 | `search_docs` のツールの説明と入力のスキーマの項目の説明に、`regex` が行単位で当たることと、抜粋の行番号・`before`・`after` を記載する |
| 画面の検索 | 画面の検索の `items[].snippets`（文字列の配列）の形式は変えない（[#17](https://github.com/shuhei1101/dev-docs/issues/17) が API から型を作るため。task-planner の着手の指示） |

<!-- /table -->

インターフェース定義設計で次のとおり決めた。

- 抜粋の行番号の書式: markdown は grep の `-n` と同じく、当たった行を `{行番号}:{行}`、前後の行を `{行番号}-{行}` で出し、抜粋の間に `--` を置く。json は `items[].snippets[].lines[]` の各行に `line`（1 始まり）・`text`・`hit`（当たった行か）を持つ（当たった行と前後の行を見分けられ、要望の json の行ごとの番号になる）
