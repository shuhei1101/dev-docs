### 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 設定の書き方 | `documents[].schema` に、文字列（今の相対パス）と、配信元の ID・パス・リビジョンを持つオブジェクト（`source`・`path`・`ref`）のどちらかを受ける | |
| スキーマの読み取り | オブジェクトの参照は、参照先の配信元のリポジトリから指定したリビジョンのファイルを Git のオブジェクトとして読む。作業ツリーの今の内容は読まない | リビジョンの解決は `default_ref` の読み込みと同じ `resolve_ref` を使う |
| `$ref` の解決 | 参照したスキーマの中の相対の `$ref` は、同じ配信元の同じリビジョンのファイルとして解決する | `resolve_schema_refs` がディスクのパスでなく、読み取りの関数で参照先を引けるようにする |
| 読み取りの集約 | 検査・`describe(source, kind)`・描画・`check_project` が個別に `root / schema_path` を組み立てている所を、行の参照からスキーマを返す 1 つの関数にまとめる | 4 か所の読み方の食い違いを防ぐ |
| 誤りの検査 | 配信元・パス・リビジョンが見つからないときは、`check_project` と起動時の検証で `documents[{番号}].schema` の違反にする | 参照先が `not_served` でも端末の設定に行があり Git のリポジトリなら読み、端末の設定に無い・Git のリポジトリでないときは違反にする |
| 起動の順序 | 起動時のスキーマの読み込みは、参照先の配信元の root を端末の設定から引けるようにする | 参照先の配信元より先に組み立てる配信元でも読めるようにする |
| 既存機能への影響 | 文字列の `schema` の行は今と同じ読み方・同じ `$ref` の解決にする | |
