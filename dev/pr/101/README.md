# 画面を mdmark#222 の機能につなぎ、dev-docs.yaml の schema でほかの配信元のスキーマをリビジョンで参照でき、write_docs の違反に該当キーのスキーマの説明を添える

## 概要

利用者が文書の画面で比較元からの変更箇所の強調・列の出し入れの保存・コメントの修正と削除と本文の該当箇所への移動を使え、配信元の管理者が `dev-docs.yaml` の `schema:` でほかの配信元のスキーマをリビジョンを指定して参照でき、エージェントが `write_docs` の違反から該当キーのスキーマの説明・決まり・例を参照できるようにする。

## 背景

[#99](https://github.com/shuhei1101/dev-docs/issues/99) の束（[#44](https://github.com/shuhei1101/dev-docs/issues/44)・[#94](https://github.com/shuhei1101/dev-docs/issues/94)・[#96](https://github.com/shuhei1101/dev-docs/issues/96)）。

- #44: [#36](https://github.com/shuhei1101/dev-docs/pull/36) で作った画面は、[shuhei1101/mdmark#222](https://github.com/shuhei1101/mdmark/issues/222) が入るまで `baseMarkdown`・`onColumnsChange`・`commentStore.update`/`remove`・`reloadComments`/`focusComment` を呼ばずに済む範囲で実装した。列の出し入れは mdmark の内部の DOM を参照して保存している
- #94: 設計書のスキーマは各プロジェクトがコピーを持ち、ai-monitor の正本とほぼ全てずれている。knowledge に 1 つだけ置き、各プロジェクトの `dev-docs.yaml` がリビジョンつきで参照する方針に決まった。今の `schema:` は配信元の root からの相対パスしか参照できない。後続は [shuhei1101/ai-monitor#3188](https://github.com/shuhei1101/ai-monitor/issues/3188)
- #96: `write_docs` の違反は `path`・`rule`・`fix` だけを返し、エージェントがスキーマを参照し直さずに推測で書き直して再び弾かれる（11-03 までの 48 時間で引数の誤り 28 回・検査で弾かれた 11 回）
