# 要件

## 要望

`dev-docs.yaml` の `documents[]` の行に、`paths[]` に当たったファイルのうちファイル名の glob で外すものを並べるキー `exclude[]`（任意・既定 `[]`）を追加する。
`exclude[]` は `paths[]` に当たったファイルのファイル名（最後の段）に当て、どれかに当たったファイルはその行の文書にしない。
外したファイルは、他の行の `paths[]` に当たればその行の文書になる。

「ファイルがその行に当たるか」（`paths[]` のどれかに当たり、`exclude[]` のどれにも当たらない）の判定を 1 か所にまとめ、`paths[]` で行を判定する全ての箇所に当てる。

<!-- table: data -->

| 箇所 | 終わりの条件 |
| --- | --- |
| 読み込み（`collect_files`） | `exclude[]` に当たるファイルを文書として読み込まない。検索・取得・関連のたどり・画面の API に出ない |
| 変更の一覧（`list_changes`） | 変わったファイルの行を決めるとき、`exclude[]` に当たる行を飛ばす |
| 画面の文書のページ（`_kind_of`） | ファイルの行を決めるとき、`exclude[]` に当たる行を飛ばす |
| 書き込みの置き場所（`new_document_path`） | `create` で決めた置き場所のファイル名が `exclude[]` に当たる場合、書き込まずに `InvalidArgumentError` を返す |
| 設定の検査 | スキーマが `documents[].exclude[]`（文字列の配列）を受け付ける。`exclude[]` の無い既存の設定はそのまま読める |

<!-- /table -->

外したファイルは読み込まないため、`defaults[]`（`apply_defaults`）も当たらない。
`apply_defaults` は `documents[].defaults[].paths` の照合で、行の判定ではないため変えない。

`未確定`: 管理用の YAML を持つ行（`records`・`body_file`）で、`exclude[]` に当たるファイルを `unindexed_files`（索引に無いファイル）の件数に数えるか（決める段: モジュール構成設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | `unindexed_files` が、管理用の YAML のフォルダの配下のファイルのうち `exclude[]` に当たるものも数えない | 目次の `README.md` などを外せば、索引の同期の警告から消える | 「索引に無いファイル」の範囲が行の設定で変わる |
| B | 数える（今のまま） | 範囲が変わらない | 外したファイルが毎回、警告のログに残る |

推奨: A

`exclude[]` に書くのは配信しないと決めたファイルで、管理用の YAML に記載していなくてもずれではないため。

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| shuhei1101/alias-inject の `dev-docs.yaml` の否定の glob（`[!R]*.md`・`[!i]*.yaml`）を `exclude[]` へ書き換える | 別のリポジトリで、この PR の `exclude[]` を前提にする | 起票予定 |
| どの行にも当たらないファイルを知らせる検査 | 本文の困りごとは否定の glob で外すことによる漏れで、名前で外せれば起きない（[扱いの判断](https://github.com/shuhei1101/dev-docs/issues/26#issuecomment-6477409241)） | 予定なし |
| `records` の行の `body_file` が指すファイルへの `exclude[]` の適用 | `exclude[]` は `paths[]` に当たったファイルに当てる。`body_file` が指すファイルは管理用の YAML の `files[]` に記載するかで選べる | 予定なし |
