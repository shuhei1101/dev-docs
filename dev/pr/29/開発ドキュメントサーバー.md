## 変更方針

<!-- table: data -->

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 設定のスキーマ | `documents[].exclude` を `minLength: 1`・`pattern: ^[^/]+$` の文字列の配列で追加する（任意） | 既存の設定はそのまま読める。`/` を含む要素は起動時の設定の検証で違反になる |
| `DocumentTable` | `exclude: list[str]`（既定 `[]`）を持たせ、設定の組み立てで読む | - |
| 行の判定 | `PurePosixPath(path)` が `paths` のどれかに `full_match` で当たり、ファイル名が `exclude` のどれにも当たらないときだけ「当たる」とする関数を 1 つ置く | `DocumentTable.matches`（ファイル名の判定は `DocumentTable.excludes`）に置く |
| 読み込み | `collect_files` が行の判定で集める（引数を `DocumentTable` にする） | `defaults[]` は読み込んだ文書だけに当たる |
| 変更の一覧・画面の文書のページ | 行を決める `full_match` を行の判定に置き換える | 外したファイルは次の行へ進む |
| 書き込みの置き場所 | 決めた置き場所のファイル名が `exclude` に当たる場合、`path` が `operations[{i}].kind` の `InvalidArgumentError` を送る | `fix` の文言は単一ユースケース設計で決める |
| 索引に無いファイル | `unindexed_files` が行を受け取り、`excludes` に当たるファイルを数えない | 要件.md の `## 要望` の案 A |
| 既存機能への影響 | `exclude` を持たない行の振る舞いは変えない | 既存のテストを回帰確認で流す |
