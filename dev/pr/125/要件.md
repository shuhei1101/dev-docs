# 要件

## 要望

反映作業『dev-docs のサーバーの再起動』のスクリプトが、再起動の後の新しいサーバーの待ち受けと、配信元の読み込みの終わりを待ってから確認する。

| 対象 | 終わりの条件 |
| --- | --- |
| 実行スクリプト | 再起動を要求した後、新しいサーバーが待ち受けるまでを、2026-11-08 に観測した約 78 秒より長い上限まで待つ。上限は規約『資源の値の決め方』で導く |
| 確認スクリプト | 文書の MCP の `describe` が応答する（配信元の読み込みが終わる）まで待ってから、件数の検索の応答時間を測る。待つ上限は、2026-11-08 に観測した約 6 分の読み込みより長く、規約『資源の値の決め方』で導く |
| 以後の再起動の反映作業 | 新しく書く dev-docs のサーバーの再起動の反映作業が、上の 2 つの待ちを同じ上限で持つ |

- 対象は [dev/pr/120/反映作業/dev-docs のサーバーの再起動/実行.sh](https://github.com/shuhei1101/dev-docs/blob/26dbb0f1e3aebc6dec8224244986d913acfd78a4/dev/pr/120/%E5%8F%8D%E6%98%A0%E4%BD%9C%E6%A5%AD/dev-docs%20%E3%81%AE%E3%82%B5%E3%83%BC%E3%83%90%E3%83%BC%E3%81%AE%E5%86%8D%E8%B5%B7%E5%8B%95/%E5%AE%9F%E8%A1%8C.sh)・[dev/pr/120/反映作業/dev-docs のサーバーの再起動/確認.sh](https://github.com/shuhei1101/dev-docs/blob/26dbb0f1e3aebc6dec8224244986d913acfd78a4/dev/pr/120/%E5%8F%8D%E6%98%A0%E4%BD%9C%E6%A5%AD/dev-docs%20%E3%81%AE%E3%82%B5%E3%83%BC%E3%83%90%E3%83%BC%E3%81%AE%E5%86%8D%E8%B5%B7%E5%8B%95/%E7%A2%BA%E8%AA%8D.sh) と、待ちの変更に合わせた [dev/pr/120/反映作業/index.yaml](https://github.com/shuhei1101/dev-docs/blob/26dbb0f1e3aebc6dec8224244986d913acfd78a4/dev/pr/120/%E5%8F%8D%E6%98%A0%E4%BD%9C%E6%A5%AD/index.yaml) の確認方法
- 読み込みの終わりは、読み込みの終わりまで待ってから返る文書の MCP の `describe` の応答で判定する。管理の MCP の `status` は読み込み中は待たずに `loading: true` を返すが、読み込みが終わると全ての配信元の同期を調べて 200 秒を超えても返らないため使わない
- 上限は規約『資源の値の決め方』の下流を待つタイムアウト（実測 + 50%）で、待ち受けを 78 秒 + 50% = 117 秒 → 120 秒、読み込みを実測の最大 357 秒 + 50% = 536 秒 → 540 秒とする
- 以後の再起動の反映作業へは、待ち受けと読み込みの終わりを待つ共通のスクリプト `scripts/dev-docs-server-wait.sh` を置き、各作業 PR の実行・確認のスクリプトはそれを呼ぶ。呼び方は開発コマンドの設計書の `管理作業` に書く
