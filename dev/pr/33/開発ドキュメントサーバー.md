## 変更方針

<!-- table: data -->

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 設定のスキーマ | `documents[].type`・`defaults` を削除し、`metadata` を `additionalProperties: {type: string, minLength: 1}` に、`alias_type` を行の属性（alias-inject のスキーマの選択肢）にする。`exclude` は残す | 書いた `type`・`defaults`・オブジェクトの `metadata` の値は違反になる |
| 配布用の JSON Schema | リポジトリの直下に `schemas/dev-docs.schema.json` を置き、サーバーのスキーマと内容の一致を単体テストで確かめる | 正本は `未確定`（`要件.md`） |
| 設定の型と組み立て | `DocumentTable` から `type`・`defaults` を削除し、`metadata: dict[str, str]`・`alias_type: str \| None` を持たせる。`MetadataMapping`・`DocumentDefaults` を削除する。`is_writable` の既定は `true` にする | `schema` は全ての行で必須にする |
| メタデータの解決 | `resolve_metadata` は共通のキーごとに `metadata` の列名（無ければキー名）の値を取る。`apply_defaults` を削除する。`missing_ref_fields` は `metadata` に書いた列が無いものを返す | `alias_type` は行の属性から文書のメタデータへ入れる |
| 読み込み | `split_front_matter` と `type: markdown` の分岐を削除する | Markdown の本文は `body_file` で読む |
| 書き込み | `write_docs` の `data` のキーと `path` の先頭のキーを、`metadata` の対応で列名へ読み替えてから当てる。Markdown の行の分岐と `defaults[]` 由来の `related` の違反を削除する | 列名をそのまま渡したときは読み替えない |
| `describe` | `describe(source, kind)` の結果に、共通のキーと列名の対応（`metadata`）を追加する | Markdown・JSON の両方に出す |
| ツールの説明 | `write_docs`・`search_docs` の説明に、共通のキー名で読み書きでき、列名は `describe(source, kind)` で引けることを追加する | #28 の記載を取り込んでから加える |
| 変更の一覧・試しの変換 | `type == "markdown"` の分岐を削除する | - |
| `check_project` | `missing_refs` を `metadata` に書いた列が無い文書の件数にする。前の形式のキーを違反として返す | 項目名 `missing_refs` は変えない（`status` の `sources[].sync` と揃える） |
