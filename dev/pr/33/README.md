# メタデータを列の対応だけにし、documents の行の type・custom・defaults[]・フロントマターをやめ、write_docs が対応を解いて書く

## 概要

利用者とエージェントは、文書 1 つのメタデータを YAML の列の 1 か所で持ち、`write_docs` で 1 つずつ直せるようになる。
`dev-docs.yaml` は「どのファイルを、どの種類として、どの列から読むか」の定義だけを持ち、エディターで配布の JSON Schema による補完と検証が効く。

## 背景

[Issue #32](https://github.com/shuhei1101/dev-docs/issues/32) の要望。
今の `documents[].metadata` の `ref`・`custom` と `defaults[]`（#20 で導入）は、1 ファイルのメタデータを MCP で 1 つずつ直せない（`custom` のキーを書いても検索に効かない、`defaults[]` の `tags`・`related` を 1 ファイルだけ外せない、`ref` の列名が違う種類に共通のキー名で書くと新しい列ができる）。
メタデータの置き場所が文書の列・管理用の YAML・`custom`・`defaults[]`・フロントマターに分かれ、重ねる順を覚えないと値が読めない。
各リポジトリへ `dev-docs.yaml` を展開する移行の Issue より先に入れる（[着手の指示](https://github.com/shuhei1101/dev-docs/issues/32#issuecomment-6499715102)）。
#4（PR #21）が今の形式で作った `/dev-docs:setup`・`dev-docs migrate`・`templates/dev-docs.yaml` の切り替えと、#26（PR #29）が加えた `exclude[]` の移し替えもこの PR で行う。
