## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 置き場所 | `dev/設計書/モジュール構成/画面/{container}.yaml`（例 `features/docs/not-found/hooks/use-missing-view.ts.yaml`） | #70 の `{container}.yaml` |
| `title`・`lead` | `画面 / {分類名} / {物理ファイルの名前}`。`lead` はファイルの JSDoc の内容 | 分類名は同じフォルダの他の設計書に揃える（`features/docs/` は `文書の画面`、`features/settings/` は `設定画面`、`shared/`・`testing/` は `共通`） |
| 要素 | コンポーネントは `components`、フックと関数は `functions`、型は `data_models` に置く。`container` は `frontend/src/` からのパス、`usecase` は使う画面のユースケース（共用は `共通`） | 同じフォルダの他の設計書と同じ置き方 |
| `test_files`・`unit_tests` | 条件分岐か振る舞いを持つ要素（`compareBase`・`useDocNavigation`・`useMissingView`・`servingSources`・`MissingLinks`・`DocMain`・`SkipLink`・`useDelayedFlag`・`useMediaQuery`）は条件分岐ごとに `unit_tests` を持ち、`tests/unit/frontend/src/` の下に単体テストのファイルを作って `test_files` に載せる。`SourceSkeleton`・`testing/setup-tests.ts` は持たない | 書くツールは無いファイルを `test_files` に載せられないため、テストのファイルを作ったときに載せる |
| 設計しないファイル | `shared/components/ui/`・`shared/lib/utils.ts`・`*.stories.tsx` を分類の設計書の `directory` に `（設計しない）` と書く | `分類/アプリとルート.yaml` の生成物の行と同じ書き方 |
| 目次 | 置き場所のフォルダの `index.yaml` に行を追加し、`summary` に中身を加える。上の階層の目次の行も同じ `summary` にし、`README.md` を生成し直す | `not-found/components/`・`not-found/hooks/` は新しく作る |
| 分類 | 分類の設計書の `directory` に作ったファイルの行を加える。構成図に載せる要素は、使う側の矢印がある要素だけ加える | 他の行の文言は変えない |
| 参照する設計書 | 処理の本文で、対象の要素を使う箇所を作った設計書の論理名で指す。対象の要素の中身を自分の処理として書いている箇所は、その中身を作った設計書へ移し、呼び出しだけを残す | 振る舞いの記述は変えない |
| 書き方 | 書くツール（`write_design_doc_module`）で作り・書き換え、検査を通す | |
