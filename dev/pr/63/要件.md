# 要件

## 要望

プラグインの `.mcp.json` の接続先 `/mcp`・`/_admin/mcp`（スラッシュ無し）への MCP の POST を、リダイレクトを挟まずに文書の MCP・管理の MCP へ届け、200 を返す。

- `/mcp/`・`/_admin/mcp/`（スラッシュ付き）への POST は今のまま 200 を返す
- 画面の配信は、`/_api/`・`/mcp`・`/_admin/` 以外のパスで今のまま `index.html` と `assets/` を返す
- `/mcp`・`/_admin/mcp` への initialize の POST が 200 で返ることを確かめる結合テストを追加する（画面の配信のルートの追加で再発したときに落ちる）
- マージの後、稼働中の dev-docs のサーバーを起動し直し、Claude Code から `/mcp` で接続できることを確かめる（反映作業）
- 完了したら、後続の [shuhei1101/ai-monitor#3093](https://github.com/shuhei1101/ai-monitor/issues/3093) に着手できる旨を起点 Issue にコメントする

修正するルーティングの処理: 案 A（インターフェース定義設計で決定）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | スラッシュ無しの `/mcp`・`/_admin/mcp` を MCP へ届ける（マウントのパスの扱いを変える） | 画面の配信のルートの増減に左右されない | マウントの扱いを Starlette の既定から外す |
| B | 画面の配信のルートのパスの指定で、`/_api`・`/mcp`・`/_admin` で始まるパスに当たらないようにする | 画面の配信の側だけで閉じる | ルートに当たらなかった `/mcp` が末尾のスラッシュへのリダイレクト（307）になり、リダイレクトを挟まず 200 を返す条件を満たさない |

推奨: A

プラグインの接続先そのものに応えるのは MCP のマウントの側で、画面の配信の側で除外しても `/mcp` は 307 を挟む。
