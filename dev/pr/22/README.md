# 文書を新しく作るか既存を修正するかと、どの documents の行に入れるかの判定フローチャートを使い方に置く

## 概要

dev-docs で文書を書くエージェントが、書く前に「新しく作るか既存を修正するか」と「どの documents の行（kind）に入れるか」を判定フローチャートで決められるようになる。

## 背景

[Issue #18](https://github.com/shuhei1101/dev-docs/issues/18) の要望（D-110 の ① と ③）。
既存のプロジェクトの文書を dev-docs で配信する（D-101・D-102）と、AI は文書を書くたびにこの 2 つを判定するが、決まりが無い。
外すと同じ話の文書が重複して検索で両方出る、同じ種類の文書が別の kind に散ってスキーマと検査が揃わない。
documents の行の `metadata`・`defaults[]` の設計は [#3](https://github.com/shuhei1101/dev-docs/issues/3)・[#14](https://github.com/shuhei1101/dev-docs/issues/14) で develop へ入っている。
