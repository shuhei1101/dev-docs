# 要件

## 要望

変換器（`converters[]`）を持たない YAML の文書をスキーマ駆動で Markdown にする汎用の描画（`features/convert/markdown.py`・`diagrams.py`）を、knowledge の規約『表し方の優先順位』（[knowledge#132](https://github.com/shuhei1101/knowledge/issues/132)）に沿って修正する。
修正後の Markdown は、画面が使う mdmark の記法で描ける（Mermaid のコードブロックを出すのは、ER 図と mdmark に部品の無い図だけ）。

`未確定`: 説明の列への `wide=`（決める段: ユーザーの確認。Issue の やりたいこと 7 をこの PR で満たすかが変わるため）

`wide=` を持つ mdmark は develop にだけある（[mdmark#283](https://github.com/shuhei1101/mdmark/pull/283)、064265d6）。
画面が読む mdmark は jsDelivr の `master`（v0.9.0）で、v0.9.0 は `wide=` を `使えないキーです` の警告にする。

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | この PR では `wide=` を出さず、mdmark のリリース後に別の Issue で出す | 画面に警告が出ない | Issue の やりたいこと 7 がこの PR で満たされない |
| B | この PR で `wide=` を出す | 1 回で終わる | mdmark のリリースまで、全ての表に警告が出る |
| C | この PR のマージ前に mdmark をリリースしてもらい、この PR で `wide=` を出す | Issue の要件を満たし、警告も出ない | mdmark のリリースを待つため、マージが遅れる可能性がある |

推奨: C

mdmark#283 は develop へマージ済みで、リリースは実装の完了までに間に合う見込みがある。
間に合わない場合は A へ切り替える。

`未確定`: 手で書く Mermaid の文字列（共通の型 `mermaid`。シナリオの `flow`・モジュール構成の `diagrams[].diagram` など）の扱い（決める段: ユーザーの確認。Issue の やりたいこと 2 の sequence の部品をこの PR で満たすかが変わるため）

起点 Issue の現状の No.2 の 262 個の図（シナリオ 15・I/F 定義 31・モジュール構成 18・ER 8・アーキテクチャ 1 ページ）の大半は、YAML に Mermaid の文字列で書いた図（`sequenceDiagram`・`flowchart`・`classDiagram`）である。
`x-diagram` にシーケンスの種類は無く、シナリオの `flow` は ai-monitor のテンプレートのスキーマが Mermaid の文字列と定めている。
mdmark にクラス図の部品は無い。

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | `sequenceDiagram` と `flowchart` の Mermaid を読んで mdmark のシーケンス図・フロー図の部品にし、`classDiagram` などはコードのまま出す | Issue の やりたいこと 2 を満たし、配信元の YAML とテンプレートのスキーマを修正せずに多くの図が描かれる | 変換に Mermaid の構文の読み取りを持つ |
| B | 共通の型 `mermaid` を構造化した値へ移すよう ai-monitor のテンプレートのスキーマを修正し、dev-docs は `x-diagram` にシーケンスを追加する | Mermaid の構文を読まずに済む | ai-monitor の配布物と全リポジトリの設計書の移し替えが要り、Issue の範囲を超える |

推奨: A

Issue の要件どおりで、他のリポジトリの修正を待たずに解消する。
Mermaid の構文の読み取りは `sequenceDiagram`・`flowchart` の範囲に限る。
