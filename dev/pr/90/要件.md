# 要件

## 要望

変換器（`converters[]`）を持たない YAML の文書をスキーマ駆動で Markdown にする汎用の描画（`features/convert/markdown.py`・`diagrams.py`）を、knowledge の規約『表し方の優先順位』（[knowledge#132](https://github.com/shuhei1101/knowledge/issues/132)）に沿って修正する。
修正後の Markdown は、画面が使う mdmark の記法で描ける（Mermaid のコードブロックを出すのは、ER 図と mdmark に部品の無い図だけ）。

説明の列には `wide=` を付ける（[確認ログ](./確認ログ.md)）。
画面が読む mdmark の master（v0.9.0）は `wide=` を `使えないキーです` の警告にするが、mdmark のリリースを待たずにこの PR で出す。
知らないキーを警告にしない変更は [mdmark#295](https://github.com/shuhei1101/mdmark/issues/295) で扱う。

YAML に手で書いた Mermaid の文字列（共通の型 `mermaid`。シナリオの `flow`・モジュール構成の `diagrams[].diagram` など）のうち、`sequenceDiagram` は mdmark のシーケンス図の部品に、`flowchart` はフロー図の部品にする（[確認ログ](./確認ログ.md)）。
読み取るのはこの 2 種に限り、`classDiagram` など mdmark に部品の無い図はコードのまま出す。
変換が読み取れない行を 1 つでも含む図も、図ごとコードのまま出す。
