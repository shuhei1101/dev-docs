# 要件

## 要望

変換器（`converters[]`）を持たない YAML の文書をスキーマ駆動で Markdown にする汎用の描画（`features/convert/markdown.py`・`diagrams.py`）を、knowledge の規約『表し方の優先順位』（[knowledge#132](https://github.com/shuhei1101/knowledge/issues/132)）に沿って修正する。
修正後の Markdown は、画面が使う mdmark v0.9.0 の記法だけで描ける（Mermaid のコードブロックを出さない）。

`未確定`: 説明の列への `wide=`（決める段: モジュール構成設計）

`wide=` を持つ mdmark は develop にだけある（[mdmark#283](https://github.com/shuhei1101/mdmark/pull/283)、064265d6）。
画面が読む mdmark は jsDelivr の `master`（v0.9.0）で、v0.9.0 は `wide=` を `使えないキーです` の警告にする。

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | この PR では `wide=` を出さず、mdmark のリリース後に別の Issue で出す | 画面に警告が出ない | 説明の列の幅は mdmark のリリースまで変わらない |
| B | この PR で `wide=` を出す | 1 回で終わる | mdmark のリリースまで、全ての表に警告が出る |

推奨: A

警告は全ページの表に出て、修正前より読みにくくなる。

`未確定`: 手で書く Mermaid の文字列（共通の型 `mermaid`。シナリオの `flow`・モジュール構成の `diagrams[].diagram` など）の扱い（決める段: モジュール構成設計）

起点 Issue の現状の No.2 の 262 個の図には、`x-diagram` の値から組み立てる図のほかに、YAML に Mermaid の文字列で書いた図（`sequenceDiagram`・`classDiagram`）がある。
mdmark にクラス図の部品は無い。

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | この PR では手で書く Mermaid を変換しない。配信元の YAML を `x-diagram` の値へ移す後続（aituber の設計書の修正）で直す | 変換が Mermaid の構文を読まずに済む | 移すまで、手で書く図はコードのまま出る |
| B | `sequenceDiagram` を読んでシーケンス図の部品に、`flowchart` を読んでフロー図の部品にする。`classDiagram` はコードのまま出す | 配信元の YAML を直さずに多くの図が出る | 変換に Mermaid の構文の読み取りを持つ |

推奨: A

規約は図を mdmark の部品で描くと定め、Mermaid の文字列を正本にし続けるより、配信元の YAML を構造化した値に移すほうが規約に沿う。
