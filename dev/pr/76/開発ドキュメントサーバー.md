## 変更方針

<!-- table: data -->

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| `auto` のフォルダの束ね | 文書のページのパスのフォルダごとに `group` を作り、入れ子のフォルダは入れ子の `group` にする。group の名前はフォルダ名。フォルダの `index.yaml` の文書をその group の先頭の `page` にする | 書き方は 要件.md の `未確定`（推奨 B: `'@folder'`）。決める段: インターフェース定義設計 |
| nav が無いときの既定 | 行ごとのタブの `auto` をフォルダで束ねる | 直下の文書は group に入れずタブの先頭に並べる |
| 手で書いた `page` との重なり | 同じタブの中で、手で書いた `page` が指す文書を `auto` の結果から除く | 手で書いた `group`・`page` の並びは変えない |
| スキーマ | `schemas/dev-docs.schema.json` と `src/dev_docs/schemas/dev-docs.schema.yaml` の `nav_item.auto` に `group_by` を追加し、2 つの定義をそろえる | |
| nav の検査 | `write_nav` と起動時の nav の警告が、フォルダの指定を項目のパスとして検査しない | |
| 待ち受けまでの順番 | 計測した 3 区間（import と `registry.reload`・`check_sync`・残りの部品と `build_app`）を元に、待ち受けに要らない処理を待ち受けの後へ回す | 縮め方は 要件.md の `未確定`（推奨 A）。決める段: インターフェース定義設計 |
| 検査の途中に届いた要求 | 配信元を読み終えていれば、検査を待たずに答える | 案 A のとき。検査は警告をログに書くだけで、答えを変えない |
| 再起動から待ち受けまでの時間 | 非機能要件に項目を追加し、決定値と測り方を置く | 値は計測の後に決める。外部の制約は #62 の再起動のスクリプトの打ち切り（60 秒） |
| 端末の設定の保存 | `_to_yaml_row` が `config` を常に配列で書く | 設計書は `save_sources` の処理の 2 と単体テスト `test_save_sources_when_defaults` の並びに書く |
