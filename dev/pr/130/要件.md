# 要件

## 要望

スキーマ駆動の変換が、設計書の `decisions` の値（検討事項の ID。`^[A-Z]+-[0-9]+$`）を、話し合いの記録の検討事項の文書へのリンクにする。

| 終わりの条件 | 内容 |
| --- | --- |
| リンクの描画 | 表のセル・項目の属性・箇条書きのどこに出る `decisions` も、リンク先が決まる ID はリンクにする |
| リンク先が決まらない ID | 今と同じく ID の文字のまま出す（本文の変換を失敗にしない） |
| 他のキー | `decisions` 以外の文字列の並びの出し方は変えない |

`未確定`: リンク先の決め方（決める工程: インターフェース定義設計）

話し合いの記録（MindStella のワークスペース）は、各リポジトリの Git 管理外の `tmp/{話し合い}/.mindstella/` に話し合いごとに配置され、検討事項は `decisions.yaml` の行と `docs/{ID}.md` の文書を持つ。
ID は話し合いごとに `D-1` から振られ、話し合いをまたぐと重なる。設計書の `decisions` は ID だけを持ち、どの話し合いの ID かを持たない。

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 配信元の設定に、検討事項のリンク先の型（話し合いの場所と `{ID}` を埋める URL・パス）を持たせ、設定がある配信元の設計書の ID だけをリンクにする | 設計書のスキーマを変えずに済む。設定の無い配信元は今と同じ出し方のまま | 配信元 1 つに話し合い 1 つしか結び付けられない |
| B | 話し合いの記録を dev-docs の配信元に加え、配信元をまたぐ文書の ID として参照する | 検索・関連のたどりでも検討事項を参照できる | ID が話し合いをまたいで重なるため、どの配信元の ID かを設計書側で区別する手段が要る。Git 管理外のフォルダを配信元にする設定がユーザーの環境ごとに要る |

推奨: A

設計書のスキーマ（AI Monitor の配布物）を変えずに、配信元の設定だけで要望を満たせるため。
配信元の設定はユーザーの環境の設定に関わるため、決める工程でユーザーへ確認する。
