## 変更方針

<!-- table: data -->

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| `@matches` | 計算項目に追加し、`body`・`*` の条件に当たった本文の行の数を返す。行の判定は抜粋（`find_snippets`）と同じ。`fields`・`order_by` で使える | 本文の条件が無い `filter` のときの値は、インターフェース定義設計で決める |
| 本文の一部 | `search_docs` に節（Markdown の見出しの文字列）と行の範囲（`offset`・`limit`）で本文を切り出す引数を追加する。節は見出しから次の同じか上の階層の見出しまで | 引数の名前と、`snippets`・`max_chars_per_field` と同時に渡したときの扱いはインターフェース定義設計で決める |
| 返した範囲 | 本文の一部を返した文書の `scope` を `section` にする | `_scope` に条件を追加する |
| 返し済みの記録 | 本文の一部を返した文書は返し済みとして記録しない（全文を返したときだけ記録する） | `list_changes` の前回読んだ時点と、同じ本文を 2 回取ったときの扱いを、全文を読んだことと食い違わせない |
| `not` | `Group` に `not`（中は条件か束 1 つ）を追加し、`and`・`or`・`not` のどれか 1 つだけを持つ束にする。`check_filter` で中の条件も検証する | #16 が `nav` の式で同じスキーマを使えるよう、`Group` の入れ子の書き方は変えない |
| `glob` | `Condition.op` に `glob` を追加し、`**`（`/` をまたぐ）・`*`・`?` で値全体に当てる。`case_sensitive` は他の `op` と同じ | `list_changes` の `filter` も同じ判定を使う |
| `contains` | `list_changes` に `contains`（語か正規表現）を追加し、差分の追加・削除の行に当たる文書だけを返す | 返す区間は要件の `未確定`（決める段: インターフェース定義設計） |
| 説明 | ツールの説明と入力のスキーマの項目の説明に追加するオプションを書き、`docs/リファレンス/文書のMCP.md` も同じ内容にする | - |
| 既存機能への影響 | 追加した引数・項目を渡さない呼び出しは今と同じ結果を返す | 画面の検索（`features/view/search.py`）は `match_words` を使い、`filter` を受けないので変わらない |
