# 要件

## 要望

grep・Read・jq・git で普段やっている探し方のうち `search_docs`・`list_changes` でできないものを、ツールを増やさず既存のツールのオプションで埋める。
仕様の正本は起点 Issue の必読の資料（D-141〜D-143・A-33・L-86）で、ここでは終わりの条件を並べる。

<!-- table: data -->

| 対象 | 終わりの条件 |
| --- | --- |
| 文書ごとの当たった数 | 計算項目 `@matches`（文書ごとに、本文の条件に当たった行の数）を `fields` で返せ、`order_by: [{field: "@matches", direction: desc}]` でよく当たる順に並べられる。当たった行の判定は抜粋（`snippets`）と同じ |
| 本文の一部の取得 | 本文の一部だけ返すオプションを `search_docs` に追加する。Markdown は見出しで節を選べ（例 `sections: ["決まったこと"]`）、行の範囲でも選べる（例 `lines: {offset: 120, limit: 40}`）。一部を返した文書の `scope` は `section` で、返し済みの記録（`list_changes` の前回読んだ時点・`repeat_seen`）は全文を返したときだけ付ける |
| 束ごとの否定 | `filter` に `not`（中の条件か束に当たらない文書）を追加する。`and`・`or` の中にも置ける。[#16](https://github.com/shuhei1101/dev-docs/issues/16) が画面の `nav` の `auto` のタグの式でそのまま使える書き方にする（task-planner の着手の指示） |
| パスの glob | 文字列の条件の `op` に `glob`（`**`・`*`・`?`）を追加する。`@path` を含む文字列の項目で使える |
| 変更の中身での検索 | `list_changes` に `contains`（語。正規表現も選べる）を追加し、commit の前後で語の出現数（正規表現なら当たった数）が変わった文書と区間を返す（`git log -S`、正規表現は `--pickaxe-regex` と同じ当て方） |
| 説明 | `search_docs`・`list_changes` のツールの説明と入力のスキーマの項目の説明、[docs/リファレンス/文書のMCP.md](https://github.com/shuhei1101/dev-docs/blob/develop/docs/%E3%83%AA%E3%83%95%E3%82%A1%E3%83%AC%E3%83%B3%E3%82%B9/%E6%96%87%E6%9B%B8%E3%81%AEMCP.md) に記載する |
| 既存の呼び出し | 追加した引数・項目を渡さない呼び出しは今と同じ結果を返す |
| #16 への連絡 | マージの後、#16 へ「否定は #28 の `filter` の `not` を使う」ことを知らせる（task-planner の着手の指示） |

<!-- /table -->

単一ユースケース設計で次のとおり決めた。

- `list_changes` の `contains` が返す区間: 文書ごとに、語が入った・消えた commit（その commit と直前の commit の区間）を並べて返す（`git log -S` と同じ）。`from`・`to` の両端だけを比べると、区間の中で入って消えた語の文書を返せないため。前回読んだ時点から比べる呼び出し（commit を持たない）では、比べた区間全体を返す

## スコープ外

<!-- table: data -->

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| 画面の `nav` の `auto` のタグの式（AND・OR・NOT） | この PR は `filter` の `not` を入れるだけで、画面のナビゲーションは #16 が持つ | [#16](https://github.com/shuhei1101/dev-docs/issues/16) |
| 画面の検索への `@matches`・本文の一部・`not`・glob | 画面の検索は語で探し、`filter` を受けない。要望は文書の MCP のツールのオプション | 予定なし |
| `describe` への記載 | `describe` は配信元ごとの `instructions` と種類のスキーマを返すだけで、検索の書き方を載せる場所を持たない（PR #30 と同じ判断） | 予定なし |
| YAML の文書の本文の節での取得 | YAML はキーを `fields` で選べる（Issue の困っていること）。節での取得は Markdown の見出しだけにし、行の範囲は文書の種類を問わない | 予定なし |
| 索引に載っていないファイルとコードの記号（定義・参照）の検索 | dev-docs の対象外で、今後も Grep・LSP を使う（起点 Issue の見送った案） | 予定なし |

<!-- /table -->
