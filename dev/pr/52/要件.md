# 要件

## 要望

AI Monitor の配布物を v0.2.0 から v0.3.0 へ追従する。
終わりの条件は次のとおり。

- `docs/_theme/` に v0.3.0 のサイトの共通の部品がそろっている（`python -m ai_monitor.distribution import-site --version v0.3.0` を worktree の直下で流し、出力の JSON の書き込み・削除の一覧が v0.3.0 の `docs/_theme/` と一致する。`docs/_theme/_data/nav.project.yml` は書き換わらない）
- リポジトリの直下に控え `ai-monitor-theme.yaml` があり、`source: copy`・`version: v0.3.0` を持つ（取り込みのコマンドが書く）
- `ai-monitor-version.ini` の先頭行が `v0.3.0` になっている
- v0.3.0 の規約『ドキュメント管理』の「手で書く 6 行以上の表は `<!-- table: data -->` で包む」に従っていない表が、`dev/`・`docs/` の Markdown（`dev/pr/`・`dev/mock/`・生成した `README.md` を除く）に残っていない
- v0.2.0..v0.3.0 で変わった規約・外部規約・判定フローチャート・チェックシート・観点のうち、上記のほかに dev-docs の成果物が従っていない箇所が無い（読み直して見つけた箇所は、この PR で修正するか `## スコープ外` へ回す）

## 影響するユースケース

現状調査で洗い出した複合 / 単一ユースケースのうち、影響するものは無い。
`docs/_theme/` と 2 つの控えは dev-docs の開発ドキュメントサーバー・画面・管理用プラグインのどれからも読まれず（`src/`・`frontend/`・`plugins/` に参照が無い）、表のマーカーは文書の書式だけを変える。

| 種別 | ユースケース | 影響 | 依存 |
| --- | --- | --- | --- |
| 複合ユースケース | [dev-docsで文書を配信して読み書きする](https://github.com/shuhei1101/dev-docs/blob/develop/dev/%E8%A8%AD%E8%A8%88%E6%9B%B8/%E3%82%B7%E3%83%8A%E3%83%AA%E3%82%AA/%E8%A4%87%E5%90%88%E3%83%A6%E3%83%BC%E3%82%B9%E3%82%B1%E3%83%BC%E3%82%B9/dev-docs%E3%81%A7%E6%96%87%E6%9B%B8%E3%82%92%E9%85%8D%E4%BF%A1%E3%81%97%E3%81%A6%E8%AA%AD%E3%81%BF%E6%9B%B8%E3%81%8D%E3%81%99%E3%82%8B.yaml) | なし（配信・読み書きの流れを変えない） | |

## スコープ外

<!-- table: data -->

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| 設計書の変換（`design_docs convert --from v0.2.0 --to v0.3.0`） | v0.3.0 の `dev/テンプレート/変換/versions.yaml` に v0.2.0→v0.3.0 の範囲の変換が無く、dev-docs の `*.schema.yaml` は v0.3.0 と同じ（[扱いの判断](https://github.com/shuhei1101/dev-docs/issues/35#issuecomment-6502067358)） | 予定なし |
| `rules.yaml` への行の追加 | 配布物のルール索引は `rules.global.yaml` で、監視対象からもそのまま参照する。dev-docs の `rules.yaml` は `rules: []` で写していない（同上） | 予定なし |
| 配信設定（`docs/_config.yml` のキーの追加） | dev-docs に `docs/_config.yml` が無い | 予定なし |
| プラグイン（MCP `update_plugins`） | AI Monitor のプラグインは全プロジェクトで共有し、入っているのは v0.3.0 より後の develop の `e760309a`。dev-docs の作業 PR で取り直す対象ではない | 予定なし |
| 設定スキーマ（`settings.yaml` のキーの追加） | モニターの `settings.yaml` は全プロジェクトで共有する。v0.3.0 の `settings.yaml.example` で増えたキーは全て既定値を持ち、足さなくても既定値で動く | 予定なし |
| MCP ツール（`agents[].mcp_tools` の見直し） | `settings.yaml` の `agents` は implementer を除き `mcp_tools` を持たず既定の割り当てで、v0.3.0 で増えたツール（`capture_screenshots`・`reopen`・`get_api_usage` 等）は planner に既に割り当たっている | 予定なし |
| `dev/mock/` の実画面 HTML から共通アセット `docs/_theme/assets/style.css` を読む | v0.3.0 の規約『モック画面構成』は、採用スタイル本体（`dev/mock/assets/style.css`）を共通アセットの後に読むとする。dev-docs のモックは採用スタイル本体だけを読んで作られ、合意済みの見た目が共通アセットを足すと変わりうる。含めるかの判断は後段のレビューで確定する。現時点の判断は、合意済みのモックの見た目を変えないため含めない | 予定なし |
