## 変更方針

<!-- table: data -->

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 1 ファイルの文書の ID | メタデータの `id` が無ければ、`path`（配信元の直下からのパス、拡張子付き）をそのまま ID にする | `_stem` を削除する |
| `body_file` の行の文書の ID | メタデータの `id` が無ければ、`body_path`（拡張子付き）をそのまま ID にする | 同じフォルダの `plan.ts`・`plan.js`・`plan.css` が別の文書になり、`unindexed_files` に数えられない |
| `body_file` を持たない行の文書の ID | `{path}#{位置}`（`path` は拡張子付き） | |
| `name` の既定 | ファイル名から拡張子を除いた名前のまま変えない | |
| 当たらない関連の検査 | `check_sync` で配信元の全ての文書の ID の集合を 1 回作り、各文書の `related[]` の `to` が集合に無い行を `unresolved_related` に `{行の id}: {文書の id}: {to}` で入れる | `source` を持つ行は照合しない。1 文書の判定は `features/documents/fields.py` の `unresolved_related` に置く（`documents` から `related` の機能を import しない） |
| 検査の結果の出し方 | `SyncReport`・`SyncCounts`・`SyncItem` の種類と、`check_project`・`status`・起動時の警告のログ・セッションの文脈に `unresolved_related` を加える。項目の並びは `missing_refs`・`unindexed_files`・`missing_body_files`・`unresolved_related` | |
| 既存機能への影響 | `id` を持たない文書の ID が全ての配信元で変わる（破壊的変更）。`related[].to`・`id:` のリンク・`get_docs`・`trace_related` の `from_ids` は新しい ID で引く | 移行の手順は作らない（要件.md の `## スコープ外`） |
| 性能 | 追加する照合は、ID の集合を 1 回作って各 `related[]` を集合で引く（文書数と関連の行数に比例） | [#65](https://github.com/shuhei1101/dev-docs/issues/65) と同じ `check_sync` を触るため、先にマージした方を後の方へ取り込む |
