# 要件

## 要望

開発ドキュメントサーバー本体を作る。
端末の設定 `sources[]` に並べた配信元を 1 プロセス・1 ポートで配り、利用者には画面、エージェントには文書の MCP で YAML の正本の文書を出す。
仕様の正本は Issue の必読の資料（A-14・A-23・A-24・A-25・A-33・A-30・R-36）で、ここでは終わりの条件を並べる。

<!-- table: data -->

| 区分 | 終わりの条件 |
| --- | --- |
| 起動 | `dev-docs serve` が `DEV_DOCS_CONFIG`（既定 `~/.config/dev-docs/settings.yaml`）を読み、`127.0.0.1:{DEV_DOCS_PORT}`（既定 8781）で待ち受ける。文書の MCP は `/mcp`、画面は `/{配信元の id}/`・`/{配信元の id}@{ref}/`。`/_admin/mcp` はパスだけを組み立て、ツールは #4 |
| 起動時の検証 | 各配信元の設定（マージした結果）をスキーマで、検査・変換・生成のスクリプトを実行できるかで確かめる。失敗した配信元は配信せず、配信元の id・違反したキーのパス・理由をエラーログに残し、他の配信元は配信する |
| 端末の設定 | `version` と `sources[]`（`id`・`config`・`enabled`・`scope.read`・`scope.write`）を読む。`config` の YAML の配列を上から順にマージし、同じキーは後のファイルで上書き、`documents[]` などのテーブルは `id` で行ごとに上書き・追加する |
| 権限 | フックが入れる `cwd` が `scope.read`・`scope.write` の glob に当たるかで、その配信元を読めるか・書けるかを決める（`/**` を付けないパスはそのフォルダだけ）。当たらない配信元を指した呼び出しは断り、今の作業場所から使える配信元の一覧を返す |
| 作業中の配信元 | `cwd` を含む配信元のフォルダのうち一番深いものを作業中の配信元にし、`source` を省いた呼び出しはそれを指す。読み書きのツールは `worktree`（ワークツリーのパス）の引数を受け、配信元の設定の `worktrees`（既定 `[./.claude/worktrees/*]`）に当たるパスなら、読み書きをそのワークツリーの同じ相対パスの設定と文書へ向ける。当たらないパスは断る。`worktree` を省き `cwd` がワークツリーの中なら、そのワークツリーを指す |
| 配信元の設定 | `dev-docs.yaml` の `version`・`documents[]`・`validators[]`・`converters[]`・`generators[]`・`nav`・`ids.format`・`related.types`・GitHub のリポジトリと起票のラベルなどを A-25 のキー一覧どおりに読む。`documents[].records`・`body_file` で 1 ファイルの `items[]` を 1 件ずつの文書として読む。Git 管理外のフォルダも配信元にできる |
| 設定のバージョン | 端末の設定と `dev-docs.yaml` の `version` を、サーバーが読めるバージョンと比べ、古い設定の配信元を検出する（知らせるのは #4 の `check_project` と SessionStart） |
| 文書の MCP | `search_docs`・`write_docs`・`delete_docs`・`describe`・`list_changes`・`trace_related` の 6 つを、A-14 の引数・既定値・上限（`limit` 既定 20・最大 100、`max_chars` 既定 20,000・上限 40,000、`write_docs` の操作は 1 回 50 件まで、`trace_related` の `depth` 既定 2・上限 4）・返す形式・エラーどおりに返す。`source` は配信元の id、`search_docs`・`list_changes` は配列か `*` も受ける |
| 書き込み | 変更を当てた後の文書が配信元のスキーマと `validators[]` に通ったときだけ、作業ツリー（Git 管理外の配信元はそのフォルダ）のファイルを書き換える。commit はしない。`expected_version`（内容のハッシュ）が今のバージョンと違えば書かない。Git の配信元はワークツリーにだけ書け、書く先がクローン本体のときは断る |
| 削除 | 物理削除。他の文書の `related` から参照されていれば既定で失敗して参照元を返し、`on_referenced: unlink` で参照も外して消す |
| 作成日時・更新日時 | Git の履歴があればそのファイルの最初と最後のコミットの日時、無ければメタデータの `created`・`updated`（Git 管理外の配信元は `write_docs` が付ける）、どちらも無ければ空で並べ替えの末尾 |
| 1 セッション 1 回 | `session_id`・`agent_id` ごとに返した文書の id とハッシュを記録し、同じバージョンの本文・関連の相手は 2 回目に `（この会話で返し済み）` だけを返す。`repeat_seen: true` で取り直せる |
| 画面 | ai-monitor の開発ドキュメントサーバーの汎用の部分（R-36: 本文・目次・未発見の画面・`@{ref}` のリビジョンの切り替え・`?diff=` の差分の強調・検索・表の列を隠す・選んだ文字列へのコメント）を持つ。タブとサイドバーは `nav`、`nav` が無ければ種類ごとのタブ。タブを開くとサイドバーの一番上の文書を出し、文書の一覧の画面は持たない。本文は変換した Markdown を mdmark で描く |
| コメント | 溜めたコメントはどの配信元でもまとめてコピーでき、`dev-docs.yaml` に GitHub のリポジトリを書いた配信元では、溜めたコメントと文書のパスを添えて GitHub の Issue の作成画面を開ける |
| 設定画面 | `/_settings/` で端末の設定の `sources[]` の追加・削除と、各行の `enabled`・`config`・`scope` の編集ができる。スキーマに通ったときだけ `settings.yaml` を書き換えて読み直す。画面と別のオリジンからの書き込みは断る |
| 変換 | 既定はスキーマ駆動（ai-monitor の `x-heading`・`x-key`・`x-diagram`・列の `title`）で YAML を Markdown にし、`converters[]` を指す種類だけ配信元のスクリプト（標準入力に YAML、標準出力に Markdown）に替える。Markdown の中の埋め込みのマーカーを、mdmark に渡す前に YAML の表に置き換える |
| ai-monitor 固有 | フェーズ・設計とテストの対応・Pages の公開の処理を持ち込まない。dev-docs のコードは ai-monitor・MindStella を参照しない |
