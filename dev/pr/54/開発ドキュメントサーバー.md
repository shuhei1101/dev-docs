## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| `records` の行のスキーマの当て方 | 行の `schema` はファイル全体のスキーマとし、1 行ずつの検査・`search_docs`・`list_changes` の項目の一覧には（`describe` はファイル全体のスキーマを返す） `properties.{records}.items` を取り出して当てる | `要件.md` の `## 要望` の案 A |
| `check_project` の検出 | `records` の行のスキーマから `properties.{records}.items` を取り出せない組み合わせを、`documents[{番号}].schema` の違反として `violations` に入れる | - |
| 文書の API の応答 | `DocumentResponse` に `body_path`（配信元の直下からの本文のファイルのパス。本文のファイルを持たない文書は `null`）を加え、画面の API の生成をし直す | - |
| 本文のファイルのパスでの引き方 | 画面のパスで文書が見つからないとき、文書のファイルか本文のファイルのパスが同じ最初の文書を引く | `要件.md` の `## 要望` の案 A。`try_convert` と同じ引き方 |
| session-context の遅い経路 | `check_sync` が配信元のフォルダをたどるのを配信元ごとに 1 回にし、`walk_files` のフォルダごとの `os.path.islink` をやめる | 測った経路は `要件.md` の `## 要望`。共有のロックは長い処理の間は持っていない。直し方の詳細はモジュール構成設計で決める |
