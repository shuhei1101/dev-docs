# 反映作業の確認でのエンドポイントの不在の判定を修正し、表の外部キーのセルで物理名のテーブルもリンクにする

## 概要

反映作業の確認で、dev-docs のサーバーのエンドポイントが無いことを正しく判定できるようにする。
スキーマ駆動の変換で、表の外部キーのセルが物理名で書いた同じ文書のテーブルも見出しへのリンクにする。

## 背景

[#109](https://github.com/shuhei1101/dev-docs/issues/109) は [#104](https://github.com/shuhei1101/dev-docs/issues/104)・[#106](https://github.com/shuhei1101/dev-docs/issues/106) の束。

- #106: 作業 PR [#103](https://github.com/shuhei1101/dev-docs/pull/103) の反映作業『dev-docs のサーバーの再起動』の確認スクリプトが、削除した `POST /_admin/session-context` の不在を 404 で判定している。サーバーは画面の配信の `GET /{path:path}` を持つため、存在しないパスへの POST は 405 になり、再起動が効いているのに確認が止まった（起点 Issue [#92](https://github.com/shuhei1101/dev-docs/issues/92) の反映作業の再実施はこの対処の後）
- #104: 表の外部キーのセル（`foreign_key.table`）は、同じ文書のテーブルを論理名（`tables[].title`）でだけ引くため、物理名（`tables[].name`）で書いた外部キーがリンクにならない。作業 PR [#102](https://github.com/shuhei1101/dev-docs/pull/102) のレビューの対象外の逸脱の報告で見つかった
