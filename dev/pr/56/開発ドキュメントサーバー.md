## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 変換の置き場所 | 変換を dev-docs のパッケージに置き、配信元の `converters[].run` から CLI のサブコマンドとして呼ぶ | `未確定`（`要件.md` の変換の置き場所。決める段: インターフェース定義設計） |
| 変換の入出力 | 標準入力にプロンプトの YAML 1 件、標準出力に Markdown。読めない YAML・スキーマに合わない YAML は 0 以外で終わり、標準エラーに理由を出す | 今の `converters[]` の約束（`docs/リファレンス/設定.md`）のまま |
| 見出し | `name` を見出しに、`kind`・`lang` をバッジに、`description` を段落に出す | mdmark のバッジ |
| 本文の構成 | 見出しの下に、変数の表・テンプレート・例を `##` のセクションで並べ、その下に部品・組の `###` のセクションを置く。タブにするのは各 `###` のセクションの中の言語だけにする | mdmark はタブの入れ子を描けない（[確認ログ](./確認ログ.md)） |
| 変数の表 | `vars` を深さ優先で辿り、配列の要素は `{名前}[].{キー}`、オブジェクトのキーは `{名前}.{キー}` のパスで 1 行にする。列は変数・型・必須・例・説明・出どころ | 例は YAML のフロー形式の 1 行 |
| テンプレート | 部品ごとの `###` のセクションに `id`・`role`・`when` の見出しと本文を出し、本文の `{{ 変数 }}` を `data-hint`（説明・型・例）付きの要素にする | 部品のセクションごとに言語のタブを置く。埋め込んだ HTML のヒントは PoC 検証で画面のホバー・フォーカスと幅を確かめる |
| 例の組 | 「既定の例」（各変数の `example`）と `examples[]` の組（省いた変数は `example`）ごとの `###` のセクション（2 つ目以降は `<!-- section: closed -->`）に、`when` が真の部品を Jinja2 で描画してつなぐ。`kind: llm` は `role` ごとのメッセージに分ける。使わなかった部品の `id` と、描画した結果の字数を出す | Jinja2 は `StrictUndefined` で描画し、未定義の変数を誤りにする。組はタブにしない |
| 言語の切り替え | セクションごとに `<!-- tabs: group=lang -->` の言語のタブを置き、トップレベルの `lang` の言語のタブ名に「注入」を付ける | 同じ `group` のタブ群は揃って切り替わり、選んだ言語を覚える |
| 描画できない組 | 未定義の変数・`type` に合わない値の組は、その組のセクションに `[!CAUTION]` の注意書きで変数と理由を出し、他の組のセクションは描画する | 型は `vars` の `type`・`items`・`properties` で確かめる |
| 字数の注意 | `kind: hook` で描画した結果が 1,000 字を超えた組のセクションに `[!WARNING]` の注意書きを出す | 1,000 字は Issue の値 |
| Jinja2 の依存 | `pyproject.toml` の依存に Jinja2 を追加し、外部ライブラリの設計書を作る | 変換を dev-docs に置く場合 |
| 変換の時間 | 変換は `script_timeout_sec`（非機能要件の決定値）の中で終わる | 既存の制限時間のまま |
| 既存機能への影響 | 文書の取得・スキーマ駆動の変換・他の `converters[]` は変えない | - |
