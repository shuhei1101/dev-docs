## 変更方針

<!-- table: data -->

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| `status` | 待ち受けのアドレス・dev-docs のバージョン・配信元ごとの状態（配信中か、配信しない理由・設定のバージョンの新旧・索引の同期の件数）を返す | - |
| `reload` | 端末の設定と配信元の設定を読み直し、追加・削除・配信できなくなった配信元を返す | 読み直しは既存の `reload_sources` を使う |
| `restart` | 応答を返した後に、処理中の要求を待って止め、`os.execv` で同じプロセス ID のまま `dev-docs serve` を起動し直す | 待つ上限は `script_timeout_sec` の 1.5 倍 |
| `update` | 端末の設定の `clone` で `git pull --ff-only`・`uv sync` を行い、新しいコードの `dev-docs migrate --plan` で移し替えの要否を確かめる。要らなければ `restart` と同じ手順で起動し直す。新しいバージョンと移し替えの要否を返す | `git pull`・`uv sync` が失敗したとき、移し替えが要るときは起動し直さない。配信できなかった配信元は起動し直した後の `status` で見る |
| `POST /_admin/session-context` | 管理の MCP のツールにせず、HTTP のエンドポイントにする。cwd から使える配信元・使い方・索引の同期の件数・古い設定の警告を、SessionStart のフックが文脈に入れる文として返す。`/clear`・圧縮の後はそのセッションの返し済みの記録を削除する | SessionStart のフックが呼ぶ |
| `check_project` | 指した `dev-docs.yaml`（端末の設定に無い配信元も可）のスキーマ違反・無いフォルダ・動かないスクリプト・`ref` の列の欠け・索引の同期の件数（索引に無いファイル・ファイルが無い行）を返す | 件数を求める処理は PR #20 で入っている |
| `try_convert` | 指した配信元と文書を、配信元の変換で Markdown にして返す。書き込まない | - |
| `dev-docs migrate` | `plan`（当てる手順の一覧）・適用・`record`（当てたバージョンの記録）。適用の前に設定のバックアップを取り、失敗したら書き換えない | 移し替えの手順は `src/dev_docs/migrations/{settings|dev-docs}/{バージョン}/steps.yaml` |
| 雛形 | `templates/dev-docs.yaml` と `templates/settings.yaml` を置く。それぞれ `dev-docs.schema.yaml`・`settings.schema.yaml` の検証に通る | `templates/settings.yaml` は `/dev-docs:global-setup` が端末の設定の元にする |
| `write_docs` の説明 | 範囲のファイルを作った・消した・改名したら管理用の YAML の行を修正することを記載する | D-163 |
| アーキテクチャ図 | 管理用プラグインの役割を `.mcp.json`・フック・スキルに合わせ、`repository.layout` に移し替えの手順の置き場所を追加する | - |
| 権限 | 管理の MCP は `127.0.0.1` だけで待ち受ける既存の条件のまま、作業場所での絞り込みを持たない | - |
