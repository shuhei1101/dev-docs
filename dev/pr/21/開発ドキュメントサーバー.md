## 変更方針

<!-- table: data -->

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| `status` | 待ち受けのアドレス・dev-docs のバージョン・配信元ごとの状態（配信中か、配信しない理由・設定のバージョンの新旧・索引の同期の件数）を返す | - |
| `reload` | 端末の設定と配信元の設定を読み直し、追加・削除・配信できなくなった配信元を返す | 読み直しは既存の `reload_sources` を使う |
| `restart` | 応答を返した後に、同じ引数で自分のプロセスを起動し直す | 起動し直し方はインターフェース定義設計で決める |
| `update` | 端末の設定の `clone` で `git pull`・依存の入れ直しを行い、`restart` と同じ手順で起動し直す。新しいバージョンと配信できなかった配信元を返す | `git pull` が失敗したら起動し直さない |
| `check_project` | 指した `dev-docs.yaml`（端末の設定に無い配信元も可）のスキーマ違反・無いフォルダ・動かないスクリプト・`ref` の列の欠け・索引の同期の件数（索引に無いファイル・ファイルが無い行）を返す | 件数を求める処理は PR #20 で入っている |
| `try_convert` | 指した配信元と文書を、配信元の変換で Markdown にして返す。書き込まない | - |
| `dev-docs migrate` | `plan`（当てる手順の一覧）・適用・`record`（当てたバージョンの記録）。適用の前に設定のバックアップを取り、失敗したら戻す | 移し替えの手順の置き場所は要件.md の `未確定` |
| 雛形 | `templates/dev-docs.yaml` を置く。`dev-docs.schema.yaml` の検証に通る | - |
| `write_docs` の説明 | 範囲のファイルを作った・消した・改名したら管理用の YAML の行を修正することを記載する | D-163 |
| アーキテクチャ図 | 管理用プラグインの役割を `.mcp.json`・フック・スキルに合わせ、`repository.layout` に移し替えの手順の置き場所を追加する | - |
| 権限 | 管理の MCP は `127.0.0.1` だけで待ち受ける既存の条件のまま、作業場所での絞り込みを持たない | - |
