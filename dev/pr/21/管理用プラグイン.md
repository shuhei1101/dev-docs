## 変更方針

<!-- table: data -->

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| `.mcp.json` | `dev-docs`（`http://127.0.0.1:${DEV_DOCS_PORT:-8781}/mcp`）と `dev-docs-admin`（`/_admin/mcp`）の 2 つ | - |
| SessionStart のフック（起動） | ポートにつながらなければ、`DEV_DOCS_CONFIG` の端末の設定の `clone` で `dev-docs serve` を切り離して起動し、待たずに戻る | PR #9 の PoC のとおり。起動したセッションでは `/mcp` のつなぎ直しを案内する |
| SessionStart のフック（文脈） | `POST /_admin/session-context` で、cwd で使える配信元（名前・権限・`description`）と、索引の同期の件数・設定のバージョンの新旧を取り、A-32 の短い使い方と合わせて文脈に追加する。使い方には D-163 の 1 文（範囲のファイルを作った・消した・改名したら、管理用の YAML の行を修正する）も含める | サーバーがまだ待ち受けていないときは、つなぎ直しの案内だけを追加する |
| PreToolUse のフック | 文書の MCP のツールの呼び出しの入力に `cwd`・`session_id`・`agent_id` を入れる | 管理の MCP のツールには入れない |
| フックの実行 | 失敗してもセッションを止めない（終了コード 0 で戻り、理由を文脈に追加する） | `hooks.json` の `timeout` は SessionStart 6 秒・PreToolUse 5 秒 |
| スキル `global-setup` | A-34 の「1. バージョンの確認」「2. global-setup」の手順 | AskUserQuestion で聞く |
| スキル `setup` | A-34 の「1. バージョンの確認」「3. setup」「4. 2 回目以降の setup」の手順。YAML でない範囲は `templates/files.schema.yaml` に沿って管理用の YAML の行を書く | 書く前に表で確認する |
| 言語・実行 | フックは Python 3.14 の標準ライブラリだけで書き、`uv` を前提にしない | アーキテクチャ図の `runtime` のとおり |
