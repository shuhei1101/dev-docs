# 要件

## 要望

dev-docs のリポジトリをマーケットプレイスにし、プラグイン `dev-docs` を配る。
利用者はユーザースコープで入れ、各リポジトリはプラグインを持たない。
ai-monitor には依存しない。
仕様の正本は Issue の必読の資料（A-23・A-24・A-25・A-32・A-34・A-35・A-36）で、ここでは終わりの条件を並べる。

<!-- table: data -->

| 対象 | 終わりの条件 |
| --- | --- |
| `.mcp.json` | 文書の MCP `http://127.0.0.1:${DEV_DOCS_PORT:-8781}/mcp` と管理の MCP `/_admin/mcp` を配る |
| SessionStart のフック | ポートにつながらなければ、端末の設定の `clone` で `dev-docs serve` を切り離して起動し、待たずに戻る。cwd から使える配信元の一覧（名前・権限・`description`）と場面ごとの短い使い方（A-32 の「1. SessionStart で注入する文」）を文脈として追加する。索引に無いファイル・ファイルが無い行の件数と、設定のバージョンが古い配信元があれば知らせる。使い方に「範囲のファイルを作った・消した・改名したら、管理用の YAML の行を修正する」を記載する |
| PreToolUse のフック | 文書の MCP のツールの呼び出しに `cwd`・`session_id`・`agent_id` を入れる |
| 管理の MCP | `status`・`reload`・`restart`・`update`（クローンで `git pull` して依存を入れ直し、再起動）・`check_project`（配信元の設定とスクリプトの検証。`ref` の列の欠けと索引の同期の件数も返す）・`try_convert`（試しに変換）を持つ |
| スキル `/dev-docs:global-setup [クローンのパス]` | clone・依存・雛形から端末の設定・env の `DEV_DOCS_CONFIG`・起動と `/mcp` の確認を行う。2 回目以降は設定のバージョンを比べ、足りないキーだけを聞く（A-34） |
| スキル `/dev-docs:setup [path]` | バージョンを確かめ、`scope.write`・`scope.read`・検索できるようにするファイルを AskUserQuestion で聞き、仮のメタデータを表で確認してから、索引（YAML でない範囲は管理用の YAML の行）と端末の設定の `sources[]` の行を書く。2 回目以降は範囲のファイルと索引を突き合わせ、追加・削除・改名（Git はリネームの検出、Git 管理外は内容のハッシュ）を確認してから書く（A-34）。MindStella のワークスペースもほかの配信元と同じ手順で扱う |
| CLI `dev-docs migrate` | plan・適用・record を持つ。端末の設定と `dev-docs.yaml` の `version` を比べ、移し替えの手順（`src/dev_docs/migrations/{settings|dev-docs}/{バージョン}/steps.yaml`）を古い順に当てる。当てる前にバックアップを取り、失敗したら書き換えない |
| 雛形 | 配信元に置く `dev-docs.yaml` の雛形を `templates/` に置く。管理用の YAML のスキーマ `templates/files.schema.yaml` は PR #20 で入っており、setup はそれに沿って書く |
| `write_docs` の説明 | 「範囲のファイルを作った・消した・改名したら、管理用の YAML の行を修正する」を記載する |

<!-- /table -->

移し替えの手順の置き場所は `src/dev_docs/migrations/{settings|dev-docs}/{バージョン}/steps.yaml` に決めた（モジュール構成設計）。`dev-docs migrate` はパッケージのコードから手順を読むため、手順もパッケージに入れる。
