# 要件

## 要望

`dev-docs.yaml` の `tags`（タグのマスター）とマスターに無いタグの検査をやめ、タグを自由な文字列として扱う（Issue の D-169）。
使われているタグは `search_docs` の `group_by: tags`（横断は `source: "*"`）で件数つきで引き、集計の前に値を正規化（NFKC・大文字小文字）する。

<!-- table: data -->

| 対象 | 終わりの条件 |
| --- | --- |
| `dev-docs.yaml` の `tags` キー | スキーマ（`src/dev_docs/schemas/dev-docs.schema.yaml` と配布の `schemas/dev-docs.schema.json`）から外し、書いた設定は起動時・`reload`・`check_project` の検証で違反になる。マスターのファイルの有無の検査とマスターの読み込み（`_tag_master`・`ServedSource.tag_master`）をなくす |
| タグの検査 | 文書の検査（`check_tags`）をなくし、マスターに無いタグを違反にしない |
| 設定のバージョン | 配信元の設定のバージョンを `3` に上げ、`dev-docs migrate --source` が `version: "2"` 以前の設定から `tags` を削除する。雛形 `templates/dev-docs.yaml` の `version` も `3` にする |
| `group_by` の集計 | 値を正規化（NFKC と `casefold`）してから数え、表記だけが違う値（`MCP`・`ｍｃｐ`・`mcp`）を 1 つの値として件数を合わせる |
| 検索の条件 | 条件の比較は既に正規化している（`features/search/filters.py` の `normalize`）ので変えない |
| SessionStart の使い方・ツールの説明 | `describe(source)` で種類と書き方を確かめ、タグは `search_docs` の `group_by="tags"` で使われているタグを見て同じ意味のタグを使い回す案内にする。`describe` がタグを返す書き方をなくす |
| 公開ドキュメント | 下の `## 更新ドキュメント` のページからタグのマスターの記載を削除し、`group_by: tags` で使われているタグを引く使い方を記載する |

<!-- /table -->

`未確定`: 正規化で 1 つにまとめた値の表示（決める段: インターフェース定義設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 正規化した値（`mcp`）を返す | 処理が単純で、返る値が文書の並びに左右されない | 文書に無い表記（大文字を小文字にした値・全角を半角にした値）を返し、使い回すとその表記が増える |
| B | まとめた元の表記のうち付いている文書が最も多いもの（同数なら値の昇順で先のもの）を返す | 文書に実際に付いている表記を返し、使い回すと表記がそろっていく | 代表の表記を選ぶ処理が要る |

推奨: B

集計の目的は、エージェントが使われているタグを見て同じ表記を使い回すことで、文書に無い表記を返すと表記のずれを増やす。

`未確定`: 正規化して数える対象（決める段: インターフェース定義設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | `group_by` の全ての項目 | 検索の条件の比較（全ての項目を正規化する）と同じ扱いになる | `status` など値が決まった項目も正規化する |
| B | `tags` だけ | 変える範囲がタグに限られる | 項目によって集計と条件の比較で扱いがずれる |

推奨: A

条件で 1 つに当たる値は集計でも 1 つに数えないと、集計の件数で絞った結果の件数が合わない。

`未確定`: `dev-docs migrate` の `tags` の削除を破壊的な手順にするか（決める段: インターフェース定義設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | `value` を持たない `delete`（破壊的な手順）にし、`--allow-destructive` で当てる | 今の手順の種類のまま書け、利用者が削除するキーを確かめてから当てる | `version: "2"` 以前の配信元は `--allow-destructive` を付けて流し直す |
| B | 破壊的としない削除の手順を新しく設ける | 付けずに 1 回で移し替えが終わる | 手順の種類と CLI の説明が増える |

推奨: A

`tags` はファイルのパスで、削除しても配信元のマスターのファイルは残り、利用者が確かめてから当てる今の仕組みで足りる。
