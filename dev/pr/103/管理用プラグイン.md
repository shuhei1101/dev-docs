## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 待ち受けているとき | 文脈を取得せず、`additionalContext` を出力しない | |
| `/clear`・圧縮 | `reason` が `clear`・`compact` のときだけ、記録の削除のエンドポイントを呼ぶ | 未確定 1 |
| 記録の削除の失敗 | 理由を 1 行 `additionalContext` に入れ、終了コード 0 で戻る | 未確定 2 |
| 落ちているとき | 起動・起動できないときの通知・`/mcp` の再接続の案内は今と同じ | |
| 打ち切りの秒数 | 記録の削除の呼び出しの打ち切りと `hooks.json` の `timeout` を、規約『資源の値の決め方』で導き直す | インターフェース定義設計で決める |

`未確定` 1: 記録の削除を呼ぶ条件（決める段: インターフェース定義設計）

| 案 | 内容 |
| --- | --- |
| A | `reason` が `clear`・`compact` のときだけ呼ぶ |
| B | 毎回呼び、サーバーが `reason` で判定する |

推奨: A

フックの役割を起動時の処理に限り、`startup`・`resume`・`fork` の往復を省くため。

`未確定` 2: 記録の削除に失敗したときの通知（決める段: インターフェース定義設計）

| 案 | 内容 |
| --- | --- |
| A | 通知しない（`repeat_seen: true` で取り直せる） |
| B | 理由を 1 行入れる |

推奨: B

記録が残ると本文を省かれたまま気づかないため。
