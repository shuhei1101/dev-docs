# 要件

## 要望

- SessionStart のフックは、ポートにつながらないときのサーバーの起動と、起動できなかったときの通知・起動したときの `/mcp` の再接続の案内だけを `additionalContext` に入れる。待ち受けているサーバーがあるときは、使える配信元・使い方・警告を注入しない
- `/clear`・圧縮（`reason` が `clear`・`compact`）のとき、フックは返し済みの記録の削除を引き続きサーバーへ依頼する。`POST /_admin/session-context` は、記録の削除だけを行い文を返さないエンドポイント（例: `/_admin/session-start`）に置き換える
- 文の描画と `content/prompts/session-context.yaml` を削除し、起動時の必須のプロンプトから除外する
- 今は文脈に入れている警告（`check_sync` のずれ・エイリアスのキーの違反・配信元と端末の設定のバージョンが古いこと・`nav_warnings`・`not_served`）を、引数なしの `describe()` の応答に載せる
- 文書の MCP の instructions の「使える配信元は、SessionStart の文脈と引数なしの `describe()` の一覧にあります。」を、引数なしの `describe()` だけを示す記述に修正し、SessionStart の文だけが持つ案内（設計書から調査する・`outside_scope` で作業場所の外を参照する）を instructions へ移す

`未確定`: 読み込み中の案内の扱い（決める段: インターフェース定義設計）

| 案 | 内容 |
| --- | --- |
| A | `describe` は読み込みを待って答えるため、読み込み中の案内は載せない |
| B | `describe` が読み込みを待たずに読み込み中であることを返す |

推奨: A

終わりの条件:

- 待ち受けているサーバーがある作業場所で始めたセッションの `additionalContext` に、配信元の一覧・使い方・警告が入らない
- `/clear`・圧縮の後、文書の MCP が前に返した文書の本文を省かずに返す
- 引数なしの `describe()` が使える配信元と警告を返す
- instructions が SessionStart を参照しない
