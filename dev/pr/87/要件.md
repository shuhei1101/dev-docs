# 要件

## 要望

SessionStart で追加する文（`content/prompts/session-context.yaml`）の、配信元の一覧（`sources`・`omitted` のパーツ）の後ろに、次の 2 点の案内を追加する。

- コードや不具合の調査も、dev-docs で設計書から参照し、設計書が指すコードを参照すること（ソースコードだけで調査すると、設計上の前提や対象の漏れを見落とす）
- 作業場所の外のリポジトリも、`describe` と `search_docs` に `source`（配信元の ID）と `outside_scope: true` を指定すれば参照できること。他のリポジトリでも、ソースコードを直接参照せず、dev-docs で設計書から参照すること

制約:

- 特定のプロジェクト名（配信元の ID・リポジトリ名）を文に入れない。例を出すときは `{配信元の ID}` のような汎用の表記にする
- 追加する文は短く保ち、文書の MCP の instructions と同じ内容を繰り返さない
- 2 点の案内は、使える配信元が 1 件以上あるとき（`usage` のパーツと同じ条件）だけ出す

終わりの条件:

- 配信元が 1 件以上ある作業場所の SessionStart の文が 2 点の案内を含み、配信元の ID・リポジトリ名を固有の値で含まない
- 文が 1,000 字（`CONTEXT_MAX_CHARS`）の上限に収まる
- エージェントが、作業場所の外で `outside_scope: true` で読める配信元の ID を、ツールの呼び出しで知ることができる

`未確定`: 作業場所の外で読める配信元（`outside_read` が真で `scope` に当たらない配信元）の ID をエージェントが知る手段（決める段: インターフェース定義設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | SessionStart の配信元の一覧に、作業場所の外で読める配信元の ID を並べる | ツールを呼ばずに ID が分かる | 1,000 字の上限（`omitted`）を作業場所の配信元と分け合い、作業場所の配信元の説明が省かれやすくなる。[#40](https://github.com/shuhei1101/dev-docs/issues/40) の決定（SessionStart の一覧に外の配信元を出さない）と食い違う |
| B | 引数なしの `describe()` の一覧に、作業場所の外で読める配信元を別の表で並べる | SessionStart の字数を使わない | 引数なしの `describe()` に外の配信元を載せないとした [#40](https://github.com/shuhei1101/dev-docs/issues/40) の決定と食い違う |
| C | `describe(outside_scope: true)`（`source` なし）で、作業場所の外で読める配信元の一覧を返し、SessionStart の文はその呼び出しを案内する | SessionStart の字数を使わず、[#40](https://github.com/shuhei1101/dev-docs/issues/40) の決定（外の配信元の名前は `describe(outside_scope: true)` で引く）のとおりになる | ID を知るのに呼び出しが 1 回増える |

推奨: C

[#40](https://github.com/shuhei1101/dev-docs/issues/40) で「外の配信元は SessionStart の一覧・引数なしの `describe` に出さず、名前は `describe(outside_scope: true)` で引く」と決めたが、今の `outside_scope` は `source` に ID を 1 つ渡したときだけ効き、引数なしの一覧には効かないため、決めた引き方が実装されていない。
C はその決定を実装するだけで、字数の上限をどちらから減らすかの問題も生じない。
